# Lute 0.49.1 — patch: Rust coding-rules sweep

This is the normative 0.49.1 contract, a patch release on the 0.49 contract
line. The words **MUST**, **MUST NOT**, **SHOULD** and **MAY** have their RFC
2119 meanings. The input is the
[Rust coding rules](../../design/rust-coding-rules.md) (Accepted): its §9
sweep applies §1–§5, with the 2026-10-25 amendments, to all existing code
under `crates/`. Release order: see the
[triage note](../../superpowers/notes/2026-10-23-lute-0.49-dogfood-triage.md).
0.49.0 is done, this sweep comes next, and 0.50 (authoring extensibility)
follows. The owner renumbered the sweep from 0.50 to 0.49.1 on 2026-10-25.
The sweep runs with no other branch open. The implementation plan is
[`2026-10-25-lute-0.49.1-coding-rules.md`](../../superpowers/plans/2026-10-25-lute-0.49.1-coding-rules.md);
its header holds the counts measured at `f34f141f` (v0.49.0).

## 1. Scope and version contract

The release is **behaviour-preserving**. It changes Rust source, the lint
configuration, CI, and the snapshot tool's compare mode. It MUST NOT change:

- syntax or static semantics: no diagnostic is added, removed or reworded;
- the execution IR, the Event or snapshot shapes, or their contents;
- any CLI output, exit code or `--explain` text;
- the player, runtime or launcher packages, apart from version stamps.

The toolchain, language, IR, Event and snapshot stamps, player packages and
launcher packages read `0.49.1`. Schema filenames and bodies stay on the
`0.49` line. The toolchain earns the release; every other axis is a content
no-op, as in 0.36.6 and 0.48.1.

| Axis | 0.49.1 rule |
|---|---|
| Toolchain | The Cargo workspace, `lute version` and all seven npm packages stamp `0.49.1`. Lint configuration, module layout, visibility and Rust error types change (§2). |
| Language | `luteVersion` stamps become `0.49.1`; no syntax or semantic change. |
| IR | `irVersion` stamps become `0.49.1`; no field or meaning change. |
| Event/snapshot | Stamps become `0.49.1`; shapes and schema bodies unchanged. |
| Player bindings | `bindingsVersion` stays `"0.49"`; schema body and generated TypeScript unchanged. |
| Player | The save and profile format stays `"0.49"`; there is no format-version reset. An existing save stays loadable with the same compiled bundle; a bundle recompiled with 0.49.1 stamps gets a new project fingerprint (`lute-runtime/src/snapshot.rs` hashes `irVersion`), so the existing project-identity checks apply to it as to any recompile. No behaviour change. |
| Report ids | `0.48.0.check`, `0.48.0.schema`, `0.49.0.constraints`, … keep their names: a report id names the release that introduced the report. |

The release MUST NOT alter the bodies of
`schemas/lute-{ir,events,snapshot,player-bindings}-0.49.schema.json`,
`packages/runtime/src/generated/**` or `packages/player/src/bindings/schema.ts`.
Engines and hosts gated on `0.49` need no gate change. Every command output
captured by `scripts/cli-snapshot.py` MUST be identical to 0.49.0 after
version-stamp normalization, with no exception (§5).

A patch number is right even though public Rust signatures change (§4). The
version axes describe the authoring, artifact and host contracts. The Rust
crates have no external consumers: they ship only inside the npm binaries and
are not published to crates.io (rules note §4). So the Rust API is not a
versioned axis.

## 2. What changes

The work is the five steps of rules note §9, with the 2026-10-25 amendments.
The plan splits them into slices.

1. **Lints (note §1).** By the end, `[workspace.lints.rust]` and
   `[workspace.lints.clippy]` in the root `Cargo.toml` hold exactly the note's
   block. Each of the 21 crates sets `[lints] workspace = true`, and a root
   `clippy.toml` holds the two `disallowed-methods` entries. A lint is
   enabled in the slice that brings its count to zero (amendment 1). The
   `clippy` job of `.github/workflows/test.yml` gains the production command
   `cargo clippy --workspace --lib --bins --locked -- -D warnings -D clippy::unwrap_used`.
   `clippy.toml` joins the workflow's `pull_request.paths`.
2. **Lint sites** are fixed in two ways:
   - by `cargo clippy --fix`, for the lints whose every site carries a
     machine-applicable suggestion (except `allow_attributes`, amendment 2);
   - by hand, for the rest.

   A local exception is `#[expect(lint, reason = "…")]`, never `#[allow]`.
3. **Module files (note §2).** The eight self-named module files become
   `mod.rs`.
4. **Visibility (note §3).** `pub(super)` and `pub(in …)` become
   `pub(crate)`. A new `scripts/check-visibility.py` rejects both in
   `crates/*/src`; the `clippy` job runs it, and the script joins the
   workflow's trigger paths.
5. **Error types (note §4).** Every Rust error type implements `Debug`,
   `Display` and `std::error::Error`. No `pub fn` returns
   `Result<_, String>`.

Before any Rust change, `scripts/cli-snapshot.py --compare` gains a
`--strict` mode (§5), so that the byte-identity proof also covers the set of
commands.

The sweep is done when two things hold:

- the `clippy` job passes with the note's configuration, including the
  production `unwrap_used` command;
- the counts of note §1–§4, re-measured as in the plan header, are zero.

## 3. Behaviour-preservation rules

These rules apply where a mechanical fix could change behaviour.

- **Narrowing casts.** An `as` cast that can truncate, wrap or lose sign is
  handled by where its value comes from:
  - From source text, a manifest, an IR artifact or a host message: keep the
    `as` and add `#[expect(clippy::cast_…, reason = "…")]`. The reason states
    the defined semantics, for example "`f64 as i64` saturates; CEL integer
    conversion relies on it" (amendment 3). `try_from(..).expect(..)` would
    add a panic on author or host input, which note §5 forbids.
  - Range guaranteed by an internal invariant: use
    `T::try_from(n).expect("<why it fits>")`.
  - Lossless conversion: use `From` / `into()`.
- **Typed errors keep their text.** A new error type's `Display` MUST produce
  byte for byte the string that the `String` error produced, wherever that text
  reaches a diagnostic, a CLI message or a runtime error. A `From` impl
  replaces a `map_err` that only re-wraps.
- **`unwrap()` in production** becomes `expect("<why it cannot fail>")`. Where
  the caller already returns a `Result` with the same observable outcome, the
  error may be propagated instead. It never becomes a silent default.
- **Mechanical rewrites.** The other lint fixes are mechanical: `for_each` →
  `for`, `Arc::clone`, `Debug` derives, `let … else`, and the rest.
  - A `Debug` impl for a type with a field that is not `Debug` is written by
    hand, ending in `finish_non_exhaustive()`.
  - `Debug` output MUST NOT be routed into any output.
- **Visibility** only widens, and only inside a crate (`pub(super)` →
  `pub(crate)`). A type that becomes reachable through a signature is made
  `pub(crate)` as well, never re-hidden.
- **No `#[allow]`, no new `catch_unwind`, no `unsafe`.**

## 4. Breaking changes and migration

| Class (D6) | Change | Migration |
|---|---|---|
| Rust API | `pub fn`s that returned `Result<_, String>` return typed `<Domain>Error`s. Error types gain `Display` and `std::error::Error` impls. | Match the new error type, or call `.to_string()` for the old text. |
| Release | All axes `0.49.1`; schemas, `bindingsVersion` and the save format stay on `0.49`. | None. `lute fix` raises `luteVersion` stamps. |

There are no Syntax, Semantic, IR, Plugin, CLI or Player rows.
`pub(super)` → `pub(crate)` and the `mod.rs` moves change no path outside a
crate.

**PR label.** The `public-api` job of `test.yml` runs
`scripts/check-public-api.py`. It compares rustdoc item inventories and fails
only on **removed** items; the `api-change` label exists to permit those
removals (`--allow-removals`).

- The sweep removes no public item:
  - typed errors keep every fn and add types;
  - `pub(super)` items, and the `pub fn`s in private modules that S5 may
    narrow, are not in the crate-root inventory;
  - `Debug` impls are not items.
- So the PR goes **without** `api-change`, as the 0.47.2 and 0.48.1 patch PRs
  did. If the job reports a removal, that is a defect in the slice that caused
  it, and it is fixed there. It is never labelled away.
- The signature changes are recorded in the CHANGELOG instead (§6).

## 5. Acceptance

- **Byte-identity matrix, strict.** After every slice and in the final gate,
  this command reports **0 changed, 0 added, 0 removed** and exits 0:

  ```sh
  python3 scripts/cli-snapshot.py target/debug/lute "$SNAP/<slice>" --compare "$SNAP/base" --strict
  ```

  `$SNAP/base` is the snapshot of the v0.49.0 binary (`$SNAP/lute-0.49.0`),
  taken from the v0.49.0 tree: 6,280 outputs.
- **What `--strict` adds.** Without it, `--compare` accepts added commands
  ("not compared") and renamed commands, the 0.47.2 → 0.48 argument mapping.
  `--strict` makes both fail. It still fails, as today, on removed commands,
  changed arguments, missing outputs and differing bytes. `--self-test`
  proves the behaviour on synthetic snapshot pairs:
  - an added command fails under `--strict` and passes without it;
  - a removed command, a renamed command and a changed output byte each fail
    under `--strict`.
- **The normalizer stays as it is.** It already maps `0.49.x` stamps
  (`0\.(?:48|49)(?:\.\d+)?`), so after the Z stamps the compare still needs no
  delta class.
- **Conformance unchanged.** The `conformance` and `session_conformance`
  nextest binaries pass, and so do the Go and JS harnesses
  (`conformance/harness/run.sh`). `conformance/regenerate.sh` produces no
  diff before Z, and a stamp-only diff at Z.
- **Cost unchanged.** `python3 scripts/vocab-grid.py gate --lute
  target/debug/lute` passes after every slice.
- **Schemas.** `lute-contract-schema` produces no diff under `schemas/`, at
  every slice and at Z.
- **Lint completeness.**
  - These commands pass: `cargo clippy --workspace --all-targets --locked --
    -D warnings`, the wasm32 form, the production `unwrap_used` command and
    `scripts/check-visibility.py`.
  - Re-measured, the counts of note §1–§4 are zero.
- **Every other CI gate** passes, as listed in the plan's final gate.

## Appendix A — decisions

1. **0.49.1, a patch on the 0.49 line** (owner, 2026-10-25). It follows
   0.36.6 and 0.48.1: every visible axis moves to `0.49.1`, while the schema
   files, `bindingsVersion` and the save format stay on `0.49`. Engines need
   no gate change, and 0.49.0 saves load. The authoring-extensibility release
   becomes 0.50. With no save-format change there is no save migration, so
   review finding F3 (the save reset of the earlier 0.50.0 draft) is moot.
2. **Acceptance is 0 snapshot deltas under `--strict`**, with no allowed
   class. A behaviour-preserving release has nothing to classify. Strict mode
   (review F2) closes the gap where an added command passed unnoticed.
3. **No `api-change` label**, because the workflow does not require it (§4).
4. **Lints are enabled per slice:** each slice adds to `[workspace.lints]`
   exactly the lints it brings to zero, so every commit passes the `clippy`
   job with `-D warnings`. The note's full block is in place after the last
   lint slice (note amendment 1).
5. **Measurement is isolated from implementation** (review F1). Counts come
   from a subshell with a command-local `CARGO_TARGET_DIR` and
   `CLIPPY_CONF_DIR` under `$SNAP/count`. Implementation and RG build into
   `target/` and read the repository `clippy.toml`.
