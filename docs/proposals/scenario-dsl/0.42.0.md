# Lute 0.42.0 — player contract and volume bindings

This is the normative 0.42.0 contract. It is a clean cutover: all callers in
this repository, the corpus, conformance fixtures, generated contracts, the
player, player-web, CI and documentation migrate together. There is no
compatibility alias for a removed volume spelling or numeric volume form.

The words **MUST**, **MUST NOT**, **SHOULD** and **MAY** have their RFC 2119
meaning. A point left open by an issue is marked **spec decision** and is
listed in Appendix A. The implementation anchors in Appendix B are evidence
at `f014cdbb`; the first 0.42 commit MUST re-check them after `v0.41.1`.

## 1. Scope and version contract

Every public version axis is `0.42.0`: language/toolchain stamp, IR, Event,
snapshot, player bindings, the seven npm packages, and generated contracts.
The schema line is the `0.42` line (filenames use `-0.42`; the JSON version
stamps use `0.42` or `0.42.0` as their existing axis requires). Project files
use `bindingsVersion: "0.42"`.

| Axis | 0.42.0 contract |
|---|---|
| Language/checker/CLI | `volume` is a project domain of absolute levels; the documented scale is `[silent, quiet, normal, loud, full]`. `lute fix` migrates only the exact old scale. Bindings validate `volumes`. |
| IR | Staging command fields remain the authored/resolved command shape. Runtime records gain an `attrs` object for every emitted media/staging record (§4). |
| Event/snapshot | `music`, `sfx`, `vfx`, `bg`, `actor`, `camera`, `cg`, `video`, and `sequence` records carry resolved `attrs`; generated Event and snapshot schemas are `-0.42`. |
| Bindings | Top-level `volumes: { member: gain }`, gains finite in `[0,1]`, and `bindingsVersion: "0.42"`. |
| `@lute-lang/player` | `LutePlayer.make` accepts `cueFactory`; the handle exposes `snapshot`; media volume resolves only through `bindings.volumes`; replay uses `voiceKey`; `Director.make` wires `host.plugin`. |
| TypeScript tooling | Package `typecheck` scripts use `bun check`; `build` retains `tsc` for declaration emit. CI pins Bun `1.4.3` and compares Bun and `tsc --noEmit` once for this release. |
| npm | `@lute-lang/lute`, the three platform packages, `@lute-lang/runtime`, `@lute-lang/player`, and `@lute-lang/player-web` publish `0.42.0` in lockstep. |

Out of scope: other repositories, C ABI/native bindings, concurrent
presentations, a numeric volume syntax, accepting both old and new volume
members, or a second compatibility schema line.

## 3. Volume domain and bindings (#77)

### 3.1 Story vocabulary

`volume` remains a project domain, not a numeric type and not a relative
operation. A music command's `volume` is an absolute member of the resolved
project `volume` domain. Repeating a member has no accumulation semantics.
The templates, docs and corpus use this ordered documented scale:

```yaml
enums:
  volume: [silent, quiet, normal, loud, full]
```

A project MAY define a different `volume` domain. Its members are still
absolute levels and are not renamed by the release migration.

### 3.2 Binding shape and checking

`player.bindings.yaml` gains a top-level map:

```yaml
bindingsVersion: "0.42"
volumes:
  silent: 0
  quiet: 0.25
  normal: 0.5
  loud: 0.75
  full: 1
```

`volumes` is optional for backward decoding but a project that has a
`volume` domain is checked as follows:

1. Every key MUST be a member of the folded project's `volume` domain. An
   unknown key is `E-BINDING-KEY` (error), message
   ``volume binding key `<key>` is not declared`` with the existing
   did-you-mean suffix where applicable.
2. Every declared `volume` member MUST have a key. A missing key is
   `W-BINDING-MISSING` (warning), message
   ``declared volume member `<member>` has no binding``.
3. Every gain MUST be a finite number in `[0, 1]`; a non-number, NaN,
   infinity, or out-of-range value is `E-BINDING-SHAPE` (error), at the YAML
   value span. The checker MUST NOT clamp malformed configuration.
4. A project without a `volume` domain does not receive member diagnostics;
   an authored music `volume` still receives the normal checker diagnostic for
   an unknown domain/member.

The player resolves a member only through this table. An absent command volume
means gain `1` (the 0.41 default). A present member with a missing/invalid
runtime lookup resolves to gain `0`, never to full volume. Numeric values are
not parsed; a numeric value in a hand-built record is treated as unresolved,
not as a gain. The final gain is clamped defensively to `[0,1]` after lookup.

### 3.3 `lute fix` migration

The fix table adds one project-conditional rule. It applies only when the
project's **folded** `volume` domain is exactly the ordered old documented set
`[silent, down, normal, up, full]` (same members and order; no extra members,
no missing members). For such a project, `lute fix` rewrites, preserving
comments, quoting, key order and layout:

- the domain declaration `down` → `quiet` and `up` → `loud`;
- `volume` member values in `.lute` commands and YAML CEL/domain/member
  references;
- matching `volumes` keys, if present.

It MUST NOT rewrite a project with a custom set such as `low`, `muted`,
`raised` or `alarm`, even if it contains `up` or `down` as an unrelated value.
A run that has already migrated is a no-op; running `lute fix` twice produces
byte-identical output after the first run. The rule contributes one applied
fix per rewritten token to the existing summary. A project whose old domain is
split across declarations is eligible only after folding yields exactly the
old set; ambiguous or conflicting declarations are not rewritten.

## 4. Runtime Event records (#78)

### 4.1 Which records carry `attrs`

The runtime currently dispatches these staging commands as records:
`bg`, `music`, `sfx`, `vfx`, `actor`, `camera`, `cg`, `video`, and `sequence`
(see Appendix B). In 0.42 every one of those record kinds MUST carry
`attrs`, always an object (use `{}` only when a kind has no fields). This is
intentional: hosts can consume an output without reopening artifacts or
indexing `(document, position)`. Non-staging records retain their 0.41 shape;
plugin records continue to carry their existing `attrs`.

`attrs` is the command's resolved fields, with the same rules as 0.41 §5.5:
authored values and declared defaults are typed/resolved at compile time;
state-dependent CEL is not shipped as CEL text; timing keys `wait`,
`duration`, and `delay` stay in `timing`; provenance and plugin cross-cutting
`stampAttrs` stay at their existing top-level locations. `position`, `kind`
and `family` are record envelope fields, not members of `attrs`.

### 4.2 Per-kind shapes

Optional fields are omitted, not set to null. Required/defaulted fields are
present exactly as the IR command supplies them.

| kind | `attrs` fields |
|---|---|
| `bg` | `location?`, `time?`, `assetId?` |
| `music` | `playback?`, `stop?`, `mood?`, `volume?`, `assetId?` (volume remains the resolved domain member) |
| `sfx` | `sound?`, `assetId?` |
| `vfx` | `type` (required), `label?`, `transition?` |
| `actor` | `character` (required), `anchor?`, `action?`, `exit?`, `emotion?`, `costume?`, `posReset?`, `preload?` |
| `camera` | `focus?`, `framing?`, `move?`, `transition?` |
| `cg` | `assetId` and `display` (resolved default `show`) plus `layout?` |
| `video` | `assetId` and `display` (resolved default `show`) |
| `sequence` | `name` (required) |

The Rust Event and snapshot types, `lute-events-0.42.schema.json`,
`lute-snapshot-0.42.schema.json`, generated TypeScript `Contract.ts`, and
all conformance JSONL must agree with this shape. The player cue factory
consumes `attrs` as the authoritative resolved command fields; it MAY retain
an artifact lookup only for presentation-only text/cast data, never to recover
media fields.

## 5. Player API

### 5.1 `LutePlayer.make` cue seam (#79)

The documented public seam is:

```ts
export type CueFactoryWrapper =
  (base: CueFactoryShape) => CueFactoryShape

export type LutePlayerOptions = LutePlayerStart & {
  readonly bindings: Bindings | string
  readonly presenter: Presenter
  readonly audio: AudioPort
  readonly assets: AssetLoader
  readonly host?: PlayerHost
  readonly cueFactory?: CueFactoryWrapper
  readonly linePacing?: LinePacing
  readonly autosave?: Autosave
}
```

`LutePlayer.make` constructs the default factory, applies `cueFactory` once,
then gives the resulting factory to the director. The wrapper MUST preserve
`fromOutput`'s one-cue-per-output-event and event order unless the host
explicitly accepts responsibility for those invariants. `cueFactory` is not a
second plugin API; plugin handlers use `host.plugin` (§5.3).

### 5.2 Snapshot handle (#79)

```ts
export interface LutePlayerHandle extends DirectorHandle {
  readonly session: Runtime.Session.SessionShape
  readonly program: Runtime.Program.Program
  readonly snapshot: Effect.Effect<SaveRuntime, Errors.RuntimeRejection>
}
```

`handle.snapshot` is serialized with `send` and `restore` on the player
session's own lock—the same lock that `send` takes—and therefore has a
precise linearization point. The session commits the runtime state, accepted
input log and backlog atomically under that lock. A call made while a batch is
running waits for the lock and returns the last committed point: normally the
point after the most recent accepted input, never a partially updated
runtime/log/backlog generation.

It returns one coherent `SaveRuntime` containing:

- `snapshot`: the runtime snapshot (contract version, project fingerprint,
  await/request, world and continuation); the continuation includes the
  pending `Stage`, so stage is captured and no separate stage field is added;
- `log`: the start entry (`{seed}` or `{snapshot}`) followed by every runtime
  input accepted by the session;
- `backlog`: all replayable line entries, including each line's `voiceKey`.

It does not capture renderer fibers, active timers, presenter overlays,
profile settings/read marks, or host/plugin fibers. `restore(save)` remains the
existing `DirectorHandle.restore` operation: its only input is a `SaveRuntime`;
it checks the project fingerprint/version, restores runtime snapshot + log +
backlog, clears rollback history, removes abandoned read marks, rewrites the
autosave when enabled, restores stage/music, and re-presents the await. A
snapshot call fails only with `Errors.RuntimeRejection`; it does not fail with
`DirectorBusy` and does not mutate the player.

The player test takes a snapshot while a batch is blocked in a presenter cue,
then completes/abandons that batch, restores the snapshot, and asserts the
same await, stage, log length and backlog as the last committed point. A
snapshot taken before the input and one taken after the accepted input are
both valid checkpoints; neither can contain half of the in-flight batch.

### 5.3 Director plugin wiring (#80)

`Director.make` MUST accept `host?: PlayerHost` and a default cue-factory
construction seam (the existing hand-composed `DirectorOptions` is migrated
so the director can build the same default factory as `LutePlayer.make` from
its bundle, bindings and optional wrapper). It passes `host.plugin` into the
factory, so a plugin handler is a waiting cue in both composition paths. A
missing handler remains bookkeeping; there is no silent no-op caused by
forgetting a second wiring call.

**Spec decision:** when both a factory is pre-composed with
`Cues.make({ plugin })` and `host.plugin` supplies a handler for the same tag,
`host.plugin` wins for that tag; tags present in only one map remain available.
This makes the explicit host option authoritative and prevents a stale
pre-composed handler from shadowing the host. The merge is deterministic and
never runs both handlers.

### 5.4 Voice replay (#70)

`BacklogEntry` and the `replayVoice` action/event carry `voiceKey` alongside
`lineId`. A backlog replay MUST call `voiceFile(bindings, entry.voiceKey)`,
using exactly the key used by the original line cue. `lineId` is for display
and identity only and MUST NOT be used as a voice filename fallback. A missing
voice binding is a no-op as before; a different `lineId`/`voiceKey` pair must
still replay the original file.

## 6. TypeScript checks and CI (#68)

The `typecheck` script in `packages/runtime`, `packages/player`, and
`packages/player-web` is `bun check`. `build` retains the existing `tsc`
declaration-emitting path. Bun is pinned to `1.4.3` in every workflow under
`.github/workflows/` (including docs, publish, test and VS Code extension).

For exactly the 0.42 release, the checked-in
`scripts/compare-typecheck.sh <package-dir>` helper is wired into the
`runtime`, `player`, and `player-web` CI jobs. It MUST:

1. run with `set -euo pipefail`, create `tmp=$(mktemp -d)`, and install
   `trap 'rm -rf "$tmp"' EXIT`;
2. run `bun check --no-pretty --all -p <package-dir>` and
   `bunx tsc --noEmit --pretty false -p <package-dir>`, capturing each
   complete stdout/stderr stream and exit status without letting the first
   failure suppress the second;
3. parse both streams with the same expression
   `^(.+)\(([0-9]+),([0-9]+)\): error (TS[0-9]+): (.*)$`, normalize each
   match to a sorted unique `relative/path.ts:line:column TSdddd` record,
   and discard Bun's `Found N errors in M file(s), checked K files [...]`
   summary. The `-p` argument is the package directory and paths are made
   relative to it; messages after the code are not part of the comparison;
4. print both exit statuses and a unified diff of the normalized sets, then
   fail if either command's pass/fail status differs from the other or if the
   sets differ. A failed command with an empty extracted set is still a
   failure.

`--no-pretty --all` is mandatory because Bun's default output is
environment-dependent (pretty terminal output versus agent XML-like output)
and without `--all` Bun groups identical errors after the first 50. These
flags force the same tsc-compatible diagnostic lines in every CI environment.
The D slice tests this helper with a fixture containing one known error whose
expected line is
`a.ts(1,14): error TS2322: Type 'string' is not assignable to type 'number'.`
and therefore yields the same one-record set from both commands, plus a
mismatched fixture and a command-failure/empty-set case. The comparison is
removed after 0.42.0; package `typecheck` remains `bun check` and `build`
remains the only normal `tsc` declaration-emission surface.

## 7. Breaking changes and migration

| CHANGELOG class | Breaking change | Migration |
|---|---|---|
| Language | documented `volume` members `down`/`up` become `quiet`/`loud`; numeric volume is not accepted | run `lute fix` only for the exact old domain; custom domains migrate manually; author absolute members |
| Bindings | `bindingsVersion` and schema line move to 0.42; new `volumes` map is checked against `volume` | add one finite gain per domain member; do not rely on an unmapped member (it resolves to 0) |
| Event | nine media/staging record kinds gain resolved `attrs`; Event/snapshot schemas move to `-0.42` | regenerate consumers; read `attrs`, not artifacts, for media fields |
| Player API | `BacklogEntry`/replay events carry `voiceKey`; numeric `musicVolume` parsing is removed | persist the key from line output and resolve voice by key; use bindings volume members |
| Player API | `Director` construction uses the unified cue-factory seam; explicit host plugin wins over a pre-composed duplicate | pass `host.plugin` and migrate custom composition to `cueFactory(base)` |
| Tooling/CI | package `typecheck` now means Bun's checker; Bun pin is 1.4.3 | use `bun check`; keep `tsc` only for build/declarations |
| Release | all seven packages and all contract axes stamp 0.42.0 | widen version gates and install the matching package line |

## 8. Tests, conformance and CLI identity

Rust tests cover: exact-set and custom-domain `lute fix` (including
idempotence), `E-BINDING-KEY`, `W-BINDING-MISSING`, gain shape/range, all nine
record `attrs` shapes/defaults, schema generation, and 0.42 version stamps.
Player tests cover volume lookup (absent, each member, missing, malformed),
wrapper order/one-cue preservation, `snapshot` contents and rejection,
Director plugin precedence, hand-composed parity, and voice replay where
`lineId != voiceKey`. CI tests run both typecheck implementations and the
normalized-set comparison once.

The late conformance regeneration adds representative records for every
staging kind and the volume members, plus snapshot/event contract fixtures.
The CLI snapshot delta is limited to 0.42 stamps, `lute fix` volume migration,
new binding diagnostics, media records' `attrs`, migrated corpus members, and
help/version text that names the new release. No unrelated ordering or prose
change is accepted.

## Appendix A — spec decisions

| § | Decision | Reason |
|---|---|---|
| 1 | All axes, including schema line and `bindingsVersion`, move to 0.42.0/0.42 | clean lockstep release and no mixed contract line |
| 3.1 | `volume` remains an absolute project domain, with the ordered documented five-member scale | numbers/relative names cannot be statically checked or composed |
| 3.2 | absent command volume means gain 1; a present unmapped member means gain 0 | preserve 0.41 default while ensuring an unmapped member never silently becomes full volume |
| 3.3 | exact old member set includes order and is the only `lute fix` trigger | custom project vocabularies must not be rewritten |
| 4.1 | all nine runtime staging record kinds carry attrs, not only music/sfx/vfx | all are emitted staging records and hosts otherwise need artifact joins |
| 4.2 | attrs omits envelope/timing/stamp keys and optional absent fields | same resolved-field rule as 0.41 §5.5 and no duplicate ownership |
| 5.1 | `cueFactory` is a one-time wrapper over the default factory | public seam without a second factory convention |
| 5.2 | snapshot error channel is only `Errors.RuntimeRejection`; stage lives in runtime continuation | snapshot is a runtime operation, not a director command, and SaveRuntime already captures stage |
| 5.3 | `host.plugin` wins on duplicate tags | explicit host configuration is authoritative; run one handler |
| 6 | compare normalized diagnostic sets, and remove the A/B comparison after 0.42 | simple, deterministic one-release compatibility check |
