# Scenario DSL 0.30.0

0.29 made every name an identifier so it could follow a `.` in a condition.
That forced authors to rename what their engine already spells
(`zero-coke-001`, `lab-b2`, `001`), and 0.29.1 had to carve engine-owned ids
back out. CEL itself answers the question the way JavaScript does: a name that
is not an identifier is reached with an index, `m["zero-coke-001"]`. 0.30
adopts that.

## 1. One name rule

Every name an author writes that a condition reaches by path, index or fact
argument — ids of scenes, beats, entries, quests, objectives, branches, hubs,
choices and marks; document id segments; `share` keys; seasons, relations,
enum and entity kinds and members; plugin occasions and events; targets and
categories — is a **name**: one or more of letters, digits, `_` and `-`, not
starting with `-`. A dotted id joins names with `.`.

A name read bare as `@name` — defs, def params, component and template
params — stays an identifier, like a JavaScript variable: there is no quoted
spelling of a reference.

`.`, whitespace, quotes and other characters are errors at the name, under the
slot's existing code. The reserved-name table (`E-RESERVED-NAME`) is
unchanged.

0.29.1's split between "Lute-declared names" and "engine-owned ids" is gone:
what matters is how a name is read — by path (a name) or as `@name` (an
identifier).

## 2. Writing a name in a condition

A name that is an identifier (a letter or `_`, then letters, digits or `_`)
may be written bare. Any name may be written quoted. The two spellings are the
same name.

| Where | Bare | Quoted |
|---|---|---|
| A path segment | `quest.zeroCoke001.state` | `quest["zero-coke-001"].state` |
| A family member | `run.visits.labB2` | `run.visits["lab-b2"]` |
| A fact argument | `holds(at(labB2))` | `holds(at("lab-b2"))` |
| A comparison | — | `occasion.target == "lab-b2"` (as before) |

Single and double quotes are both accepted, as in CEL. The index must be a
string literal (or `occasion.target` / a template param, as before). This
applies to every place a condition is written, to `::set` / `::assert` /
`::retract` targets, `{{…}}` interpolation, Datalog rule bodies and heads, and
play/test/trace inputs (`--state 'run.visits["lab-b2"]=1'`, `state:` keys).

A name that is not an identifier written after a `.` (`quest.zero-coke-001`)
reads as subtraction in CEL. The checker reports it once, at the path, and
names the bracket spelling.

## 3. The artifact

Conditions ship to the engine as written: `quest["zero-coke-001"].state` is
valid CEL over the engine's state maps. Path fields in the IR (`set` targets,
state declarations, index entries) carry the canonical dotted string; a
segment may contain `-` and never contains `.`, so `split('.')` recovers it.

## Compatibility

- Names 0.29 refused for containing `-` or starting with a digit are
  accepted. Nothing 0.29 accepted is refused.
- `E-PATH-IDENT` now covers characters outside the name rule and a
  non-identifier name after a `.`; its advice names the bracket form instead
  of a camelCase rename.
- Additive for engines that evaluate CEL over nested maps.
