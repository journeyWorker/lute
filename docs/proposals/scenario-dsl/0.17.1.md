# Lute Scenario DSL — 0.17.1: No Language Change

- **Version:** 0.17.1
- **Status:** Draft (**alignment-only** revision of 0.17.0)
- **Date:** 2026-09-21
- **Scope:** no grammar production, no static-semantic rule, no IR shape, no
  `decide()` (§5.1 R1–R5) change, no Closure change. Language 0.17.1 is
  **byte-for-byte 0.17.0 semantics** for every document. The single change on
  this axis is the version stamp: `LUTE_LANG_VERSION` advances from `"0.17.0"`
  to `"0.17.1"` in the release that aligns the toolchain and the IR at the same
  number.

## 1. Why this file exists

This revision changes nothing an author writes. It is written down anyway,
because [`docs/versioning.md`](../../versioning.md) makes two commitments that
would otherwise contradict each other:

> Every release re-aligns every visible axis number to that release's number.

and

> **Language** … History is the versioned spec stack under
> [`docs/proposals/scenario-dsl/`](.).

Together they mean a language version with no entry in this stack is a hole:
a reader who resolves `luteVersion: "0.17.1"` against the stack finds nothing,
and cannot distinguish "this revision changed nothing" from "the revision was
never written down". `0.7.0` set the precedent for closing that hole, `0.10.1`
was the second, and this is the third.

## 2. What changes on the language axis

`LUTE_LANG_VERSION` → `"0.17.1"`. Nothing else. Every diagnostic code, grammar
production, admission rule, vocabulary slot, and `decide()` result is exactly as
`0.17.0` defined it. Historical citations of the form "dsl 0.17.0 §N" continue
to name the proposal that defined the rule and are **not** rewritten.

The IR advances to `0.17.1` under the same alignment rule and is likewise
shape-identical. `schemas/lute-ir-0.15.schema.json` is **not** renamed and its
`$id` does not move: the file's `0.15.x` title already covers `0.17.1`, the
runtime contract has gated on IR MAJOR only since `0.13.0`
([`docs/runtime/execution-model.md`](../../runtime/execution-model.md#version-negotiation)),
and a consuming engine that accepts a `0.17.0` artifact accepts a `0.17.1`
artifact with no edit.

## 3. What the release does change

`0.17.1` is a **repository hygiene** release: the public history was rewritten
so that every example, fixture, snapshot, and design note uses neutral,
self-contained names, and one internal adoption assessment that was never a
normative source was removed. Example cast and project identifiers changed
(same byte length, so every span and snapshot is unchanged); no checker,
compiler, LSP, or launcher behavior moved. Per
[`docs/versioning.md`](../../versioning.md)'s "which bump when" this is a
toolchain patch, and this stack does not earn its move.

## 4. Stale-stamp remedy

Because the language version advances, a document carrying
`luteVersion: "0.17.0"` now lags `LUTE_LANG_VERSION` and fires
**`W-LUTE-VERSION-STALE`** (dsl 0.6.1 §3). The stamp is still never validated
against capabilities (D13 stands); the warning is a freshness signal only. The
remedy is mechanical — restamp to `luteVersion: "0.17.1"` — and because
`0.17.1` is byte-for-byte `0.17.0` semantics, a `0.17.0`-clean document
restamped to `0.17.1` checks clean with no other edit.

## 5. Non-goals

- No grammar, semantic, or IR shape change.
- No new diagnostic code on the language axis and none removed.
- No change to the axis-independence policy. The axes MAY drift when an axis
  genuinely does not change; this release re-aligns the visible numbers so a
  single release presents a single number, and this file is where a reader
  learns that the language axis did not earn its move.
