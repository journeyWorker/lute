# Lute 0.42.1 — tooling and hygiene patch

This is the normative 0.42.1 contract, a patch release on the 0.42 contract
line. The words **MUST**, **MUST NOT**, **SHOULD**, and **MAY** have the RFC
2119 meanings.

## 1. Scope and version contract

The versioning rule in `docs/versioning.md` aligns every visible axis on every
release. The toolchain, language, IR, Event/snapshot stamps, player packages
and launcher packages read `0.42.1`. Schema filenames and bodies stay on the
`0.42` line.

| Axis | 0.42.1 rule |
|---|---|
| Toolchain | Cargo workspace, `lute version` and all seven npm packages stamp `0.42.1`. |
| Language | `luteVersion` stamps become `0.42.1`; grammar, checker semantics and diagnostics are unchanged. |
| IR | `irVersion` stamps become `0.42.1`; IR shape and the `lute-ir-0.42.schema.json` body are unchanged. |
| Event/snapshot | Stamps become `0.42.1`; shapes and schema bodies are unchanged. |
| Player bindings | `bindingsVersion` stays `"0.42"`; schema body and generated TypeScript are unchanged. |
| CLI | Help text changes as §3 specifies; no other command output changes. |

The release MUST NOT alter the bodies of
`schemas/lute-{ir,events,snapshot,player-bindings}-0.42.schema.json`,
`packages/runtime/src/generated/**` or `packages/player/src/bindings/schema.ts`.
Every command output captured by `scripts/cli-snapshot.py` MUST be
byte-identical to 0.42.0 after version-stamp normalization.

## 2. Rust formatting

The workspace's Rust sources MUST be formatted by rustfmt with its default
configuration; the repository carries no `rustfmt.toml`. The formatting change
MUST be a single commit that contains formatting only, and its hash MUST be
listed in `.git-blame-ignore-revs`. CI MUST run `cargo fmt --all --check` on
the pinned toolchain and fail on any difference. Formatting MUST NOT change
behaviour: the test suite and the CLI snapshot pass unchanged.

## 3. CLI help

1. The summary of each subcommand listed by `lute --help` (clap `about`) MUST
   be one sentence.
2. The detail previously used as the summary MUST remain available in that
   subcommand's `lute <command> --help` (clap `long_about`); no documented
   behaviour, exit code or flag description is dropped.
3. `lute --help` MUST be under 4096 bytes.
4. `lute fix`'s help MUST name the migrations it performs in 0.42.1: legacy
   line/choice syntax, literal `<when>` comparisons, 0.31 CEL calls to 0.32
   standard CEL, domain member renames, stale `luteVersion` stamps and the
   0.42 volume members.

## 4. Package checks

`scripts/compare-typecheck.sh`, its fixtures under
`scripts/test/compare-typecheck/`, the CI steps that run it and the
documentation of the comparison MUST be removed. Package `typecheck` scripts
remain `bun check`; `build` still emits declarations through `tsc`.

## 5. Repository hygiene

Python bytecode MUST NOT be tracked; `__pycache__/` is ignored. Documents under
`docs/design`, `docs/proposals` and `docs/superpowers` whose work has shipped
MUST read `status: Implemented`, and ones replaced by later work
`status: Superseded`.

## 6. Out of scope

Language, IR, Event, bindings or player API changes; `serde_yaml` replacement;
a structured JSON error envelope; `lute schema` introspection; output
projection. These are 0.43 candidates.

## Appendix A. Decisions

| § | Decision | Rationale |
|---|---|---|
| 2 | Default rustfmt configuration. | Measured smallest rewrite of the existing tree; no style debate to carry. |
| 2 | One formatting-only commit plus `.git-blame-ignore-revs`. | Keeps history readable and `git blame` useful. |
| 3 | Short `about`, unchanged detail in `long_about`. | Halves discovery cost for agents without losing documentation. |
| 4 | Remove the comparison now. | 0.42.0 scoped it to one release. |
