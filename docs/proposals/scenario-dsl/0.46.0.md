# Lute 0.46.0 — Brinewake dogfood: player-web host parity, named endings, play refusals, checker fixes

This is the normative 0.46.0 contract. The words **MUST**, **MUST NOT**,
**SHOULD** and **MAY** have their RFC 2119 meaning. Inputs are issues
#100–#112 from the first game built on `@lute-lang/player-web`; conservative
choices are listed in the decision note ("Orchestrator choices") and
Appendix A.

## 1. Scope and version contract

Every public version axis is `0.46.0`: toolchain, `luteVersion`, `irVersion`,
`eventVersion`, `snapshotVersion`, the seven npm packages and the generated
contracts. The contract schemas move to the `0.46` line
(`schemas/lute-{ir,events,snapshot,player-bindings}-0.46.schema.json`), project
files use `bindingsVersion: "0.46"`, and the player's save and profile format
version is `"0.46"`.

| Axis | 0.46.0 contract |
|---|---|
| Language | A component param may not be named `at` or `instance` (§2.1). No syntax or lowering change; compiled output of every valid document is unchanged apart from stamps. |
| IR / Event / snapshot | Shapes unchanged; stamps and schema line only. |
| Bindings | `ui.ended` added (§3.2); `ui.*` asset references resolve like the player (§3.1). Schema body changes only by `ui.ended`. |
| Runtime | Unchanged. Package peers: §5.5. |
| Player core | Unchanged. |
| player-web | Mount parity (§5.1), private assets (§5.2), name plate (§5.3), ending screens (§5.4). |
| CLI | Coverage merges play arms (§4.1); play `expect: { refused }` (§4.2); diagnostics of §2–§3. |
| Docs | Clock HUD and clock-following backdrop recipes (§6.1–§6.2), end-to-end tutorial (§6.3). |

## 2. Checker

### 2.1 Reserved `::use` names as component params (#100)

A `::use` site reserves `component`, `when`, `at` and `instance`: none of them
is ever bound to a component param (`at` is a timeline clip's offset —
`E-AT-CONTEXT` elsewhere; `instance` is the use's identity). A component (or
beat template) that declares a param with one of these names MUST be refused
once, at that `params:` entry, with `E-TEMPLATE`; the message MUST name the
reserved list (`component`, `when`, `at`, `instance`) and suggest a rename.
Beat-template header keys keep their existing rule. Uses of such a component
are not additionally diagnosed for the param (the declaration error explains
them).

### 2.2 Entity kind shape message (#108)

Entity kinds keep one spelling: `{ members: [...] }` or `{ open: true }`. When
an entity kind's value is a YAML list, `E-ENTITY-KIND-SHAPE` MUST show the
exact corrected spelling with the author's members, e.g.
``entity kind `spot` must declare exactly one of `members:` or `open:` — write `spot: { members: [bellRope, bellFooting] }` ``.
Other shapes keep their message apart from naming the `{ members: [...] }`
form. The list form stays an error (no second spelling).

## 3. Bindings

### 3.1 `ui` asset references (#104)

Every asset reference under `ui` — `ui.title.background`, `ui.title.music` and
`ui.ended.screens.<member>.background` (§3.2) — resolves as player-web
resolves it: a value that is a key of `assets:` refers to that entry (and
counts as a use of it for `W-BINDING-UNUSED`; its file is checked through the
`assets:` entry); any other value is a file below `assetsBase` and MUST exist
(`E-BINDING-FILE`). Before 0.46.0 the checker read `ui.title.background` as a
path only and did not look at `ui.title.music`.

### 3.2 `ui.ended` — named ending screens (#112)

```yaml
ui:
  ended:
    by: run.ending
    screens:
      restore: { title: "The Bell Rings Again", text: "Brinewake keeps its light.", background: dawnHarbor }
      retire:  { title: "Quiet Water", text: "You hand the bell rope to Ivo." }
```

- `ui.ended` is optional. When written, `by` (a state path) and `screens` (a
  map) are REQUIRED; a screen has REQUIRED `title` and `text` strings and an
  optional `background` asset reference (§3.1). Unknown keys are
  `E-BINDING-SHAPE`.
- `by` MUST name a declared state field (no index) whose type is a domain with
  a closed member list — an enum domain, or an entity kind declared with
  `members:`. Otherwise `E-BINDING-KEY` (unknown path, or a field that is not
  closed-domain-typed).
- Each `screens` key MUST be a member of that domain; an unknown key is
  `E-BINDING-KEY` with the usual nearest-member suggestion. A member without a
  screen is not diagnosed: it shows the stock ended screen.
- The JSON schema (`lute-player-bindings-0.46.schema.json`) and the generated
  TypeScript `Bindings` type gain the same optional section.

## 4. Tooling

### 4.1 Coverage counts play arms (#106)

`lute test --coverage` MUST count the `match` arms and guard outcomes executed
by the expect-carrying play scripts it runs in the same arm table as those of
scenario-test traces (keyed by source site, merged like two traces). A `match`
taken only by plays therefore reports its arms executed. The human header no
longer says plays do not count toward match arms; it reads
`coverage over N traced path(s) and M play(s) (plays count toward what they presented, the choices they picked and the arms they executed):`.
The JSON shape is unchanged (only counts change). Projects without plays MUST
produce byte-identical coverage output.

### 4.2 Plays can expect a refused raise (#107)

An `occasion:` step MAY carry `expect: { refused: E-OCCASION-GATE }`. On any
other step (`advance`, `newRun`, `engine`, `event`, `end`) `refused` is a
play-script error (an `advance:` that meets a closed raise keeps its 0.45
behaviour: the clock moves and the raise is noted as closed).

- When the step's input is refused with that code (an occasion whose
  `raisedWhen` is false, or the game is over and the occasion is not
  `outsideRun`), the expectation holds, the state stays as it was before the
  step, and the play continues with the next step. `lute play` prints the
  refusal as a note on that step instead of halting.
- When the step is accepted, the expectation is a miss
  (`expected the raise to be refused with E-OCCASION-GATE; it was accepted`),
  and the play continues; `lute test` reports the play FAIL.
- `refused` accepts only `E-OCCASION-GATE` (any other value is a play-script
  error naming the accepted code). It MAY be combined with `state`, `facts`,
  `notFacts`, `clock` and `quests` (checked against the unchanged state) and
  MUST NOT be combined with `winner`, `offered`, `notOffered`, `presented` or
  `options` (play-script error: a refused raise presents nothing).
- A play without `refused` runs, prints and reports byte-identically to
  0.45.0.

## 5. Packages

### 5.1 player-web mount parity with `LutePlayer.make` (#102)

- `MountOptions` = `LutePlayerStart & { bindings, bundleUrl, wasmUrl,
  assetsUrl?, storageKey?, host?, cueFactory?, linePacing?, autosave? }`:
  `seed` | `snapshot` | `session` (mutually exclusive, as in
  `LutePlayerStart`), `cueFactory`, `linePacing` and `autosave` have the same
  types, defaults, meaning and validation as `LutePlayer.make`'s options and
  are passed to it unchanged.
- The Effect handle (`WebPlayerHandle`) is the `LutePlayerHandle` (with
  `send`, `snapshot`, `restore`, `program`, `session`, `view`, `actions`)
  plus `bundle`: the `Bundle` the player loaded.
- `mountPlayer` (Promise facade) resolves to `{ act, view, unmount, send,
  snapshot, restore, session, program, bundle }`. Each Promise method runs the
  handle's Effect of the same name and resolves with its value or rejects
  with its failure; `session`, `program` and `bundle` are the handle's values
  (`session.current` holds the state `program`'s queries take). No other
  behaviour.
- The custom-hosts recipe "resume in a fresh player from a save" works with
  player-web (`mount(element, { …, snapshot })`) and is shown for it.

### 5.2 player-web does not use Pixi's global `Assets` (#103)

player-web MUST NOT initialise or load through Pixi's global `Assets`
singleton. Each mounted player owns a private asset manager (its own loader,
resolver and cache) with the parsers it needs; textures it loads are not in
the global cache. A host that calls `Assets.init({ basePath })` after `mount`
keeps its `basePath` and gets no "already initialized" warning.

### 5.3 Name plate shows the speaker (#111)

In player-web's dialogue window the name plate's background MUST be drawn
below the speaker name (background first in the plate container, reused on
every relayout). A browser test MUST show a named line's plate contains the
speaker's name above the background.

### 5.4 Ending screens (#112)

When the player shows its ended screen and `ui.ended` is bound, player-web
reads the member from the ended state with the existing read-only query
`program.view(state).state[by]` (`WorldView.state` is the effective state
keyed by full path, e.g. `"run.ending"`), where `state` is the session's
current (ended) state. If the value is a string that `screens` maps, it shows
that screen's `title` in place of "The End", its `text` in place of the
subtitle and, when given, its `background` (resolved like
`ui.title.background`) behind the screen. An absent value, an unmapped
member, or no `ui.ended` shows the stock screen; so does a failing query
(the screen never blocks on it). The decision applies whatever the ended
`reason`. "Back to title" is unchanged. No runtime or player-core change.

### 5.5 Bun host install (#105)

`@lute-lang/runtime` declares its Bun platform dependencies as exact, optional
peers on the Effect release line it is built against (`effect@4.0.2`,
`@effect/platform-bun@4.0.2`, `@effect/platform-node-shared@4.0.2`). The
runtime README, `docs/runtime/typescript-runtime.md` and the website runtime
page (EN/KO) document the Bun-host install line:

```sh
bun add @lute-lang/runtime effect@4.0.2 @effect/platform-bun@4.0.2 @effect/platform-node-shared@4.0.2
```

A fresh Bun project installing the packed tarballs with that line resolves one
Effect line and `import * as RuntimeBun from "@lute-lang/runtime/bun"` runs.

## 6. Documentation

### 6.1 Clock for a HUD (#109)

No contract change. `Program.clock(state)` stays numeric (`day`, slot
**index**). The runtime-contract page (EN/KO) and `typescript-runtime.md`
MUST say that slot names and weekday labels come from
`program.view(state).clock` and show a HUD snippet using it.

### 6.2 A backdrop that follows the clock (#101)

No language change: directive fields stay build-time values. The clock page
(EN/KO) documents the recipe — an enum domain for the slots, the slot state
field typed by it, a def reading it, a component taking the slot as a param
and matching on it, and `::use` in each scene — and the alternative of
writing `time` per scene.

### 6.3 End-to-end tutorial (#110)

One tutorial for 0.46 on the website (EN + KO) over a complete project
`docs/examples/quayside/`: schema + clock → scenes/beats/barks → plays (with
a refused raise) → bindings (with `ui.ended`) → a player-web host (map
outside the player, occasions, background barks, save/resume). Every Lute and
YAML block is checked by `scripts/check-doc-snippets.py` against the project;
the project passes `lute check-project --deny-warnings` and `lute test`.

## 7. Not developed (documentation only)

- #108 — the entity-kind list shorthand is not accepted (§2.2 message).
- #109 — `Program.clock` keeps indexes (§6.1).
- #101 — no runtime-resolved directive fields and no `fromState:` lowering
  (§6.2). Candidate later, only with a second game's evidence: a player-side
  opt-in where a background binding without an authored `time` follows the
  current clock slot.

Out of scope: canon issues, C ABI, `--fields`, `--agent`, `patch` batch
input, per-report JSON Schema, dynamic bark line queries.

## 8. Breaking changes and migration

| Class | Change | Migration |
|---|---|---|
| Language/checker | A component param named `at` or `instance` is `E-TEMPLATE` at its declaration (before: every use failed, or the param could never be passed). | Rename the param. |
| Bindings | `ui.title.background`/`ui.title.music`/ended backgrounds resolve `assets:` keys first; a non-key value must be an existing file below `assetsBase` (`ui.title.music` is now checked). | Fix the path or bind it through `assets:`. |
| Bindings | Optional `ui.ended`. | None. |
| Tooling | Coverage counts play arms; the human header text changed. | Update tools that match the header. |
| Tooling | Play `expect: { refused: E-OCCASION-GATE }`. | None. |
| player-web | `MountOptions` start/options, `bundle` on the handle, Promise methods; private Pixi assets (textures are no longer in Pixi's global cache). | Hosts that relied on player-web filling the global `Assets` cache load their own assets. |
| Runtime package | Optional exact peer `@effect/platform-node-shared@4.0.2`. | Bun hosts: use the documented install line. |
| Release | All axes stamp `0.46.0`; schemas `-0.46`; `bindingsVersion: "0.46"`; saves/profiles `"0.46"`. | Widen version gates; update `bindingsVersion`. |

## Appendix A — decisions

See the decision note: reserved `::use` names `component`/`when`/`at`/`instance`
under `E-TEMPLATE`; one resolution rule for `ui` asset references; `ui.ended`
codes reuse `E-BINDING-KEY`/`E-BINDING-SHAPE`, unmapped members silent;
ending screens resolved by player-web through read-only queries; `MountOptions`
takes the whole start union; Promise facade thin; `refused` limited to
`E-OCCASION-GATE` and to state-reading companions; play arms include guards;
optional exact `@effect/platform-node-shared` peer; tutorial over
`docs/examples/quayside/`; one llms mirror update.
