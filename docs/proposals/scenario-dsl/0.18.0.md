# Lute Scenario DSL — 0.18.0: Range patterns and `is=` over `test="$ == …"`

- **Version:** 0.18.0
- **Status:** Draft
- **Date:** 2026-09-24
- **Scope:** the `<when is="…">` literal pattern (0.1.0 §7.3.1) gains ONE new
  literal kind — the inclusive numeric **range** `N..M`, `N..`, `..M` — and a
  declared `number` subject becomes a coverage-checkable domain (interval
  union over the reals). One new error (`E-WHEN-RANGE`), one new warning
  (`W-WHEN-TEST-LITERAL`) with an automatic `lute fix` migration, and
  `E-WHEN-LITERAL-DOMAIN` / `E-NONEXHAUSTIVE` / `W-OVERLAP-ARMS` /
  `E-ARM-DEAD` / `W-OTHERWISE-DEAD` extend to numeric subjects. The tree-sitter
  `when_literal` token widens to lex every range shape; `capabilityVersion` is
  unchanged.
- **IR:** no shape change. A range arm lowers to the existing comparison
  operators (`>=`, `<=`, `&&`) in `MatchArm.expr`; the IR restamps to 0.18.0
  per the alignment rule.

## 1. Motivation

`<match>` has two ways to say what an arm matches. `is="gold | silver"` is a
**pattern**: the checker knows exactly which values it covers, so it proves
exhaustiveness, catches typos against the subject's domain
(`E-WHEN-LITERAL-DOMAIN`), and finds dead arms (`E-ARM-DEAD`). `test="…"` is a
**CEL guard**: arbitrarily expressive, and therefore opaque — coverage can
only be recovered from it conservatively.

The examples and docs nevertheless taught the guard form for plain literal
comparisons — `test="$ == 'gold'"`, `test="$ == true"`, `test="$ in
['silver','bronze']"` — because it predates `is=` and because numeric
thresholds (`$ >= 2`) had no pattern form at all. The result: the most common
arm shape paid CEL's quoting cost (`'gold'` inside `"…"`) and the checker saw
less than it could.

0.18.0 closes both gaps: ranges give numeric thresholds a pattern form, and a
warning plus a mechanical `lute fix` move literal-comparison guards onto
`is=`. `test=` remains the tool for genuinely computed conditions.

## 2. Range literals

```
WhenPattern ::= Literal ( WS? "|" WS? Literal )*
Literal     ::= EnumMember | "true" | "false" | Number | "unset" | Range
Range       ::= Number? ".." Number?        ; at least one bound
```

```lute
<match on="run.shedPressure">
  <when is="2..">
    @vesna: Two. We can't carry two.
  </when>
  <when is="1">
    @vesna: One. All right. One I can carry.
  </when>
  <otherwise>
    @vesna: Nothing moved. Good.
  </otherwise>
</match>
```

- Both bounds are **inclusive**. `N..` has no upper bound, `..M` no lower
  bound. Bounds are `Number` literals (signed, decimal): `-3..-1`,
  `0.5..1.5`. `2..2` is the point `2`.
- An alternative containing `..` is **always** a range. It never falls back to
  an enum member (member idents cannot contain `.`).
- A malformed range — `..`, `a..b`, `1...2`, `1..2..3` — or an empty one
  (`3..1`, lower bound above upper) is **`E-WHEN-RANGE`**, anchored at the
  literal. Such a literal covers nothing.
- A range whose subject is resolved and **not** numeric (a `bool`/`enum`
  decl, a `scene.choices.*` branch, a declared `string`) is
  **`E-WHEN-LITERAL-DOMAIN`**. Point `Number` literals keep their 0.4.0
  behavior unchanged.
- Ranges mix freely with other literals in one alternation
  (`is="..0 | 5.."`) and with a `test` guard (`is` + `test` is AND, 0.1.0
  §7.3.1).

**Lowering.** Per alternative: `N..M` → `subject >= N && subject <= M`,
`N..` → `subject >= N`, `..M` → `subject <= M`; alternatives OR together
exactly as point literals do. No new IR operator or record kind.

**Exclusive bounds** are not expressible as a pattern. `test="$ > 2"`
remains the form for them (§6 D-C).

## 3. `W-WHEN-TEST-LITERAL` and the `lute fix` migration

A `<when>` without `is=` whose `test` is exactly one of the following shapes
is **`W-WHEN-TEST-LITERAL`** (warning), anchored at the `test` attribute:

| `test=` | Rewrite |
| --- | --- |
| `$ == L` / `L == $` | `is="L"` |
| `$ in [L1, L2, …]` | `is="L1\|L2\|…"` |
| `$ >= N` / `N <= $` | `is="N.."` |
| `$ <= N` / `N >= $` | `is="..N"` |
| `$ >= A && $ <= B` (either conjunct order, `A <= B`) | `is="A..B"` |

`L` is a string, bool, or number literal. The rewrite is offered only when the
resulting pattern **classifies to the same value**: a string literal must be
an identifier-shaped member name (`^[A-Za-z_][A-Za-z0-9_-]*$`) other than
`true` / `false` / `unset` — so `'1'` (a string that would become the number
`1`), `'true'`, `'a b'` are left alone. `>`, `<`, `!=`, `null`, `@ref`
guards, and any other expression are not flagged.

The rewrite is meaning-preserving — both forms lower to the same
`MatchArm.expr` — so it rides `Diagnostic.fixits` with `kind: "migrate"`:
the LSP offers it as a quick fix and `lute fix` applies it automatically
(the `persist="run"` precedent, 0.4.0 §7.2 — not the `refactor`-only
`W-CHOICE-INTO-NO-PERSIST` precedent, whose remedies change meaning). The
only artifact difference is the debug `MatchArm.test` string, which is empty
for an `is`-only arm, as it has been since 0.1.0.

`test="$ == …"` stays **valid**: this is a style warning, not a
deprecation, and no document's meaning changes.

## 4. Numeric coverage

A subject declared `number` (schema decl or component param) has the
**number domain** — the real line — instead of the opaque infinite domain.
Coverage over it is the union of the arms' unguarded intervals (a point `n`
is `[n, n]`, an open end is ±∞):

- **Exhaustive** (`E-NONEXHAUSTIVE`, `is_exhaustive` for definite
  assignment) iff the union is the whole line and — for a maybe-unset
  subject — `unset` is covered, exactly as for finite domains. The
  `E-NONEXHAUSTIVE` message names the first uncovered gap. Numbers are real:
  `is="..0"` + `is="1.."` leaves `(0, 1)` uncovered; `is="..0"` +
  `is="0.."` is exhaustive (first match wins at `0`).
- **`W-OVERLAP-ARMS`**: a point literal (or degenerate range such as `2..2`)
  already covered by an earlier arm. A range that partially overlaps earlier
  coverage does **not** warn — `is="3.."` then `is="1.."` is the descending
  threshold cascade, and first-match-wins is exactly what it relies on. A
  range wholly inside earlier unguarded coverage is `E-ARM-DEAD`.
- **`E-ARM-DEAD`**: an arm whose whole `is` set lies inside the union of
  earlier **unguarded** arms (`is="1..5"` then `is="2..4"` or `is="3"`).
- **`W-OTHERWISE-DEAD`**: unguarded `is` arms already cover the whole line
  (plus `unset` where applicable).

String and other opaque subjects keep the infinite domain: `<otherwise>`
remains mandatory for them.

## 5. Diagnostics

| Code | Grade | Status |
| --- | --- | --- |
| `E-WHEN-RANGE` | error | new — malformed or empty range literal (§2) |
| `W-WHEN-TEST-LITERAL` | warning | new — literal-comparison `test` that `is=` expresses; `migrate` fixit (§3) |
| `E-WHEN-LITERAL-DOMAIN` | error | extended — a range against a resolved non-numeric subject (§2) |
| `E-NONEXHAUSTIVE` | error | extended — number-domain interval coverage; message names the first gap (§4) |
| `W-OVERLAP-ARMS`, `E-ARM-DEAD`, `W-OTHERWISE-DEAD` | — | extended — interval-aware on number subjects (§4) |

## 6. Compatibility

- Every 0.17.x document is a valid 0.18.0 document. No existing literal
  changes meaning: an `is=` alternative containing `..` was previously an
  enum-member string that could never match (member idents cannot contain
  `.`), so no working document relied on it.
- New diagnostics on existing documents: `W-WHEN-TEST-LITERAL` (warning,
  `lute fix` clears it) and — on `number` subjects only — any newly provable
  `E-ARM-DEAD` / `W-OVERLAP-ARMS` / `W-OTHERWISE-DEAD` between point literals
  (`1` and `1.0` are now the same point).
- IR: no shape change; documents without ranges compile byte-identically
  apart from the version strings. Migrated documents (`lute fix`) emit an
  empty debug `MatchArm.test` for the rewritten arms; `expr` is unchanged
  except that `$ in [a, b]` becomes the equivalent `==`/`||` tree.
- Tree-sitter: `when_literal` widens to lex `..M` and signed bounds as one
  token. A grammar regeneration, not a capability restamp.

## 7. Decisions

| # | Decision | Rationale |
| --- | --- | --- |
| **D-A** | ranges are intervals over the reals | Lute's `number` is real-valued and there is no integer type; claiming `..0 \| 1..` exhaustive would be false for `0.5`. Introducing an integer type is a separate, larger change |
| **D-B** | `..` inside an alternative is always a range, never a member | a misspelled range must fail loudly (`E-WHEN-RANGE`), not become a silently dead string comparison |
| **D-C** | inclusive bounds only | matches `<reward amount="N..M">` (0.16.0), keeps one range notation in the language; exclusive thresholds stay `test` guards |
| **D-D** | a new `Domain::Number`, not a finite approximation | coverage over reals needs interval arithmetic; the opaque infinite domain stays for strings and unresolved subjects so nothing there changes |
| **D-E** | `W-WHEN-TEST-LITERAL` is a warning with a `migrate` fixit, not a deprecation | the rewrite provably preserves meaning, so `lute fix` may apply it unprompted; the guard form stays legal for authors who prefer it |
| **D-F** | the lint only rewrites literals that round-trip through the `is=` classifier | `'1'` → `is="1"` would turn a string comparison into a number comparison; the safe subset is decided by the same classifier the checker and compiler use |
