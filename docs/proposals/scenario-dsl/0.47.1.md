# Lute 0.47.1 — fix patch

This is the normative 0.47.1 contract, a patch release on the 0.47 contract
line. The words **MUST**, **MUST NOT**, **SHOULD** and **MAY** have their RFC
2119 meanings. Inputs are issues #132, #133 and #134.

## 1. Scope and version contract

The toolchain, language, IR, Event/snapshot stamps, player packages and
launcher packages read `0.47.1`. Schema filenames and bodies stay on the
`0.47` line.

| Axis | 0.47.1 rule |
|---|---|
| Toolchain | Cargo workspace, `lute version` and all seven npm packages stamp `0.47.1`. |
| Language | `luteVersion` stamps become `0.47.1`; `\{{` is literal text in compiled output as dsl 0.1.0 §7.6 always said (§3). |
| IR | `irVersion` stamps become `0.47.1`. No field change, **one meaning change**: in a line's `text`, segment runs and merged translations a literal `{{` is written `\{{` (§3). Engines that substitute placeholders themselves MUST apply §3. The schema's "escapes decoded" wording for `cmdLine.text` / `segment.text` is superseded by §3; the `lute-ir-0.47.schema.json` body stays byte-identical. |
| Event/snapshot | Stamps become `0.47.1`; shapes and schema bodies unchanged. |
| Player bindings | `bindingsVersion` stays `"0.47"`; schema body and generated TypeScript unchanged; `flow.*.target` checked in its prefixed form (§2). |
| Player | Save/profile format stays `"0.47"`. player-web camera transitions end visible (§4). |

The release MUST NOT alter the bodies of
`schemas/lute-{ir,events,snapshot,player-bindings}-0.47.schema.json`,
`packages/runtime/src/generated/**` or `packages/player/src/bindings/schema.ts`.
Every command output captured by `scripts/cli-snapshot.py` MUST be identical
to 0.47.0 after version-stamp normalization, except outputs §2–§3 change
(listed in the plan).

## 2. Bindings `flow.*.target` (#133)

A `flow` target (`flow.newGame.target`, `flow.idle.raise.target`, each
`flow.idle.menu[].target`) is a full occasion target, the value the runtime's
`raiseOccasion` takes: for an occasion whose `target` is a domain
`{ prefix, entity, members? }` it is `<prefix>.<member>` (e.g. `place.square`).
`check-project` MUST validate it with the rule beat targets and play step
targets use (`occasion_target_ok`): an `open:` kind admits any
`<prefix>.<id>`; a closed kind or a `members:` subset admits exactly its
members under the prefix. Anything else — including the bare member `square` —
is `E-BINDING-KEY` with that rule's message (it names the domain and, when
close, `did you mean \`place.square\`?`; for an `open:` kind it names the
`<prefix>.<entity>` form with no hint), prefixed `flow target \`…\`:` so the
binding is named. As in plays, an occasion with `target: true` accepts any
target and a target on an occasion without one (`target: false` or absent) is
`E-BINDING-KEY`. An occasion whose entity kind the project does not declare
makes its flow targets `E-BINDING-KEY` too (the rule's message). The
bindings docs (website `player/bindings.md` EN/KO, `docs/player/bindings.md`)
MUST say that targets are written in the prefixed form.

## 3. Escaped interpolation (#134)

dsl 0.1.0 §7.6: `\{{` in a line writes a literal `{{`.

- **One source rule.** Every scanner of line text — the inline parser
  (`parse_inline_nodes`), the placeholder scan (`scan_interps`), label
  scanning, the literal-text check and the normalizer — MUST agree on which
  `{{` is escaped: the inline parser's backslash counting (an odd run of
  backslashes directly before `{{` escapes it). Tests that pinned a
  disagreeing scanner change.
- **IR encoding.** The compiler decodes escapes as today into the plain text,
  knowing which `{{` are literal. In the IR line `text`, each segment run's
  `text`, and merged `texts` / `localeSegments`, it then writes every literal
  backslash that directly precedes a `{{` (literal or marker) doubled, and a
  literal `{{` as `\{{`. Every other backslash and every other escape stays as
  decoded today. It MUST emit one `placeholders` entry per marker, in order.
- **Engine reading.** Scan left to right. A run of n backslashes directly
  before `{{` stands for ⌊n/2⌋ literal backslashes; if n is odd the `{{` is
  literal text (consumed as one unit before looking for the next `{{`), if
  even it opens a marker substituted from `placeholders` in order. The Lute
  runtime MUST do this for the source text, the segments and the by-marker
  rendering of translations (0.47.0 §2.2); its rendered line record holds the
  decoded text (no encoding backslashes).
  `Lit \{{run.a}} and {{ run.a }}.` with `run.a = 3` renders
  `Lit {{run.a}} and 3.`; `:speed[x\\]{rate=2}{{run.a}} end.` keeps rendering
  `x\3 end.` in `text` and segments alike.
- A translation MAY contain `\{{`; it is literal there too (this replaces the
  0.47.0 note that a translation cannot show a literal marker equal to a
  source marker).
- `loc export` `sourceHash` is computed from the compiled `text` (now
  encoded), so a fresh export stays equal to the hash `compile --locales`
  compares; a 0.47.0 export of a line with `\{{` gets `W-L10N-STALE` (§7).
- The IR contract docs (`docs/runtime/execution-model.md`,
  `docs/runtime/event-contract.md`, website `tooling/runtime-contract.md`
  EN/KO, `language/dialogue-and-cast.md` EN/KO where it describes `text`,
  `player/custom-hosts.md` EN/KO which repeats the 0.47.0 translation
  limitation, the `lute context` lowering text in `cmd_context.rs` and the
  pages quoting it) MUST state the rule.

## 4. Camera transitions (#132)

The camera layer's resting state is alpha 1 with no mask. In player-web a
camera cue with a `transition` (and no `move`; a `move` keeps precedence) MUST
run as follows. For a hiding effect (`fade`, `dissolve`, `fadeOut`, the
`wipe*` and `slide*` effects, `slideOut`): the effect hides the camera layer
over the first half of the transition's duration; the framing and focus are
applied; the layer is shown again over the second half (alpha back to 1, a
wipe reveal, a slide back into place). Any other effect: the framing is
applied, then the effect plays as today. Whatever the effect, when the cue
finishes the layer has alpha 1, no mask, and the new framing's scale and
position. `cut`, `none`, a zero duration and an instant cue (skip, load) apply
the framing at once. Restoring the stage (load, rollback) cancels running
camera behaviours, sets alpha 1 and no mask, then applies the framing, so a
load during a transition never leaves the actors hidden. `cameraMove` effects
are unchanged. A browser test on the compiled player-demo MUST show the actors
drawn after its opening `::camera{framing="wide" transition="fade"}`, and the
other transitions the demo uses (`dissolve`, `wipeLeft`) MUST end visible,
and a load during the fade cue MUST leave the actors drawn. The player-web
docs (website `player/getting-started.md` EN/KO and
`docs/player/web-architecture.md`) describe the camera transition.

## 5. Testing

Each fix has a regression test that fails on 0.47.0. Player / player-web
behaviour is tested against real runtime output (compiled fixtures, the
browser suite over compiled bundles), never a hand-written view or record.

## 6. Out of scope

Everything else; option labels are attribute strings and do not accept `\{`.
