# Lute Scenario DSL — 0.15.0: Authored scene identity

- **Version:** 0.15.0
- **Status:** Draft
- **Date:** 2026-09-01
- **Scope:** the language axis gains ONE new scene frontmatter key — `id:` —
  which, when present, is the canonical scene key everywhere the derived
  `{character}.{episodeId}` join is consumed today, and relieves
  `character`/`season`/`episode` of their required status; plus ONE new
  descriptive frontmatter block — `meta:` — legal on scene and quest roots,
  never read by language semantics. Three new diagnostic codes (`E-META-ID`,
  `E-META-VALUE`, `W-META-LEGACY`), one narrowed condition
  (`E-META-MISSING`), one generalized message (`E-CONN-EPISODE-ID-DUP`).
  No grammar production changes — frontmatter is one opaque token, so the
  tree-sitter grammar and `capabilityVersion` are untouched.
- **IR:** `SceneMeta` gains required `id` (the resolved canonical key);
  `character`/`season`/`episode`/`episodeId` become optional, emitted when
  the source supplies them; `SceneMeta` and `QuestMeta` gain optional
  `meta` (the descriptive block, omitted when empty). A document that
  authors no `id:` compiles to the same artifact plus the added `meta.id`
  field — no other byte moves.
- **Design record:**
  [`docs/superpowers/specs/2026-09-01-lute-scene-id-design.md`](../../superpowers/specs/2026-09-01-lute-scene-id-design.md).

## 1. Motivation

The canonical scene key was the derived join `{character}.{episodeId}`, and
`character`, `season`, `episode` were required frontmatter. The language has
already outgrown that ontology in its own documentation:
`docs/schedule-and-play.md` instructs authors to write
`character: <event>-<variant>` and treat `season:`/`episode:` as "opaque,
frozen identity numbers", and the flagship corpus writes `character: anseo` —
a work title. Three required keys had degenerated into an opaque id authored
in three pieces, two forced to be integers. Meanwhile quest documents have
carried identity as one authored `<quest id>` since 0.2.0 §7 ("prefix = the
enclosing stable declaration id"). `0.15.0` completes that generalization
for the scene root kind and gives the demoted keys a sanctioned home.

## 2. `id:` — the authored canonical key

Scene-only frontmatter. Value: non-empty, `[A-Za-z0-9_.-]+` — a superset of
every key the derived fallback can produce, with `.` admitting namespacing
(`anseo.s01ep01`). Anything else is **`E-META-ID`**, anchored at `id:`.

When present, `id:` IS the canonical scene key, uniformly:

- the lineId prefix (`identity:` templates' `{prefix}`, dsl 0.8.0 §9) and
  the structural choice/hub option ids `{prefix}.{branchOrHubId}.{optionId}`;
- `visited('…')` targets (`after:` on scenes, `after=` on quests), including
  the nearest-key suggestion on `E-CONN-UNKNOWN-NODE`;
- connectivity nodes, reachability, and project-wide duplicate detection;
- `prereqEdges[].node` in the artifact and the document key in
  `project.index.json`;
- the runtime visited-set entry `lute play` records after presentation.

When absent, every site derives `{character}.{episodeId}` exactly as
0.14.0 — the fallback is the existing code path, so an untouched project's
lineIds, translations, `visited()` references, and `schedule.yaml` behavior
do not move. (`schedule.yaml` never consumed the canonical key at all — it
addresses documents by project-relative path.)

With `id:` present, `character`/`season`/`episode` are no longer required:
**`E-META-MISSING`** fires only on documents whose defaults-merged
frontmatter lacks `id:`. Authored and derived keys share one namespace and
one project-wide uniqueness rule: **`E-CONN-EPISODE-ID-DUP`** keeps its code
(tooling stability; renaming is churn without information) but its message
now names the *canonical scene id*, and an occurrence contributed by an
authored `id:` anchors at that key instead of `character:`.

`id` is NOT defaultable — it must be per-document unique, so a manifest
supplying one to many documents can only manufacture collisions. It stays
outside `defaults:`' closed key set (`E-DEFAULTS-KEY`, 0.10.0 D-P).

## 3. `meta:` — the descriptive block

One reserved frontmatter key holding an **open mapping**: keys free, values
scalars (string / int / bool / float) or flat lists of scalars. A nested
mapping or a non-scalar list entry is **`E-META-VALUE`**, anchored at the
offending key. Legal on Scene and Quest roots; Schema and Component
documents reject it through the existing kind gate.

`meta:` carries **no language semantics**: not readable from CEL, not a
state path, not a template token, consulted by no checker, compiler, or
runtime rule. It is serialized verbatim into the artifact meta (`meta`,
omitted when empty) so external tooling — search, TMS, editors — can key on
it. This split is what lets the top level stay closed: free-form keys go
under `meta:`, and `E-META-UNKNOWN-KEY` keeps catching top-level typos.

`meta` joins `defaults:`' closed key set; 0.10.0 §6.2's whole-value-per-key
rule applies unchanged — a document authoring any `meta:` replaces the
manifest's entirely.

## 4. Deprecation — quiet legacy, loud coexistence

A document that authors `id:` and ALSO authors any of `character:`,
`season:`, `episode:`, `episodeId:` in its **own** frontmatter draws one
**`W-META-LEGACY`** per key, anchored at that key: identity now comes from
`id:`; move the value under `meta:` if it should stay searchable.
Promotable with `--deny`.

The pass reads the authored frontmatter, never the defaults-merged view: a
manifest-inherited `character:` on an `id:`-carrying document is silent —
the document's author wrote nothing to move. (Required-key and unknown-key
enforcement continue to run over the merged view, as 0.10.0 §6 fixed.)

A document with no `id:` warns nowhere. The derived path is fully
supported; it is deprecated in prose only, and its removal is deferred to a
future major. `pov:` and `after:` carry semantics and are untouched.

## 5. IR delta

| Field | Change |
| --- | --- |
| `SceneMeta.id` | NEW, required — the resolved canonical key (authored `id:` or the derived join), so no consumer rederives it |
| `SceneMeta.character` / `.season` / `.episode` / `.episodeId` | now optional; emitted when the source supplies them (a legacy document keeps all four) |
| `SceneMeta.meta` / `QuestMeta.meta` | NEW, optional — the §3 block, omitted when empty |

`LUTE_LANG_VERSION` and `LUTE_IR_VERSION` move to `0.15.0`; the artifact
schema becomes `schemas/lute-ir-0.15.schema.json` (sceneMeta requires `id`,
legacy four optional, `meta` a free object of scalars/scalar-lists; questMeta
gains `meta`). All seven conformance fixtures restamp; the five scene
fixtures re-accept the added `meta.id`. Consumers gating by IR **major**
(runtime contract) are unaffected.

## 6. Diagnostics

| Code | Grade | Status |
| --- | --- | --- |
| `E-META-ID` | error | new — malformed `id:` value |
| `E-META-VALUE` | error | new — non-scalar(-list) value under `meta:` |
| `W-META-LEGACY` | warning | new — authored legacy identity key coexisting with authored `id:` |
| `E-META-MISSING` | error | narrowed — fires only when merged frontmatter lacks `id:` |
| `E-CONN-EPISODE-ID-DUP` | error | message generalized to "canonical scene id"; authored occurrences anchor at `id:` |
| `E-DEFAULTS-KEY` | error | unchanged; `meta` joins the closed set, `id` deliberately does not |

## 7. Compatibility

- Every 0.14.0 document is a valid 0.15.0 document unchanged; no key changed
  meaning, `id:`/`meta:` are additions.
- lineId/voiceKey derivation, `loc export/import`, `compile --locales`, and
  `schedule.yaml` resolution are byte-for-byte unaffected on documents that
  author no `id:`. The only artifact delta on such documents is the added
  `meta.id`.
- Grammar, tree-sitter snapshot, `capabilityVersion`, plugin surface,
  `*.test.yaml`, and mocks are untouched.

## 8. Decisions

| # | Decision | Rationale |
| --- | --- | --- |
| **D-A** | `id:` is opt-in with the derived join as fallback, not a hard cutover | lineId is the localization/VO join; forcing re-authorship would churn every translation table for a naming preference |
| **D-B** | `E-CONN-EPISODE-ID-DUP` keeps its code | a rename breaks downstream `--deny` configs and log tooling to convey no new information; the message carries the generalization |
| **D-C** | `W-META-LEGACY` reads authored frontmatter, not the defaults-merged view | a manifest-inherited key is not the document author's to move; warning on it would be undischargeable at the document |
| **D-D** | `id` outside `DEFAULTABLE_KEYS`, `meta` inside | a defaulted unique key can only manufacture collisions; a defaulted descriptive block is the feature's point |
| **D-E** | `SceneMeta.id` always emitted, legacy fields kept when supplied | consumers (`index`, `play`) stop rederiving identity; legacy fields stay for search/inspection without a second required shape |
| **D-F** | `meta:` values limited to scalars / flat scalar lists | keeps the block trivially searchable and diffable; nesting invites structured config the language would then be pressured to read |
