# Lute Scenario DSL — 0.26.0: Scale and many authors

- **Version:** 0.26.0
- **Status:** Draft
- **Date:** 2026-09-26
- **Scope:** everything round 4 (a Pokemon-scale monster-collecting RPG, one
  lead and four area writers in parallel) asked for:
  `lute-dogfood/round4/TRIAGE.md` T1-1…T1-8, T2-1…T2-10, T3-1…T3-13, D-1…D-8.
  One minor, no separate patch (nobody depends on 0.25.x yet).
- **IR:** additive — directive `when`, component param defaults, occasion
  target kinds, `occasion.target` reads.

## 1. Scale (T2-1)

- The fact analysis computes the app-tier seed closure (seeds + everything the
  rules derive from them) **once per project root** and extends it
  incrementally (semi-naive) with the facts a path asserts. A slot that reads
  no fact (`holds`/`count`) skips the closure.
- `lute test` loads and checks the project **once** and shares it across every
  scenario test and play; tests run in parallel on all logical cores
  (`RAYON_NUM_THREADS` respected), reported in the existing order.
- No on-disk cache in 0.26: an incremental cache pays only when nothing
  relevant changed, and a play depends on the whole project. Revisit for
  LSP/watch.
- Target (Monster League, 818 beats, 211 static facts): `check-project` < 1 s,
  a play load < 1 s, `lute test` < 10 s on an 8-core machine.

## 2. Many authors

### 2.1 State declared in several documents (T1-1)

`check-project` collects every frontmatter `state:` declaration. Declarations
of one path MUST agree on `type`, `default`, `per` and `owner`; otherwise
`E-STATE-DECL-CONFLICT` naming both files and lines. Play keys state by path
and declared type.

### 2.2 Duplicate members (T1-3)

A member listed twice in one entity kind or enum is `E-ENTITY-KIND-SHAPE`
(both positions). With §2.3, a member added by two files is the same error.

### 2.3 Kinds assembled across files (T2-2)

- A schema MAY add members to a kind declared in another imported schema:

  ```yaml
  entities:
    person: { add: [grannyWren, oldSalt] }
  ```

  Exactly one import declares the kind; `add:` without a base declaration is
  `E-ENTITY-KIND-SHAPE`.
- A `subsetOf:` child's members are members of the parent: a trainer listed in
  `trainer` (⊂ `person`) no longer needs a second line in `person`. Restating
  it in the parent is allowed (not a duplicate).

### 2.4 Defaults (T2-6)

- `defaults.uses` entries MAY be globs (`schema/areas/*.schema.yaml`),
  expanded in path order.
- `defaults.questTier: run | user` sets the default `tier=` of quests.

### 2.5 Engine content ids (T1-8, T2-10)

- A directive attribute MAY be typed by an entity kind:
  `item: { type: { entity: bagItem } }`; values are checked with a
  did-you-mean.
- A reward kind's `target:` contract is checked (`E-REWARD-TARGET`): an
  `{ entity: kind }` or provider contract validates the value; `required:
  true` rejects a missing target.
- `lute refs <dir> --attr give.item` (also `--reward ITEM`) lists every value
  with the documents using it, so a lead sees "who gives what" before a merge.

### 2.6 Checking a spine before the areas exist (T2-7)

Under `--wip`, an atom whose only producers are component asserts with unbound
params counts as unproduced for specific args, and
`E-OBJECTIVE-UNSATISFIABLE` / `E-BEAT-UNREACHABLE` caused only by missing
producers are warnings.

### 2.7 Diagnostics once, at the schema (T3-1)

`E-ENTITY-KIND-SHAPE` (sub-kind members), `E-USES-DUP-STATE` and
`E-USES-DUP-DEF` are anchored at the schema line and folded once
(`(+N more callers)`), like the other schema errors.

### 2.8 Display names (T3-13)

`lute lint` (and check-project as advisory `W-DISPLAY-NAME-DUP`) reports two
cast entries or speaker display names that are exactly equal.

## 3. Components

### 3.1 Parity with direct text (T1-2, T1-6)

- Directive result slots declared by a component's plugin directives are
  declared in the host (collected after splicing). A bridge answer is typed by
  the slot, or by the capability's `result:` shape; an untyped answer is
  refused, never stored as a string.
- `{{…}}` inside a string argument is interpolated with a placeholder record
  exactly as in direct text.
- A `speaker` param used in an attribute value (`as=@who`) renders the cast
  display name, as it does in text. A literal `{{@who}}` in an attribute value
  is interpolated.

### 3.2 Speaking as a param (T2-3.1)

`@@who: …` in a component body speaks as the cast member the `speaker` param
`who` names (portrait, voice, cast checks all apply). `@@x` for a non-speaker
param is `E-COMPONENT-ARG`.

### 3.3 Own results and defaults (T2-3.2, T2-3.3)

- A component MAY read the result slots of plugin directives in its own body
  (`scene.battle.<key>.won`); they are not ambient state.
- A param MAY declare `default:` (a literal or a `@def`); an omitted argument
  takes it.

Beat-shaped components (a component that declares its own beat) are not in
0.26.

## 4. Directives take `when=` (T2-4)

`::use`, `::accept`, `::assert`, `::retract`, `::give` and plugin passthrough
directives accept `when="<condition>"` with the meaning of `::set{… when=}`
(skipped when false; never a definite effect for the checker).

## 5. Occasions over a kind (T2-8)

A beat or entry MAY target a whole kind: `target="kind:bugMon"`. It answers
every member of the kind; the raised member is readable as `occasion.target`
in `when`, guards and text (`{{occasion.target}}`), typed by the kind. A
member-specific beat for the same cell outranks it at equal priority.

## 6. Rules

`count(R(_ , …)) <op> n` and `countDistinct` MAY appear in a rule body over a
relation the head does not depend on (stratified); otherwise
`E-RULE-AGGREGATE-CYCLE` (T3-9).

## 7. Test and play parity

- **`::next` (T1-4):** trace/test follow a taken `::next` to its target; they
  never report `complete` for a walk that stopped at a jump.
- **Handler accept (T1-5):** an `::accept` in a quest `<on>` handler is applied
  by trace/test exactly as by play.
- **Ineligible beats (T1-7):** `eligible:` works for scene documents too;
  `eligible: false` does not walk the body; a test that walks a beat whose
  `when` is false under its mocks fails unless it asserts `eligible:`.
- **Project mocks (T3-5):** `accepts:` resolves quests project-wide; a quest
  document may seed its own `quest.<id>.*`.
- **Transcript needles (T3-6):** `transcriptContains` strips line attributes
  from the needle; a miss shows the nearest presented line.
- **Clock in included steps (T2-5):** `advance: { to: night }` and
  `advance: { to: { weekday: Fri, slot: morning } }` move forward to the next
  such position (never backward); step `expect: { clock: { weekday, slot,
  day } }`.
- **External accept in play (T2-9):** `engine: { accept: [questId] }` accepts
  an `accept="external"` quest mid-play.

## 8. Checker and tools

- `W-BEAT-PRIORITY-TIE` normalizes negations (De Morgan) before the
  exclusivity check, uses the slot's Must set, and says why two `when`s are
  not exclusive (T3-2).
- `lute beats` shows `covered by <id>` for a fallback a higher-priority beat
  with an implied `when` always beats (T3-3).
- `W-ENTRY-WRITE-REREAD`: a repeatable entry whose body writes state or facts
  (T3-4).
- `E-FACT-DOMAIN` at `::use` gets a did-you-mean (T3-7); the
  `E-ENTITY-KIND-CLASH` hint offers renaming (T3-8).
- Play and test accept `<doc>.<entry>` as an alias for an entry id (T3-10).
- `lute scenario --facts` draws fact-producer edges
  (`scene(A) -> scene(B) [hasItem(x)]`) (T3-11).
- `lute-lsp` detects its own binary was replaced and publishes one "stale
  server, restart" diagnostic instead of stale results; `lute doctor --strict`
  exits non-zero on any ✗ (T3-12).

## 11. Decisions

| # | Decision | Rationale |
| --- | --- | --- |
| **D-A** | fix the recomputation, no disk cache | the cost was one closure recomputed per slot; a cache would hide it and invalidate on almost every edit |
| **D-B** | `add:` to extend a kind, one base declaration | an area adds members without a lead edit; one owner still defines the kind |
| **D-C** | `@@who:` for a speaker param | it is what every writer tried first |
| **D-D** | `when=` on directives, not a guard block | same meaning authors already use on `::set` |
| **D-E** | kind targets bind `occasion.target` | one beat for 12 bug species; the member stays typed |
| **D-F** | beat-shaped components deferred | largest item (L); `@@who`, defaults and `when=` remove most of the trainer boilerplate first |
