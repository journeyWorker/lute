# Lute Scenario DSL — 0.25.0: Exclusion, shared spends, graph edges

- **Version:** 0.25.0
- **Status:** Released (0.25.0, 2026-09-25)
- **Date:** 2026-09-25
- **Scope:** the items the 0.24.0 pre-release review left open as
  non-blocking (`lute-dogfood/round3/BACKLOG-0.25.md`, ids per game:
  LH lighthouse, CR crown, SU summer, ER ember). No new model area; each item
  closes a workaround a round-3 author still carries.
- **IR:** additive — `RelationDecl.excludes`, `BeatIr.share`, bundle
  `BeatIr.after`, placeholder format `ordinalWord`, `QuestCmd.accept` (`external`).

## 1. Exclusive relations (LH F17)

A relation MAY declare the relations it can never hold together with, on the
same arguments:

```yaml
relations:
  seenAfter: { args: [character], tier: run, excludes: [fell] }
  truthful:  { args: [character], tier: run, excludes: [liar] }
```

- `excludes` is symmetric: `fell` excludes `seenAfter` without restating it.
  Excluded relations MUST have the same argument kinds (else
  `E-RELATION-DECL`).
- The checker treats `holds(A(x)) && holds(B(x))` as false: a guard that needs
  both is dead (`E-ARM-DEAD` / `E-BEAT-UNREACHABLE`), and `!holds(B(x))` follows
  from `holds(A(x))` (so `W-FACT-GUARANTEED` / presence / exhaustiveness use
  it).
- A write or derivation that could make both hold is checked where it is
  provable: an `::assert{A(x)}` on a path where `B(x)` is in the Must set is
  `E-FACT-EXCLUSIVE`. Where it is only possible, `lute play` / `lute trace`
  report the violation at the step (`✗ exclusive: seenAfter(elias) and
  fell(elias) both hold`), never silently.
- Derived relations may exclude each other; the play/trace check covers their
  derivations.

## 2. Shared spends (SU N9)

Beats that stand for one event in different places MAY share one spend:

```lute
<beat id="solRadio" on="talk" target="npc.sol" once="day" share="solWarm">
<beat id="solRoof"  on="talk" target="npc.sol" once="day" share="solWarm">
```

- Beats with the same `share` key (project-wide) are spent together: once one
  is presented, every beat of the key is spent for the `once` period.
- All beats of a key MUST declare the same `once` (else `E-BEAT-ATTR`);
  `share` without `once` is `E-BEAT-ATTR`.
- `lute beats` shows the key; the calendar and presence ladder treat the
  group as one spend.

This replaces the `::set{run.x = clock.index when=…}` day stamp.

## 3. Bundle beat `after=` (LH N9)

A bundle `<beat>` MAY carry `after="…"` with the same meaning as a scene's
`after:` (an eligibility conjunct and a scenario edge). A `visited()` conjunct
in a beat's `when` still gates but draws no edge; the hint on `lute scenario`'s
unanchored list suggests `after=`.

## 4. Quest graph edges (ER F17, N13)

- `lute scenario` draws `quest(parent) -> quest(child) [subquest]` for nested
  quests, so a parent with children is no longer listed as unanchored.
- A quest whose `start=` is a conjunction that includes `visited(...)`,
  `entry.X.everRead` or `quest.Y.state == …` is anchored by those conjuncts
  (`[start]` edges); a duplicate `after=` is no longer needed.

## 5. Externally accepted quests (LH N5)

- `<quest accept="external">` declares that the quest is accepted outside the script (a quest board, a menu, a UI): the moment is not in any document, and the engine
  accepts it whenever the player chooses. It silences `W-QUEST-NEVER-ACCEPTED` and is the only
  non-content source that does.
- A `*.test.yaml` / trace `accepts:` mock no longer counts as a source: a
  quest only a test accepts still warns, and the hint names `accept="external"`.

## 6. Presence after engine events (0.24 `assume: true` limit)

A reserved relation MAY name the occasions on which the engine may change it:

```yaml
relations:
  fell: { args: [companion], reserved: true, changedOn: [battleEnd] }
```

With `changedOn`, cast `assume: true` holds only for units that are not
after-descendants (`after:` / `after=` / `[start]` edges) of a unit presented
on one of those occasions. A line after the battle is checked again, so
`assume: true` no longer hides the post-battle bugs. Without `changedOn`,
0.24 behaviour stays.

## 7. Bridges

A bridge result field that no content reads MAY be omitted from a mock or
play answer; the hint lists only the fields content reads. A field content
reads is still required (`E-TRACE-MOCK-TYPE`).

## 8. Format hint `ordinalWord` (LH N10)

`{{run.day:ordinalWord}}` renders an ordinal word. The IR carries the hint;
the engine localizes it. `lute play` renders English words for 1–20
(`first` … `twentieth`) and falls back to `:ordinal` digits above.

## 9. Tooling

- `lute scenario knowledge`: a defeater lists every derivation route of the
  defeating atom, not only the first (LH N6).
- An undeclared `<match on>` subject under a broken schema import reports the
  import error and the undeclared path only, not a follow-on
  `E-NONEXHAUSTIVE` (SU N8).

## 10. Docs

Cheatsheet (en/ko) lists `//` line comments; a `{mono when=…}` example
(LH F4); the resolution base of `components:` (document directory) vs
`defaults: components:` (manifest directory) (CR D-3).

## 11. Diagnostics

| Code | Grade | Status |
| --- | --- | --- |
| `E-FACT-EXCLUSIVE` | error | new (§1) |
| `E-RULE-EXCLUSIVE` | error | new (§1): a rule derives a relation from one it excludes, on the head's own arguments |
| `E-RELATION-DECL` | error | new cause: `excludes` kinds mismatch, `changedOn` on a non-reserved relation or an undeclared occasion |
| `E-BEAT-ATTR` | error | new causes (§2) |

## 12. Decisions

| # | Decision | Rationale |
| --- | --- | --- |
| **D-A** | exclusion is declared on relations, not inferred | the author knows "a dead man is never seen after"; inference from rules cannot |
| **D-B** | a shared spend is a key, not a time read | "once a day, whichever place" is one event; a `presentedToday()` read would bring back the stamp logic |
| **D-C** | only `accept="external"` stands for acceptance outside the script | a test mock proves a test, not the game |
| **D-D** | presence ordering uses the scenario graph | occasions have no static order; `after:` edges do |
| **D-E** | `{vo}` stays exempt from presence, `{os}` stays checked; no remote-speaker flag yet | `{os}` means "in the scene, not on screen" (both of 0.24's real crown catches were `{os}`); add a remote flag when a game needs phone/radio lines |
| **D-F** | not planned: occasion names in a project-less `lute check <schema>` | no occasion list exists there; check-project reports them |
