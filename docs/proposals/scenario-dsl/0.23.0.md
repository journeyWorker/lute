# Lute Scenario DSL — 0.23.0: Author overviews and time

- **Version:** 0.23.0
- **Status:** Draft
- **Date:** 2026-09-25
- **Scope:** what a writer needs to see and say once a story is selected by
  occasions rather than read top to bottom: overviews of who can say what
  when (a beat ladder, a calendar, a knowledge map), windows and missed
  events, composing a routine with an event, several beats in one file, cast
  and reward vocabularies, and a sharper condition decider.
- **Evidence:** dogfood triage T2-8, T2-11, T2-12, T2-13, T2-14, T1-17, T2-7
  (`prev`), T2-9 (`cast`), T3-13, T3-16, T3-18.
- **IR:** additive — `IndexBeat.when` / `title`, `ObjectiveEntry.by` /
  `target`, `BeatIr.also`, occasion `select: sequence`, `LoreMeta` beat
  bundles, capability `cast` and `rewardKinds.credits`.

## 1. Overviews

- `IndexBeat` gains `when` (raw, expanded) and `title` (scene title / entry
  title).
- `lute beats <dir> [--occasion O] [--target T]` prints, per occasion and
  target, the beats in selection order with priority, `once`, `after:`,
  `when`, and the static verdicts (unreachable, shadowed, tied).
- `lute calendar <dir> --axis run.day=1..7 --axis run.slot=morning,afternoon,night
  [--occasion O …] [--script save.play.yaml]` evaluates, for every cell of
  the axes' product and every listed occasion (default: all), the eligible
  beats and the winner, starting from the script's seeds (0.22.0 §3). Output:
  a table (text), `--json`, or `--csv`. Beats never eligible in any cell are
  listed at the end.
- `lute scenario <dir> knowledge [--for <node>]` traces, for every
  fact-guarded beat/entry/objective, the relations its condition reads and
  their producers through rules (asserting documents, seeds, reserved).
- The `lute scenario` graph notes how many `visited()`/`completed()`
  references were left out because the referencing quest has no `after=`.

## 2. Windows and missed events

- `<objective by="<condition>">` — while the objective is not done, the first
  time `by` becomes true the objective **fails** (a required objective fails
  its quest). `by` is a condition slot like `done`.
- `<objective on="<occasion>" target="<target>">` — the objective is judged
  only when the occasion is raised for that target (the beat target rule).

## 3. Composing occasions

- Occasion `select: sequence` — the engine presents **every** eligible beat
  in selection order (a routine followed by the day's event).
- A scene beat MAY set `also: true`: on a `select: first` occasion, an
  eligible `also` beat is presented in addition to the winner, after it (a
  side remark that never replaces the main beat). `W-BEAT-SHADOWED` ignores
  `also` beats.

## 4. Beat bundles

A lore document MAY hold scene-like beats: `<beat id on target when priority
once>` blocks with a scene body (lines, choices, match, directives). A
bundle beat is a beat of the project in declaration order; its canonical id
is `<document id>.<beat id>`. `<hub prompt="…">` attaches a prompt line shown
with the hub's options.

## 5. Components with sentences

A component `string` param MAY be interpolated (`{{@p}}`); it is substituted
at expansion like other params (0.21.1). The localization key is the host
line's.

## 6. Previous run

`prev.run.<path>` reads the value `run.<path>` had when the previous run
ended (reserved, read-only, `unset` before the first `newRun`). The engine
snapshots it at run end; `lute play` does so at `newRun`.

## 7. Cast

A plugin or schema MAY export `cast: { <id>: { name: "…" } }`. When a cast is
declared, a speaker id outside it is `E-CAST-UNKNOWN` with a did-you-mean;
without one, speakers stay shape-only.

## 8. Rewards that credit state

A `rewardKinds:` entry MAY declare `credits: <state path>`; `lute run` / `lute
play` then add the reward amount to that path when granted, and a content
`::set` of that path in the same quest's handler is `W-REWARD-DOUBLE-CREDIT`.

## 9. The condition decider

`decide` treats a conjunction as a set of constraints per path: equalities,
disequalities, and numeric intervals. A conjunction whose constraints on one
path are unsatisfiable decides **false** (`run.n > 5 && run.n < 3`,
`run.slot == 'a' && run.slot == 'b'`, `x && !x`). A disjunction decides true
when its cases cover the path's domain. A negated fact atom whose positive is
Must-true decides false.

## 10. Work in progress

`lute check-project --wip` downgrades `E-ENTRY-UNREACHABLE`,
`E-BEAT-UNREACHABLE` and `E-OBJECTIVE-UNSATISFIABLE` caused by a relation
that has **no producer at all** to warnings (content not yet written). A
relation that has producers but can never match remains an error.

## 11. Interview menus

On `select: all`, index rows carry `title`, so an engine can label the menu;
an entry beat that is already read is marked `read: true` in the play
transcript's candidate list.

## 13. Decisions

| # | Decision | Rationale |
| --- | --- | --- |
| **D-A** | the calendar is a tool over play, not a schedule file | the day-clock VN proved beats express every cell; what was missing was a way to see them |
| **D-B** | `by=` fails on the first true | a deadline is an event, and "first time true" is observable by the engine without a clock |
| **D-C** | `also` over multi-winner `select: first` | keeps "one main beat per occasion" explainable while letting a remark ride along |
| **D-D** | bundles live in lore documents | lore already groups many ids in one file with series and categories |
| **D-E** | interval reasoning only in conjunctions | enough for every false negative the dogfood found; full SMT is not warranted |
