# Scenario DSL 0.31.0

## 1. Beat clock movement

A scene beat's frontmatter, or a lore `<entry>` / bundle `<beat>` declaration,
MAY carry `advances: slot`, `advances: day`, or `advances: <n>`, where `<n>` is
a whole number greater than zero. A declaration is metadata: the engine owns the
clock and performs the movement when the beat is presented. The compiled IR
carries the declaration as `advances: "slot"`, `advances: "day"`, or a number.

A scene example:

```yaml
---
kind: scene
id: market.main
on: slotStart
advances: slot
---
```

A lore beat uses an attribute:

```lute
<beat id="main" on="slotStart" advances="2">
@narrator: The bell rings twice.
</beat>
```

`advances` requires a declared project clock. `lute play` applies the move as
an `advance:` step would: clock state changes, quest deadlines settle, and the
clock's declared raises are presented. An explicit `advance:` immediately
duplicating a beat's declaration is a usage mistake and SHOULD be removed; the
beat declaration is the source of truth.

Only main beats and large hangouts should advance time. Talking, inspecting and
small side beats remain free. A missed run-tier timed event is retried in the
next run; permanent user-tier progress MUST NOT depend on a single slot.

## 2. Required-objective schedule diagnostics

`check-project` reports `W-OBJECTIVE-STRANDED` when a required objective can be
completed only by beats whose clock-bounded windows can all close, while the
objective declares neither `until=` nor `by=`. Add a deadline and a `failedBy`
handler (or otherwise handle deadline failure). A run-tier result in a project
whose clock resets per run is informational: it is retried on the next run.

`W-SLOT-CONTENTION` reports two required run-tier objectives whose only
advancing completing beats occupy the same single clock position. This is a
static calendar check; it does not perform path search.
## 3. Advance cascade safety

An `advances:` beat MUST NOT answer the same clock raise that presents it
without a guard or repetition policy that stops it at the next position.
`check-project` reports `E-ADVANCE-CASCADE` for an unguarded repeatable beat
whose own raise can present it again. Runtime play still bounds nested declared
advances at 64 presentations and reports the looping beat instead of hanging.


## 4. Main closer

No new objective attribute is required. A main beat is identified by its
`advances` declaration; it is the closer of the slot it advances from. The
notebook may recommend it without turning side discoveries into mandatory
checklist objectives.

## Compatibility and migration

`advances` is additive. Existing content is unchanged. Engines that previously
used plugin frontmatter `spendsSlot: true` / `spendsSlots: n` should migrate to
`advances: slot` / `advances: n`; the engine, not the plugin, moves the clock.
