# Lute 0.45.0 — stage meaning follows the lowered record; background barks; no concurrent presentations

This is the normative 0.45.0 contract. The words **MUST**, **MUST NOT**,
**SHOULD** and **MAY** have their RFC 2119 meaning. Conservative choices are
listed in Appendix A; evidence is in the decision note.

## 1. Scope and version contract

Every public version axis is `0.45.0`: toolchain, `luteVersion`, `irVersion`,
`eventVersion`, `snapshotVersion`, the seven npm packages and the generated
contracts. The contract schemas move to the `0.45` line
(`schemas/lute-{ir,events,snapshot,player-bindings}-0.45.schema.json`; bodies
change only in `$id`, title and version stamps), project files use
`bindingsVersion: "0.45"`, and the player's save and profile format version is
`"0.45"`.

| Axis | 0.45.0 contract |
|---|---|
| Language (semantics) | Implicit staging keys on the lowered record kind (§2). Documents using only core directives compile byte-identically. |
| IR / Event / snapshot / bindings | Shapes unchanged; stamps and schema line only. |
| Runtime | Unchanged; the read-only queries are documented as answering at every await (§3.1). |
| Player packages | No API change; documentation (§3). |
| CLI | Unchanged apart from the stamp and §2's effect on plugin-using projects. |

## 2. Stage meaning follows the lowered record (shape 2)

### 2.1 Rule

Implicit staging — the records the toolchain injects for stage hygiene
(`stage-bookkeeping`, `auto-anchor-on-show`, `entry-emotion-lookahead`,
`auto-pose-reset`, `stage-clear`) and the diagnostics that read the same
stage model (`W-STAGE-ABSENT`, `W-EXIT-INERT`) — MUST treat a directive by
the **staging record it lowers to**:

- a core directive by its own lowering (`::bg` → `bg`, `::actor` → `actor`,
  `::music` → `music`);
- a plugin directive declaring `lower: { record: <kind>, fields: {…} }` by
  `<kind>` and the record fields its `fields` resolve to, through the same
  resolution `lute compile` uses for the artifact;
- a builtin hook (`lower: { kind: builtin, name: … }`) as the core directive
  it names (unchanged since 0.24.0);
- any other directive (passthrough, bridge) as no staging record.

Per kind:

| Record kind | Stage meaning |
|---|---|
| `bg` | A scene change: every character on stage (or on stage on some path) leaves with an injected hide placed before the record, departures are recorded for `W-STAGE-ABSENT`, pending pose resets are dropped, and the background is recorded. |
| `actor` | `character` names the actor (none: no effect). `exit: true` takes them off stage. Otherwise, absent → an entrance (anchor default and first-emotion preload injected after the record when not written); present → a reposition, `action`/`emotion` mark the pose dirty. `posReset: true` resets the pose. `preload` does not change the stage model. |
| `music` | Bookkeeping only; never touches characters. |
| `cg`, `video`, `camera`, `sequence`, `sfx`, `vfx` | No stage-model effect (as before). |

For a core `::actor`, `exit` is set by lowering exactly when its `action` is a
member of the `action` domain's `exits:`; the rule above therefore reproduces
0.44's behaviour for core directives. `semantics:` flags still do not drive
staging (dsl 0.9.0 §7).

### 2.2 Output invariants

- Authored records MUST keep their relative order. Relative to 0.44.0, a
  document's compiled output MAY differ only by injected records appearing or
  disappearing where the rule places them (hides before a scene change, a pose
  reset before its line, an entrance's anchor/preload after it), with the
  positions that follow renumbered.
- A document whose directives are all core directives (or builtin hooks) MUST
  produce byte-identical `check`, `compile`, `trace`, `play`, `test` and
  `run` output to 0.44.0, apart from version stamps.
- No compatibility mode (D6).

`lute trace` marks an `actor` record with `exit: true` as an exit (as it marks
`::clear`), whichever directive produced it.

### 2.3 Amendment to the base spec §11.5

The base spec says implicit staging is implementation-defined. From 0.45.0 it
remains a toolchain rule (its exact injections are not part of the language),
but it MUST be a function of the staging records a document lowers to — kind
and fields — and MUST NOT depend on which directive produced a record. A
plugin author can rely on a directive lowered to `bg` changing the scene like
`::bg`, and on one lowered to `actor` staging a character like `::actor`.

## 3. Background barks during a conversation (host pattern)

### 3.1 Queries at every await

`candidates`, `evaluate`, `def`, `gate` and `view` (Rust `Runtime`, wasm,
TypeScript `Program`/`Session.program`, the player handle's `program`) read
the state and MUST NOT change it. They answer at `idle`, `awaitChoice`,
`awaitBridge` and `ended` alike (and, on a TypeScript session, during a
running input against the last committed state). Inputs are unchanged: while
a choice or bridge is pending only its answer is accepted (`E-RUNTIME-BUSY`).

### 3.2 The pattern

While the story waits at `awaitChoice` or `awaitBridge`, a host MAY show an
ambient bark outside the presentation:

1. `candidates(occasion, target?)` on the current state; take the first
   candidate with `verdict` eligible and `kind: "entry"`.
2. Find the document's artifact (`index.documents[].path == candidate.document`
   → `artifact`), the head `commands[i]` with `kind: "entry"` and
   `id == candidate.id`, and the body: the records from the head's `body`
   position up to the next `entry`/`beat` head.
3. The bark is **static** when every body record is a `line` with no
   `placeholders`. Its lines give `text` (or `texts[locale]`), `speaker`
   (display name `index.cast[speaker]`, none for narration), `voiceKey` and
   `lineId`.

Showing a static bark this way records nothing — no `entry.<id>.read`, no
`once` spending, no writes. A bark that must record (first read, `once`,
authored writes) or whose body is not static MUST be raised as its occasion
once the story is back at `idle`.

### 3.3 Not in 0.45

A query that resolves a beat's lines (placeholders, `match`, locales) without
stepping is a candidate, not part of 0.45.

## 4. Concurrent presentations

The runtime keeps one open presentation. Concurrent presentations are not
planned: a multi-speaker conversation is one scene, ambient lines are lore
barks, and a background line during a conversation is §3's pattern.

## 5. Out of scope

`--fields`, `--agent`, `patch` batch input, per-report JSON Schema, C ABI
(when the first native game exists), the beat-lines query (§3.3).

## 6. Breaking changes and migration

| Class | Change | Migration |
|---|---|---|
| Semantics | A plugin directive lowered to `bg` now changes the scene: characters on stage get injected hides before it, later lines by them warn `W-STAGE-ABSENT` until re-shown, and no pose reset is injected for them. One lowered to `actor` now stages its character (entrance anchor/preload, exit by `exit: true`, dirty pose). | Remove manual exits/`::clear` added as the 0.44 workaround if they are now redundant (they stay valid); re-show characters after a plugin scene change. |
| Release | All axes stamp `0.45.0`; schemas `-0.45`; `bindingsVersion: "0.45"`; saves/profiles `"0.45"`. | Widen version gates to 0.45; update `bindingsVersion`. |

## Appendix A — decisions

See the decision note: record kind as key (shape 2, not a flag); `actor`
included and keyed on `exit`; `posReset` honoured, `preload` neutral; no
compatibility mode; §11.5 amended; no new runtime query; concurrent
presentations dropped.
