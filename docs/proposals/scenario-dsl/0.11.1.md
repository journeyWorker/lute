# Lute Scenario DSL — 0.11.1: Branch Prompt & Timeout

- **Version:** 0.11.1
- **Status:** Draft — **backfilled 2026-08-26.** This revision shipped
  2026-08-19 (toolchain `0.11.1`) with its normative record living only in the
  changelog, violating this stack's own rule that a language version absent
  from the stack cannot be told apart from one nobody recorded (the `0.7.0` /
  `0.10.1` precedent). This file restores the record; it documents what
  shipped, byte-for-byte, and changes nothing.
- **Date:** 2026-08-19 (shipped) / 2026-08-26 (recorded)
- **Scope:** the language axis gains TWO optional attributes on `<branch>` —
  `prompt="…"` and `timeout="N"` — plus their two value diagnostics
  (`E-BRANCH-PROMPT`, `E-BRANCH-TIMEOUT`). No grammar production changes
  (both parse through the existing generic attribute production; the closed
  `<branch>` attribute set simply admits two more keys). `<hub>` is
  unchanged.
- **IR:** additive-only — the compiled `choice` record carries `prompt` /
  `timeoutSec` when authored and omits both fields entirely when not, so an
  artifact from a prompt-less document is byte-identical to `0.11.0`'s.
  Under the then-current major.minor gate the schema file stayed
  `lute-ir-0.11.schema.json`; the fields are published today in
  [`schemas/lute-ir-0.16.schema.json`](../../../schemas/lute-ir-0.16.schema.json).
  `capabilityVersion` is unaffected (`<branch>` is grammar, not a `lute.core`
  directive export).

## 1. Motivation

A `<branch>` names its options but not its question. Real choice UIs show a
situation sentence above the option labels ("The purser is waiting — what do
you do?"), and timed picks are a staple of the genre (choose within N seconds
or the moment passes). Both were previously host-side conventions with no
authoring surface: the sentence lived in a preceding content line the engine
had to guess was a prompt, and the countdown had no source of truth at all.

`prompt=` names what the choice is ABOUT. `timeout=` gives the pick a
positive-integer seconds budget, for hosts that run a countdown and emit a
timeout event when the reader does not choose. Both are author-optional;
every existing document is untouched.

## 2. Grammar (no production change)

Both attributes parse through the existing generic attribute production on
`<branch>` — the same path `id=`/`when=` already take. The change is to the
CHECKER's closed attribute set for `<branch>` (`logic_attrs.rs`), which
admits the two new keys instead of firing `E-UNKNOWN-ATTR`.

```
<branch id="dock" prompt="The purser is waiting — what do you do?" timeout="10">
  <choice id="talk" label="Talk to her">…</choice>
  <choice id="slip" label="Slip past">…</choice>
</branch>
```

`<hub>` deliberately does NOT gain either attribute: a hub is a revisitable
menu, not a dramatic beat — it has no single "question" and a countdown on a
menu is a different (undesigned) feature. `prompt=`/`timeout=` on `<hub>`
remain `E-UNKNOWN-ATTR`.

## 3. Semantics

- `prompt` is presentation data, verbatim: the checker never interprets it,
  the compiler copies it onto the lowered `choice` record, and the engine
  shows it above the option labels. It participates in no control flow.
- `timeout` is a budget in whole seconds. What happens at expiry is
  ENGINE-OWNED (this revision defines no default-option or timeout-branch
  semantics in the language); the artifact only carries the number. A
  document needing branching on expiry models it in state like any other
  outcome.

## 4. Validation

Two value diagnostics, both Error severity, both anchored to the attribute's
own span (`logic_attrs.rs::check_branch_value_attrs`):

- **`E-BRANCH-PROMPT`** — `prompt` MUST be a non-empty string (whitespace-only
  is empty). There is no "no prompt" spelling; an unprompted branch simply
  omits the attribute.
- **`E-BRANCH-TIMEOUT`** — `timeout` MUST parse as a positive integer number
  of seconds. `"0"`, negative, fractional, and non-numeric values are
  rejected: a countdown cannot count down from zero or a fraction the wire
  does not carry.

## 5. IR (additive)

The lowered `choice` command gains `prompt: string` and `timeoutSec: number`,
each present iff authored. Omission (not `null`) keeps prompt-less artifacts
byte-stable. `lute play` renders a prompted branch as
`▷ choice <id> "<prompt>" (<N>s): …` in playthrough transcripts.

## 6. What this does NOT change

- `<hub>`, `<match>`, `<choice>`-level attributes, and every existing
  `<branch>` attribute are byte-for-byte unchanged.
- No reachability, definite-assignment, exhaustiveness, or trace behavior
  reads either attribute.
- Documents that author neither attribute compile to byte-identical
  artifacts.
