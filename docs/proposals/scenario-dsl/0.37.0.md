# Scenario DSL 0.37.0

This specification is the normative 0.37.0 contract. It is a clean breaking
cutover under D6: an implementation MUST implement the surfaces below and MUST
NOT accept an old spelling as an alias or compatibility mode. The dogfood and
conformance corpora, documentation, website, tree-sitter grammar, LSP, schema,
CLI JSON, and runtime transcript all migrate in this release.

The source document remains the authoring authority. The execution IR and
project index are public versioned outputs. `position` is build-local execution
position; it is never identity, localization, patch, or save identity.

## 1. Scope and version contract

All visible version axes are `0.37.0`: toolchain, language (`luteVersion:`), IR
(`irVersion`), CLI/LSP/npm/Cargo stamps, and the current schema. The schema file
is `schemas/lute-ir-0.37.schema.json`. Historical proposal documents and
historical schemas remain historical records and are not rewritten.

The old forms are removed, not deprecated. A parser/checker MAY provide a
migration fix-it for a removed form, but a document containing that form is not
0.37 source until rewritten. An engine MUST reject an unknown command `kind` or
unknown IR envelope contract; it MUST NOT infer a renamed field from old data.

## 2. Surface vocabulary

### 2.1 Authoring case

Authoring attributes, tag attributes, frontmatter keys, project keys, and schema
keys use lowerCamelCase. A key containing `_` is rejected with `E-AUTHOR-CASE`.
This rule applies to new and existing keys; the checker message names the
lowerCamelCase spelling when it can derive one. IR JSON continues to use the
existing camelCase serialization convention.

## 3. Authoring contract

### 3.1 Sections and identity

A top-level section starts with `## ` followed by non-empty heading text. An
optional final suffix has exactly this form:

```text
## Heading text {#stable-id}
```

The suffix is removed from `heading`; `id` is the non-empty ASCII token
`[A-Za-z][A-Za-z0-9_-]{0,63}`. `id` is unique among sections in one document;
duplicates are `E-SECTION-DUP`. The IR section position is one-based document
order. `id` is identity metadata only: it is not a jump target and cannot be
used as a `::jump` label. A section without `id` retains a position fallback and
is reported as non-stable wherever identity metadata is exposed.
The first segment of a command `position` is this one-based section position;
remaining segments are command order within that section. It is regenerated
when source order changes and cannot be used as a durable identity.


`# title` is not a body title. It is an error (`E-INERT-TITLE`) whose message
says to put the value in frontmatter `title:`. The frontmatter title remains the
only document title.

### 3.2 Project-declared staging vocabulary

The existing closed-domain declaration is the vocabulary mechanism. Domains
are declared in document/schema `enums:` using either the short list or long
form. 0.37 reserves these domain names for staging slots:

| Domain | Used by | Default/semantics |
|---|---|---|
| `anchor` | actor `anchor` | `default` is used when omitted; existing stage rules apply |
| `action` | actor `action` and line `action` | `exits` members end actor presence |
| `emotion` | line/actor `emotion` | no implicit member |
| `framing` | camera `framing` | no implicit member |
| `cameraMove` | camera `move` | no implicit member |
| `transition` | camera `transition` | no implicit member |
| `cgLayout` | cg `layout` | no implicit member |
| `musicPlayback` | music `playback` | no implicit member |
| `costume` | actor `costume` | no implicit member |
| `sequence` | sequence `name` | no implicit member |
| `textStyle` | inline span modifier names | members are span names; no attrs |
The core manifest and its exact-domain assertion rename `musicAction` to
`musicPlayback`; every project, schema, and plugin declaration using that
domain MUST make the same rename. A stale domain name is `E-DOMAIN-UNKNOWN`,
not an alias.


A closed domain rejects a non-member with `E-BAD-ENUM`; an undeclared domain is
`E-DOMAIN-UNKNOWN`. Domain merging and plugin precedence remain unchanged. The
project does not gain a second directive-declaration mechanism: `::camera`,
`::actor`, `::cg`, and `::sequence` are core directives, while their members
come from merged domains.

`enums` long form continues to admit only `members`, `default`, `exits`, and
`labels`; unknown keys remain schema diagnostics. Domain metadata is emitted in
state entries only when a state slot uses that domain. Staging values are
emitted on their records and are not copied into a generic top-level `enums`
array.

### 3.3 Staging directives

All directives admit the universal `duration`, `delay`, and `wait` timing
attributes unless their existing core declaration excludes an attribute by
contract. Numeric timing values are seconds and may use the accepted time
literal syntax. `wait` is boolean.

* `::bg`: `location?`, `time?`, `assetId?`. It lowers to `kind: "bg"`.
* `::music`: `playback?` of domain `musicPlayback`, `mood?` of `mood`,
  `volume?` of `volume`, `assetId?`. `track` is removed.
* `::sfx`: `sound?`, `assetId?`. `name` is removed.
* `::vfx`: `type` of `vfxType`, `label?`, `transition?`.
* `::actor`: `character` (required string), `anchor?` of `anchor`, `action?`
  of `action`, `emotion?` of `emotion`, `costume?` of `costume`. An omitted
  anchor reads the domain default. An action in `action.exits` is an exit.
* `::camera`: at least one of `focus?` (cast reference string), `framing?` of
  `framing`, `move?` of `cameraMove`, or `transition?` of `transition` is
  required (`E-CAMERA-EMPTY`). The old numeric `zoom`, `moveX`, `moveY`,
  `shake`, boolean `reset`, and string `easing` are removed. Camera state is
  not persistent in 0.37 because no runtime consumer reads a saved camera.
* `::cg`: `assetId` is required; `display` is `show|hide` and defaults to
  `show`; `layout?` is a member of `cgLayout`. `full` and the old `action` key
  are removed.
* `::video`: `assetId` required, `display?` is `show|hide` and defaults to
  `show`; the resolved `display` is always emitted. The old `action` key is
  removed.
* `::sequence`: `name` is required and is a member of `sequence`; `wait`
  defaults to `true`. A sequence is a reference, not an inline cinematic. It
  has no bound-character declaration in 0.37.

A directive with a required attribute missing raises `E-MISSING-ATTR`. Domain
members are checked before lowering. `focus` retains the existing cast/subject
check. `action.exits` is the one source of actor-exit semantics; no prefix
heuristic is permitted.

### 3.4 Lines, roles, POV, and voice joins

A content line remains `@speaker{attrs}: text`. The default role is `dialogue`,
except the narrator speaker, which is `narration`; bare `mono`, `os`, and `vo`
select roles `mono`, `os`, and `vo`. The four delivery flags are mutually
exclusive; narrator may not carry one.

The effective POV is document frontmatter `pov`, falling back to the governing
project `defaults.pov`; an authored document value wins. `monoSpeakers` is a
new defaultable list of speaker ids in frontmatter/project defaults. A `mono`
line is valid only when its speaker is the effective POV or appears in the
effective `monoSpeakers` list. A line with neither is `E-MONO-POV`; when no POV
resolves at all it is `E-MONO-NO-POV`. A component line is checked at every
`::use` site using the caller's effective POV and allow-list. The corpus owner
must decide missing project POV values; `lute fix` MUST NOT guess them.
The checker MUST retain every `::use` site's caller context rather than a
component-name-to-first-span map. It validates the component body once per use
site, with that site's effective POV and `monoSpeakers`; a failing component
line is anchored at the `::use` site (a caller document's diagnostics cannot
point into another file), names the component file and line, and carries the
component line as a related location. This is required even when the same
component is used by multiple callers with different defaults. Speaker
parameters (`@@p`) are bound through every container a component body may
hold (branch, hub, `<on>`, objective, timeline, match) and through nested
`::use`.


Every line, including narration and mono, carries a `voiceKey` string. It is a
join key, not a claim that a recording asset exists. Recording consumers may
filter roles outside this compiler. The project-wide duplicate check examines
all lines and compares their plain, modifier-stripped source text; differing
text under one key is `E-DUP-VOICEKEY`.

### 3.5 Control and logic names

`::jump{to="label"}` replaces `::next`; it remains forward-only and uses the
one document-wide label namespace. `::label{name="label"}` replaces
`::mark{id="label"}` and emits no command. A line `id="label"` is removed and
`lute fix` inserts the equivalent label immediately before that line.

A branch or hub choice uses `text` for displayed text; `label` is removed.
`<match subject="…">` replaces `<match on="…">`; its subject semantics and
CEL rules are unchanged. Choice and hub selection records use `selectionKey`,
not `recordKey`.
`<reward>` may carry optional `id="token"`, using
`[A-Za-z][A-Za-z0-9_-]{0,63}`. It is unique among rewards in its owning quest;
duplicates are `E-REWARD-DUP`. The id is used by source maps, model keys, and
the IR `RewardEntry.id`; an untagged reward has the declaration-index fallback
specified in §3.7.


### 3.6 Inline text modifiers

Modifiers occur only in the text after the second colon of a content line. They
are not legal in headings, attrs, tag text, or choice attributes. The grammar is
as follows (horizontal whitespace is shown as `hws`):

```ebnf
text          ::= (escaped | interpolation | modifier | ordinary)*
escaped       ::= "\\:" | "\\[" | "\\]" | "\\{" | "\\}" | "\\\\"
interpolation ::= "{{" interpolation-body "}}"
modifier      ::= ":" name span? attrs?
span          ::= "[" text "]"
attrs         ::= "{" attr (hws attr)* "}"
attr          ::= name "=" value | name
value         ::= quoted | ref | number | bare
name          ::= lowerCamelName
quoted        ::= '"' (escaped | ordinary)* '"'
ref           ::= "@" identifier
number        ::= ["-"] digit+ ["." digit+]
bare          ::= identifier
ordinary      ::= any character other than the starts of the productions above
```

The parser recognizes a modifier only when `:` is followed by a valid `name` and
then `[` or `{`; otherwise it is ordinary text. `\:` is a literal colon and
never starts a modifier. Backslash escapes the next punctuation character in a
modifier body; an unknown escape is `E-TEXT-ESCAPE`. A missing closing bracket
or brace is `E-TEXT-MODIFIER`. Modifier spans nest. Interpolations are scanned
inside a span but their body is opaque to modifier parsing; the existing
`\{{` literal-interpolation escape remains effective. `{{…}}` therefore stays
in the derived plain text and in `placeholders`.

The core leaf modifier is `pause{s=seconds}`, where `s` is a required,
non-negative double. It has no span and no nested content. The core span
modifier is `speed[text]{rate=rate}`, where `rate` is a required positive
double. Attribute bodies use the normal key/value attribute grammar; positional
values such as `pause{0.5}` and `speed[text]{1.25}` are errors. Every other
modifier name must be a member of the project `textStyle` domain and has no
attrs; attrs on a text-style member are `E-TEXT-MODIFIER`.
A text-style modifier contributes its name to `styles`. A nested speed uses the
innermost rate; nested text styles are ordered outermost to innermost. This
single-rate rule is a spec decision: the wire shape has one `rate` field and an
innermost value is deterministic without inventing a multiplication unit.

`text` in the IR is the plain-text derivation: modifier delimiters and style
attributes are removed, escapes are decoded, and interpolation markers remain
verbatim. A line with no modifier has no `segments`. A line with a modifier has
coalesced text runs and pause leaves:
For example, an authored line may use `:emphasis[Hello]` when `emphasis` is a
declared `textStyle` member; the core forms are `:speed[Hello]{rate=1.25}` and
`:pause{s=0.5}`. Text-style members take no attrs.

```json
{
  "text": "Hello {{user.name}}!",
  "segments": [
    {"text": "Hello ", "styles": ["emphasis"]},
    {"pause": 0.5},
    {"text": "{{user.name}}!", "rate": 1.25}
  ]
}
```

Text segment `styles` and `rate` are omitted when absent. A pause object has
only `pause`. Empty text segments are omitted. The source modifier multiset is
retained internally for localization checking but is not a second public field.
`styles` and `rate` are derived from the active nesting stack, not from source
byte positions. The derived `text` is used for voice-key collision comparison.

### 3.7 Spec decisions for details left open by the decision log

* **Spec decision — section id token:** use the same bounded ASCII token as a
  component instance. It is portable across source maps and avoids whitespace
  and punctuation ambiguity.
* **Spec decision — actor character required:** an actor without a character
  cannot update stage state or be checked against the cast; rejecting it is
  safer than emitting the current empty-string fallback.
* **Spec decision — video display default:** resolve omitted `display` to
  `show`, like `cg`, so the two media controls have one deterministic
  normalized shape.
* **Spec decision — segment coalescing/order:** adjacent text runs with the
  same active style/rate stack are coalesced; styles serialize outermost first.
  This makes equivalent parses produce one deterministic segment shape.
* **Spec decision — timing numeric domain:** `duration`, `delay`, and `at` must
  be finite non-negative seconds. Rejecting NaN/infinity avoids non-portable
  JSON and runtime ordering.
* **Spec decision — timing ordinal:** `timing.timeline` remains an ordinal;
  only `duration`, `delay`, and `at` are seconds. This prevents the barrier's
  join ordinal from being mistaken for elapsed time.
* **Spec decision — nested speed:** the innermost rate wins because the IR has
  one `rate` and no approved multiplication unit.
* **Spec decision — locale wire:** every translated locale always has
  `texts[locale]` plain text; modified lines additionally have
  `localeSegments[locale]`. Backlog, TTS, and search need plain derivations.
* **Spec decision — sequence trace:** the reference runner records the
  reference and does not simulate an external cinematic, because no sequence
  player or bound-character contract exists in this release.
* **Spec decision — reward id:** the optional `<reward id>` uses the bounded
  ASCII token grammar and is unique within its quest; it replaces the
  owner-local declaration index as the stable model key when present.

and `name` state that hand migration is required where a domain value cannot be
proven.

## 5. Lowering and runtime consequences

### 5.1 Lowering

The compiler resolves merged domains before lowering. It emits authored and
injected actor records with `kind: "actor"`; injected anchor/preload/position
reset/hide records retain their existing ordering and provenance, but use actor
kind. Authored actor `emotion` updates stage emotion like a line emotion.
Authored `costume` is emitted when supplied; it is no longer documented as a
never-emitted field. `exit` is derived from `action.exits` and is omitted when
false/unknown.

`bg`, `music`, `sfx`, `vfx`, `camera`, `cg`, `video`, and `sequence` emit their
same logical staging operations under the new kinds/fields. Camera values are
opaque domain members; no numeric camera transform is synthesized. `sequence`
emits only its declared name and resolved timing. It does not carry bound
characters.

All command records receive `category`. The mapping is normative:

| Category | Kinds |
|---|---|
| `content` | `line` |
| `staging` | `bg`, `music`, `sfx`, `vfx`, `actor`, `camera`, `cg`, `video`, `sequence` |
| `state` | `set`, `assert`, `retract` |
| `control` | `choice`, `match`, `hub`, `jump`, `end`, `barrier` |
| `declaration` | `quest`, `on`, `entry`, `accept`, `beat` |
| `plugin` | `plugin` |

A plugin record is represented by Rust `Command::Plugin` and serialized as
`kind: "plugin"`. Its declared fields and effects remain opaque to core.

### 5.2 Timing and trace

The old flattened common stamp is replaced by this object:

```json
"timing": {
  "wait": true,
  "duration": 1.5,
  "delay": 0.25,
  "at": 2.0,
  "timeline": 0
}
```

`wait` is boolean. `duration`, `delay`, and `at` are seconds (finite, >= 0).
`timeline` is a zero-based scheduled-timeline ordinal; it is an ordinal, not a
second count, and is present only for records emitted from a timeline. The
ordinary record `timing.at` is scheduled placement in seconds. A barrier has no
`timing`; its own required `timeline` ordinal and `at` seconds remain direct
fields, so the barrier join fields cannot collide with a common stamp.

`timing` is omitted when all members are absent. `provenance` and `source`
remain optional sibling fields. Runtime dispatch reads `category` and `kind`,
then reads timing only from `timing`; it never reads legacy flattened fields.
The reference runner keeps its existing no-wall-clock behavior: it records a
barrier as a timeline join and does not simulate elapsed time. A sequence record
is recorded as staging data; `wait: true` is a blocking presentation contract
for an engine, while the reference runner records it without simulating the
external sequence.

Trace and `lute play --json` rename every emitted `addr` key to `position` and
emit the new kind/category names. `lute context --json`, the project index, and
all bridge snapshots emit `capabilitySnapshot`; no `capabilityVersion` alias is
included.

### 5.3 Exact IR records

The execution IR envelope retains its declaration arrays and command ordering,
with these required/renamed fields:

```json
{
  "lute": "0.37.0",
  "irVersion": "0.37.0",
  "capabilitySnapshot": "…",
  "requiredSemantics": [],
  "meta": {"id": "…"},
  "commands": []
}
```

Every command has required `kind`, `category`, and `position`. Optional siblings
are `timing`, `provenance`, and `source`; absent optionals are omitted. The
complete list of fields that carry a position string is:

| Record/field | Type and presence |
|---|---|
| every command `position` | required string |
| `choice.converge`, `choice.options[].target` | required string |
| `hub.converge`, `hub.return`, `hub.options[].target` | `converge` and option `target` required strings; `return` optional string |
| `match.converge`, `match.otherwise`, `match.arms[].target` | `converge` and arm `target` required strings; `otherwise` optional string |
| `jump.target` | required string |
| `objective.body` in `quest.objectives[]` | required nullable string; `null` means empty body |
| `on.body` | required string |
| `entry.body` | required string |
| `beat.body` | required string |

No other `crates/lute-compile/src/ir.rs` field is a position: ids, targets
that are entity/occasion/state identifiers, line ids, reward fields, `at`,
`timeline`, `source`, and `provenance` retain their own meanings. This list is
exhaustive; position-bearing fields keep their names but contain position
strings.

* `line`: `role`, `speaker`, `text`, `lineId`, required `voiceKey`; optional
  presentation attrs and `placeholders`. Every translated locale has a plain
  `texts[locale]`; a modified line additionally has `segments` and
  `localeSegments[locale]`.
* `bg`: optional `location`, `time`, `assetId`.
* `music`: optional `playback`, `mood`, `volume`, `assetId`.
* `sfx`: optional `sound`, `assetId`.
* `vfx`: required `type`, optional `label`, `transition`.
* `actor`: required `character`; optional `anchor`, `action`, `exit`, `emotion`,
  `costume`, and injected-only `posReset`/`preload`.
* `camera`: optional `focus`, `framing`, `move`, `transition`; at least one is
  present after checking.
* `cg`: required `assetId`, required resolved `display` (`show` by default),
  optional `layout`.
* `video`: required `assetId`, required resolved `display` (`show` by default).
* `sequence`: required `name`.
* `set`: `path`, `op`, `value`; `assert`/`retract`: `relation`, `args`.
* `choice`: `branchId`, `selectionKey`, `options`, `converge`, optional
  `prompt`, `timeout` (seconds), and `timing`.
* `match`: `subject`, `arms`, `converge`, optional `otherwise`.
* `hub`: `id`, `selectionKey`, `options`, `converge`, optional `prompt` and
  `return`.
* `jump`: `target`; `end`: optional `reason`; `barrier`: required direct
  `timeline` and `at`.
* `quest`, `on`, `entry`, `accept`, and `beat`: existing declaration fields
  with `category: "declaration"`, `position`, and the renamed common fields.
* `plugin`: `tag`, `fields`, optional `plugin`, `effects`, `asserts`, `retracts`.

The envelope's descriptive table is `sections`, each entry
`{"section": <one-based integer>, "heading": <string>, "id"?: <token>}`.
Empty optional arrays/objects follow the existing omission policy. The project
index has the same `capabilitySnapshot`, `sections` terminology where it
reports document sections, and `selectionKey` in selection records.

## 6. Localization contract

`lute loc export` preserves modifier source markup and `{{…}}` interpolation in
its exported `text`; it does not export the derived plain text. `loc import`
continues to join by `lineId`. During locale merge, the source and every
translation are parsed with the modifier grammar. The translation's ordered
modifier **multiset** (modifier name, leaf/span form, and normalized attrs) MUST
match the source's multiset. Position may differ, but a missing, extra, renamed,
or differently parameterized modifier is `E-L10N-MODIFIERS` and the translation
is not merged.

For a modified line, the source uses `segments`; every translated locale always
gets the plain derivation in `texts[locale]` and additionally gets
`localeSegments[locale]`:

```json
{
  "text": "Hello!",
  "segments": [{"text": "Hello", "styles": ["emphasis"]}],
  "texts": {"ja-JP": "こんにちは!"},
  "localeSegments": {
    "ja-JP": [{"text": "こんにちは", "styles": ["emphasis"]}]
  }
}
```

For an unmodified line, `segments` and `localeSegments` are absent, but every
translated locale still appears in the `texts` map. This is a spec decision:
backlog, TTS, and search always need the plain derivation even when a line has
inline presentation markup. Source `text` is always plain derived text; source
markup remains available only to source/locale tooling, not in the execution
field.

## 7. Migration and `lute fix`

`lute fix` is byte-exact, comment-preserving, descending-span, and idempotent.
It mechanically rewrites only these lossless forms:

1. `::auto` → `::actor`; `::cut` → `::cg`; `::next` → `::jump`; `::mark{id}`
   → `::label{name}`.
2. music `action` → `playback`; video/cg `action` → `display`.
3. `<match on>` → `<match subject>`; choice `label` → `text`.
4. A content-line `id="x"` → a preceding `::label{name="x"}` and removal of
   the line attr.
5. Inline modifier syntax is not invented by the codemod; an already valid
   modifier is preserved byte-for-byte.
6. LowerCamel mechanical key edits are applied only when the AST proves the
   target key is unique and unambiguous.

The following are diagnosed for hand migration and never guessed:

* camera `zoom`, `moveX`, `moveY`, `shake`, `reset`, `easing`;
* cg `full` (a project-specific `cgLayout` member is required);
* music `track` and sfx `name` (asset/semantic intent is ambiguous);
* missing POV/defaults and `monoSpeakers` decisions;
* project `sequence:` and reserved `<scene>`;
* body `# title` (use frontmatter `title:`).

Every old directive/attribute/tag spelling produces a diagnostic naming the new
spelling even if `lute fix` offers a fix-it. After the codemod, the corpus owner
runs manual judgments, `lute tag`, and checks every project; no compatibility
alias remains.

## 8. Conformance additions

The conformance corpus adds focused fixtures for:

* section ids, duplicate section diagnostics, and position fallback;
* every staging kind including actor injections, camera domains, cg display/
  layout, sequence wait, and nested timing/barrier fields;
* category values and the complete envelope/field rename set;
* every line role, all-line voice keys, collision comparison after modifier
  stripping, and both mono diagnostics (including component caller context);
* inline `pause`, `speed`, nested text styles, escaped punctuation,
  interpolation inside spans, plain-text derivation, and locale modifier
  mismatch;
* jump/label, choice text, match subject, reward id, and old-surface
  diagnostics;
* removed project `sequence`, `<scene>`, inert `# title`, and removed IR fields.

For each fixture, `source.lute`, schema/source dependencies, `artifact.json`,
`mock.yaml`, and `expected.json` are generated from the migrated source. A
single late release slice regenerates all artifacts and transcripts once using
the commands in `conformance/README.md`; JSON is never hand-edited.
