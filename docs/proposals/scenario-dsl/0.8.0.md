# Lute Scenario DSL — 0.8.0: Adoption Surface

- **Version:** 0.8.0
- **Status:** Draft
- **Date:** 2026-07-27
- **Scope:** one new core directive (`::end`), one new IR command kind (`end`),
  one new `after:` prerequisite primitive (`active`), one new reserved quest
  slot (`quest.<id>.activatedAt`), one narrowed author-`state:` rule
  (collections rejected), two new descriptive IR carriers (`shots`, per-record
  locale texts), and one plugin-owned cross-cutting attribute surface
  (`stampAttrs`, specified in
  [`plugin-system/0.0.2.md`](../plugin-system/0.0.2.md)).
- **Companion:** [`plugin-system/0.0.2.md`](../plugin-system/0.0.2.md) closes
  Appendix C1/C2/C4 and implements declarative `lower: { record }`.

## 1. Motivation

0.8.0 is the **adoption release**. Every change below is traceable to a
concrete gap found while assessing Lute against a real, large, non-toy game
catalog — 777 authored scenes / 73,847 command rows / 583 quests / 3,104
condition rows (`docs/adoption/oshiz-assessment.md`). Nothing here is
speculative generality: each item names the thing it could not express, or the
bug it could not avoid.

Three of the eleven items are **corrections**, not additions:

1. `addr` overflowed its own field width past 99 records in a shot, silently
   breaking lexicographic ordering (§2). A pilot hit this in production.
2. Shot headings were parsed and then discarded — the only authored structure
   with no IR carrier (§6).
3. Author `state:` accepted collection types the normative text forbade, the
   shape validator ignored, and the runtime docs described. Three sources, three
   answers (§4).

## 2. `addr` field width is uniform per artifact

**Was:** `addr = "{shot:03}-{(index+1)*100:04}"` — a fixed 4-digit index field.
A shot with 100+ records emits `001-11500` beside `001-1400`; string comparison
then reports `"001-11500" < "001-1400"`, and any engine that orders or
range-checks addresses lexicographically rewinds into already-played content.

**Is:** both segments are padded to a width computed from the document, and
that width is **uniform across the whole artifact**:

- `shotWidth = max(3, digits(maxShotNumber))`
- `indexWidth = max(4, digits(widestEmittedIndex))`

where `widestEmittedIndex` folds over every shot the **largest index value the
artifact actually emits**: `recordCount * 100` normally, or
`(recordCount + 1) * 100` when the shot carries a trailing label — the
end-of-shot converge address, legally "one past the last record", which is the
only way that value reaches the artifact.

**Normative consequence (new guarantee):** *within one artifact, every emitted
`addr` has the same length; therefore lexicographic order over `addr` equals
execution order.* An engine MAY rely on this. It remains free to compare
segment-wise numerically, and SHOULD if it loads artifacts from mixed toolchain
versions.

Both widths only ever grow past their current minimums, and the fold counts
only addresses that are actually emitted, so a document whose every shot emits
fewer than 100 addresses — with fewer than 1000 shots — is **byte-identical to
0.7.0**. A 99-record shot that *also* emits a converge address emits 100
addresses and does widen; that is correct, because `001-10000` is in the
artifact.

`addr` remains a position regenerated on every compile, never an identity
(§12 stands). The stable joins are still `lineId` / `voiceKey`.

## 3. `::end` — explicit termination

**New core directive**, the ninth in `lute.core`:

```
::end{reason?}
```

- `reason` is an optional free-form author string the host MAY surface
  (`"completed"`, `"error"`, an ending id). Lute assigns it no meaning.
- Lowers to a new IR command kind `end` (`EndCmd { addr, reason?, …stamp }`).
- Semantics: **the walk terminates at this record.** Identical to falling off
  the end of the command array, except the reason is carried.

### Why a core kind and not a plugin directive

A plugin directive lowers to `kind: "plugin"`, which is opaque to the checker —
reachability analysis cannot know it terminates, so content after it would not
be reported as dead. Termination is control flow, and control flow is core
(the data↔code boundary, plugin §12). Making it a new command `kind` is also
the honest version signal: an engine that does not implement 0.8 must refuse
the artifact rather than fall through an unknown record.

### `W-CODE-AFTER-END`

Any node following an `::end` **in the same straight-line body** — the same
shot body, `<choice>` body, `<when>` arm, objective body, or `<on>` body — is
unreachable. Reported once per body, at the first such node:

> unreachable content after `::end` (the walk terminates here)

Scope is the *immediately enclosing* sequence only: an `::end` in one
`<choice>` says nothing about its siblings, nor about content after the
enclosing `<branch>`. This is a **warning**, promotable with
`--deny W-CODE-AFTER-END`.

`::end` is not a staging leaf and MUST NOT appear inside a `<track>` clip
(same admission rule as `::assert`, 0.3.0 D9).

### Grounding

The assessed catalog carries 1,835 `end` rows across 777 scenes (≈2.4 per
scene) — per-branch endings are the norm, not the exception, in branching
dialogue. Expressing them as a jump to a shared terminal shot is possible but
loses both the reason and the dead-code check.

## 4. Author `state:` is scalar — enforced

`state:` declarations MUST be one of `bool | number | string | enum`. A
declaration whose `type` is `list`, `record`, or `map` is **`E-STATE-COLLECTION`**:

> state path `<path>` cannot declare a collection type (`list`/`record`/`map`);
> author state is scalar (number|bool|string|enum) — model collections as
> `relations:` (dsl 0.3.0 §3) or a plugin `state_shapes` slot

Like `E-TEMPORAL-ARG` (D11), the decl is **not installed**: a later read of the
path reports plain `E-UNDECLARED` rather than resolving to a phantom
collection-typed slot.

This *removes an ambiguity rather than adding a restriction*. Before 0.8.0 the
normative text said scalar-only, the shape validator accepted the full `Type`
union, and `docs/runtime/state-lifecycle.md` documented `list<…>`/`map<…>`/
`record` as valid `StateEntry.type` values. All three now agree: **author
declarations are scalar; collection-shaped `StateEntry` types reach the
artifact only through a plugin `state_shapes` expansion.** The runtime doc is
corrected accordingly.

Collections were always meant to be modelled relationally (0.3.0 §3) — an
inventory is `ownsItem(item)`, not a `list<string>`.

## 5. `quest.<id>.activatedAt` — a reserved narrative-time anchor

`validAt(rel(args), t)` has existed since 0.3.0 §8, but **no author-writable
`t` did**: `Type::NarrativeTime` is engine-surfaced only, and an author `state:`
declaration of it is `E-TEMPORAL-ARG` (D11). The query was unusable.

0.8.0 adds `quest.<id>.activatedAt` to the engine-reserved implicit quest
fields (beside `quest.<id>.state` and `quest.<id>.objectives.<oid>.done`,
0.2.0 §5.2), typed `narrativeTime`, tier `quest`:

- **readable** in CEL — specifically as `validAt`'s second argument and in the
  ordering-only comparisons `temporal.rs` admits (`<`, `<=`, `==`, `>`, `>=`;
  `!=` stays rejected per D8);
- **not author-declarable** — `E-QUEST-RESERVED-DECL`;
- **not author-writable** — `E-QUEST-RESERVED-WRITE`;
- engine-populated at the `unset → active` transition (quest-lifecycle §
  *Activation*).

**Definite assignment.** Unlike `quest.<id>.state`, `activatedAt` is exempt
from `E-MAYBE-UNSET`. This is deliberate and not a loosening: `narrativeTime`
is uninhabited by any manifest `Literal`, so the slot cannot carry a `default:`;
and the only two guard forms the reader accepts (`isSet(p)` / `has(p)`) are
themselves `E-TEMPORAL-ARG` on a narrative-time operand. `quest.<id>.state` has
an escape hatch — `<match>` exhaustiveness over its lifecycle enum — and
`activatedAt` has none, so a maybe-unset verdict here would be
**undischargeable**: every read would error with no remedy available to the
author. The engine guarantees the stamp exists for any activated instance, and
a read is only meaningful inside one.

`validAt(R, t)` is a point-in-time query — true iff `R` was valid *at* `t`
(0.3.0 §3.2: `established ≤ t < invalidated`), not "after". The `*_AFTER` gate
is therefore the conjunction "true now, and not yet true at activation":

```lute
<objective id="visitedSinceAccept" done="holds(arrivedSpace(station_front)) && !validAt(arrivedSpace(station_front), quest.q1.activatedAt)"/>
```

(A tag and its attributes must be on one physical line — dsl §2.3.)

### Grounding

"Did X happen *after this was assigned*?" is the single most common
non-expressible gate in the assessed catalog: 452 rows across seven
`*_AFTER` condition kinds, each carrying a `baselineAt` that is exactly the
quest-instance activation instant.

## 6. `shots` — authored headings survive compilation

0.6.0 §3.1 made shot headings free text and dropped `Shot.number` from the AST.
Lowering then discarded the heading entirely, so a compile → decompile round
trip lost every section title — the only authored structure with no other IR
carrier.

The artifact gains a descriptive `shots` table, appended after `prereqEdges`:

```json
"shots": [ { "shot": 1, "heading": "Station front, dusk" } ]
```

`shot` is the 1-based document position (0.6.0 §3.2), matching the `addr` shot
segment. Blank headings are skipped; a document that titles no shot emits no
table and stays byte-identical to 0.7.0. Purely descriptive — control flow
never references it.

## 7. Locale texts on the record

`lute loc export` extracted translatable content; nothing brought it back.
0.8.0 closes the round trip:

- `lute loc import <file>…` canonicalizes exports into a **locale bundle**
  keyed by `lineId` (the stable content join — never `addr`);
- `lute compile --locales <bundle.json>` merges it into the artifact:
  `LineCmd.texts` and the choice/hub option `labels`, both
  `locale → text` maps, both omitted when empty.

`text` / `label` themselves remain the **source-language** string
(`contentLang`) and are never overwritten, so a 0.7 consumer is unaffected.

A translatable record missing a locale the bundle declares is
**`W-L10N-MISSING`** (one per `(lineId, locale)` pair), promotable with
`--deny`. A bundle entry matching nothing in the document is ignored — a bundle
legitimately spans a whole project.

### Grounding

Target catalogs carry translations inline per row, not in a side file: the
assessed one has 52,796 / 44,074 / 40,059 rows for its three locales — 12,737
rows silently missing a translation, with nothing to detect it.

## 8. `after:` gains `active("questId")`

The prerequisite profile (connectivity §, `prereq.rs`) admitted exactly
`visited("sceneKey")` and `completed("questId")` under `&&` / `||`. But the
quest lifecycle is `unset → active → complete | failed`, so the profile could
express two of the three observable states. `active` closes the asymmetry:

```
PrereqFormula ::= Visited(String) | Completed(String) | Active(String)
                | And | Or
```

The profile stays deliberately closed otherwise — no negation, no arithmetic,
no state reads (`E-CONN-PROFILE` unchanged).

- **Graph semantics:** an `active` edge is identical to a `completed` edge for
  reachability and cycle detection — both assert "that node must be reachable
  before this one." `E-CONN-CYCLE` / `E-CONN-UNREACHABLE` / `E-CONN-UNKNOWN-NODE`
  behave unchanged, and `active` atoms count toward
  `E-CONN-FORMULA-TOO-COMPLEX`.
- **Envelope semantics:** strictly weaker. After `completed(q)` a consumer may
  assume `quest.q.state == complete`; after `active(q)`, only that it reached
  `active`.

`lute scenario` reports the edge kind in all three formats (`text`, `json`,
`dot` — `active` edges render dashed).

### Grounding

477 of 841 quest-referencing gate rows in the assessed catalog are
"quest is currently in progress." None were expressible.

## 9. `lineId` / `voiceKey` templates

Identity derivation was hardcoded as `{prefix}.{speaker}_{code}` and
`{speaker}-{code}`. An adopting project with an existing identity convention
had no way to match it, which blocks migrating a catalog that already carries
line ids under a different shape.

`lute.project.yaml` gains:

```yaml
identity:
  lineId: "{prefix}.{speaker}_{code}"    # default — today's exact behavior
  voiceKey: "{speaker}-{code}"           # default — today's exact behavior
```

Tokens are exactly `{prefix}`, `{speaker}`, `{code}`. An unknown token, or a
template that resolves empty, is `E-IDENTITY-TEMPLATE` at project load. Choice
and hub option ids (`{prefix}.{branchId}.{optionId}`) are **not** templated.

Defaults reproduce 0.7.0 byte-for-byte.

## 10. Non-goals — explicitly rejected

Recorded so they are not re-proposed:

- **Datalog aggregation (`sum`).** Stratified aggregation substantially
  complicates the safety/stratification analyses that make the engine's
  fixpoint provably well-defined. The motivating condition kind
  (`SHARD_SPEND_TOTAL_GTE`) has **zero rows** in the assessed catalog.
  Accumulated totals are engine-maintained `reserved` scalar state.
- **Any Datalog surface extension.** Measured: of 3,104 real condition rows,
  3,056 are unary and 48 nullary — **zero binary or n-ary**, so nothing to
  join; no condition set of 2+ predicates repeats even 5 times, so nothing to
  name with `derive:`; and the condition vocabulary contains no negation, so
  stratification has nothing to analyse. The n-ary tables that do exist carry
  payloads (weights, rates, sample strings) and are therefore lookup tables,
  not predicates — Lute relations carry no payload.
- **Author-declarable collection state.** See §4. The ambiguity is removed by
  rejecting, not by specifying.
- **A `label` field on every record.** Control-flow targets resolve to `addr`,
  but the authored names are already recoverable from `branchId` / option `id`
  / `questId` / `objectiveId`. Shot headings were the sole genuine loss, and
  §6 carries them.

## Appendix B — IR delta (0.7.0 → 0.8.0)

| change | shape |
| ------ | ----- |
| new command kind | `{"kind":"end","addr":…,"reason"?:…}` |
| `Artifact.shots` | `[{shot:int, heading:string}]`, appended last, omitted when empty |
| `LineCmd.texts` | `{locale: string}`, omitted when empty |
| `ChoiceOption.labels` / `HubOption.labels` | `{locale: string}`, omitted when empty |
| `Stamp.*` | plugin `stampAttrs` flatten alongside the reserved keys (plugin 0.0.2 §14.1) |
| `addr` | uniform width per artifact (§2) — a value change, not a shape change |

Every addition is optional and append-only. The **only** breaking element for a
0.7 consumer is the `end` command kind, which is intentional: per the
execution-model version policy an unknown `kind` is a hard error, and `end`
is real capability that cannot be faked.

## Appendix C — Version stamp

`LUTE_LANG_VERSION` and `LUTE_IR_VERSION` advance to `"0.8.0"`; the Cargo
workspace and the npm packages follow. The IR JSON schema becomes
`schemas/lute-ir-0.8.schema.json`. A document stamped `luteVersion: "0.7.0"`
fires the pre-existing `W-LUTE-VERSION-STALE`; the remedy is to restamp — no
0.7.0-clean document requires any other edit to check clean under 0.8.0
(with the single exception of a `state:` decl that used a collection type,
which was never valid per the normative text and is now diagnosed, §4).
