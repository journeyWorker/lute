# Lute Scenario DSL — 0.28.0: One rule per slot, one name per idea

- **Version:** 0.28.0
- **Status:** Draft
- **Date:** 2026-09-27
- **Scope:** closes every round-6 finding (`lute-dogfood/round6/TRIAGE.md`:
  T1-1…T1-25, T2-1…T2-13, T3-1…T3-68, D-1…D-15, and the renames decided in
  §6) found by a whole-language review of eleven existing games plus four
  new personas (novice, Ink/Yarn writer, live-ops designer, confusability
  audit). Nobody outside the dogfood games depends on Lute yet, so the
  renames land now as clean cutovers, each old spelling refused with an error
  that names the new one.
- **IR:** additive plus the renamed fields listed in §6.

## 1. Every accepting place checks the same way (T1-1…T1-5, T1-10…T1-12)

- Every YAML surface rejects unknown keys with a located did-you-mean:
  `lute.project.yaml`, `plugin.yaml` and its export files, schema state rows,
  enum long forms, relation rows, clock/season blocks (already strict).
  Engine-only keys written in the wrong layer name the layer that owns them
  (`terminal:` in the manifest → "`terminal:` belongs in a schema").
- Flag attributes (`optional`, `exit`, `once` on `<choice>`, `also`, …) are
  written bare; `="true"` and `="false"` are accepted, any other value is
  `E-FLAG-VALUE` naming the bare form. A `<choice>`'s
  `once` has one meaning (this hub visit); beat/entry `once` values on a
  choice are refused.
- Comparisons are typed: number vs string/bool, enum ordering, `is=` literals
  that are not values of the subject type are errors at check time, never a
  runtime halt or a silent false.
- Every condition slot (`when`, `after`, `rearm`, `spentBy`, season `live`,
  `raisedWhen`, `terminal`, rule `cel()`, def bodies) runs the same checks:
  declared paths, literal domains, member checks, types.
- Reserved words are refused where they are declared (state roots, `unset`,
  `true`/`false`/`null`/`none`, CEL function names, core directive names in
  plugins, template/`::use` param names that are beat header keys), with the
  list in one place (`lute --explain` and the reference page). Engine-owned
  namespaces (`scene.*`, `quest.*`, `entry.*`, `occasion.*`, undeclared
  `season.<n>`) cannot be declared or written.

## 2. One runtime, no silent gaps (T1-6, T1-13, T1-17…T1-25)

- Entry writes: an entry's writes apply on its first read per run, stated
  once in the docs; a `for=` entry is one read per member; a write that can
  never apply again (`once="day"` entry) is warned with a remedy that works.
- Hub scripts that run out in trace/test halt like play. Lore tests without
  an entry judge facts on the seeded world. Vacuous assertions are usage
  errors.
- `judge: before` evaluates the occasion's own beats before the terminal
  check that its judgement makes true.

## 3. Members and templates (T1-7…T1-9, T2-1, T2-2)

- `occasion.target`'s type is decided per beat, not per document.
- `occasion.target` can be written: `::set F[occasion.target] …`,
  `::assert r(occasion.target)`, directive and component args.
- Template headers accept `F[@param]` (the body's spelling); the dot form
  stays accepted in headers with a did-you-mean toward brackets.
- A use's `when=` still replaces the template's `when`, and says so:
  `W-TEMPLATE-OVERRIDE`, plus the documented `@only` composition.

## 4. Chapters (T1-14, T2-6, T3-13, T3-18, T3-28, T3-32, T3-47)

`sequence:` is renamed **`chapters:`**, a list of chains:

```yaml
chapters:
  - on: chapter
    scenes: [prologue, counter, kitchen]
```

`on:` matches the scene key. On a `select: sequence` occasion a chain
derives `on:` and descending priority (the order within one raise) and says
so (`W-CHAPTERS-NO-CHAIN` is not needed: the docs and `lute context` state
it). A targeted occasion requires every listed scene to declare `target:`.
`W-SEQUENCE-STALL` becomes `W-CHAPTER-STALL` and fires only on conditions
that can stay false forever; its advice changes only what matters.

## 5. Language gaps (T2-3…T2-13)

- **End vocabulary:** play and test `expect.end: complete | terminal |
  incomplete | error`; one table of the five "end" meanings.
- **Clock:** read-only `clock.day`, `clock.slot`, `clock.ended`.
- **Tiers:** relation `tier:` and `defaults.questTier` accept
  `season:<name>`; a relation without `tier:` warns
  (`W-RELATION-TIER-IMPLICIT`).
- **Payload** is readable in objectives and handlers of the raising occasion.
- **Outside the run:** an occasion may declare `outsideRun: true`; it is
  raised even after `terminal:` holds (title screens, galleries).
- `select: sequence` re-judges each beat just before it is presented.
- Label forms and number words; a hub `<return>` block that runs each time
  the hub re-presents after an option returns; `failedBy: subquest`.

## 6. Renames (clean cutover; old spelling is an error naming the new)

| Old | New |
| --- | --- |
| manifest `sequence: { occasion, scenes }` | `chapters: [{ on, scenes }]` |
| test `expect.offered` (menu options) | `expect.options` (same as play) |
| test top-level `accept:` alias | removed (`accepts:`) |
| `<quest after=>` | `<quest follows=>` (graph metadata; not a gate) |
| `<reward on=>` | `<reward outcome=>` |
| `<objective when=>` | `<objective visibleWhen=>` |
| plugin exports `rewardkinds` / `assetkinds` / `stampattrs` | `rewardKinds` / `assetKinds` / `stampAttrs` |
| `::camera{move-x move-y}` | `moveX` / `moveY` |
| `lute new --on` | `lute new --occasion` |
| "label" for a `::next` target in messages/docs | "mark" |
| docs example occasion `hubVisit` | `townVisit` |

**`spentBy` latches.** `spentBy: "<condition>"` means the beat is spent by
the condition instead of by being presented: once the condition has held
(at any judgement), the beat is spent and does not come back when the
condition turns false again. `once:` on the same beat now only sets how long
it stays spent (`run` by default; `user`, `day`, `week`, `season:<n>`), so
`once` + `spentBy` is legal. A `spentBy` that holds from the start is a
warning.

## 7. Diagnostics quality (T3-1…T3-68)

One pass over message hygiene: cause before consequence and one report per
mistake (a rejected declaration stops dependent judgements); character
columns in the CLI (UTF-16 in the LSP, unchanged); a shared did-you-mean
helper across keys, values, events, layers and ids; CEL-profile errors that
name the fix; no spec citations or ticket ids anywhere a user reads; the
remaining T3 tool items (`lute beats`/`calendar`/`lore`/`context`/coverage/
`reach --endings`/lint/`lute new`/doctor/LSP) as listed in the triage.

## 8. Docs (D-1…D-15)

Every D item, including a reserved-names reference, a "Coming from Ink /
Yarn" page, an "end" table, the clock-deadline recipe with `clock.ended`,
and the entry-write rule.
