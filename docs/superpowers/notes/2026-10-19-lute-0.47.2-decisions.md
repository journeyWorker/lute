# Lute 0.47.2 — decisions

Owner decision (2026-10-19): a patch release for two pre-existing player defects found while
implementing 0.47.1 and recorded in its decision note
([`2026-10-17-lute-0.47.1-decisions.md`](2026-10-17-lute-0.47.1-decisions.md), "Not fixed"),
filed as #137 and #138. Each issue body states the expected behaviour. The 0.47.0 **Testing
rule** applies: player / player-web behaviour is tested against real runtime output (a compiled
fixture through `@lute-lang/runtime`) or the player-web browser/e2e suite, never a hand-written
mock of a view or record.

| Issue | Decision |
|---|---|
| #137 (bug) | Every cue of a batch starts, whatever the autosave mode: the scheduler must not let the batch scope close before a forked non-waiting cue (camera, vfx, sfx) has started (`packages/player/src/scheduler/index.ts`). Regression test on a real compiled batch: a `::camera` and a `::sfx` as the last records before a `<choice>`, `autosave: false` and `"presentation"`, each effect observed. |
| #138 (bug) | A load completes while audio is still locked: restoring stage music never blocks the restore on playback start (`restartMusic`); music starts once audio unlocks. Browser test: load a save with stage music before any user gesture, reach the restored await, then a click starts the music. |

Out of scope: #139 (a literal `{` directly before a marker; contrived, low priority).

Version rule as 0.47.1: every visible axis aligns to `0.47.1` → `0.47.2`; schema file names stay
`-0.47`; `bindingsVersion` and the player save/profile format stay `"0.47"` unless a change
needs otherwise (record it here if so).
