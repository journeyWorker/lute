# Lute 0.49 / 0.50 — large-project port: triage

Inputs: issues #155–#188 (label `dogfood`) and the two follow-up comments on #169 and #173,
filed 2026-10-23 from a coverage evaluation: an existing large VN / live-game content set
(about 1.7k Lute documents after the port — scripts, quests, story steps, DMs, case sessions,
letters, schedules) moved onto `@lute-lang/lute@0.48.1` as an out-of-repo plugin + profile
extension, then round-tripped back to its source format and compared with the source's own
validator and replay planner. Every issue body carries a self-contained reproduction on
0.48.1 with neutral names; the source content is internal and is not referenced anywhere.

Triage by the orchestrator for the owner (2026-10-23). Same rules as 0.46–0.48: develop what a
real author or host hit and cannot reasonably work around; one spelling per concept; D13 (the
runtime owns no presentation); clean cutover (D6). Order of priority: **a value that
disappears or an answer that is wrong without a diagnostic** comes before any new feature.

The evaluation's headline facts that drive the split:

- Expressiveness is close: of 78 narrative-relevant rows, 57 are expressible (21 directly, 36
  through a workaround), 14 are Lute gaps, 3 need a server.
- Static answers are not yet trustworthy on this content: Lute reported **no** target
  unreachable where the source planner found 661 blocked; part of that is port modelling, but
  #181/#182 are cases where Lute drops an edge or a self-lock and still says `proven`.
- Cost: whole-project `check` ~110 s / 17 GB; one `scenario reach --node` costs a whole-project
  load (6–14 GB). The source validator checks the whole catalog in 34 s. (#173 + comment.)

## 0.49 — correctness, diagnostics, cost (develop now)

No new syntax. Every item is a bug fix, a diagnostic, or a cost fix; each lands with a
regression test that fails before the fix.

| Issue | Decision |
|---|---|
| #155, #156 | Stamp attribute names may not equal any key of the record they are stamped on (`tag`, `kind`, `family`, `speaker`, `text`, …, the full IR envelope + per-kind field set). Extend `E-PLUGIN-RESERVED-STAMP-ATTR` to that set, derived from the IR schema rather than hand-listed, so a new IR field is reserved automatically. |
| #157 | A stamp on a directive that emits no record (`::jump`, `::label`) is an error naming the directive, not a silent drop. |
| #158 | `<choice into= value=>` writes **before** the arm body. Conformance fixture for an arm ending in `::jump`. |
| #176 | `list` / `map` / `record` attribute types are refused at plugin load (`E-PLUGIN-INVALID-DIRECTIVE`, naming the attribute) until an authoring spelling exists; no type is accepted that no value can satisfy. Authoring them is a 0.50 design item. |
| #178 | Frontmatter keys typed `{ entity: K }` / `{ providerRef: P }` are checked exactly like directive attributes of the same type (one checker path). |
| #179 | A blocking bridge call's declared result writes are definite assignments on the continuation. |
| #180 | One presence guard spelling that works for every `per:` member, including ids that are not CEL identifiers (`has(path["member-id"])` or the spelling the CEL profile already admits for maps); every hint that today points at a rejected form is rewritten to it. |
| #181 | A cycle among quest `start` conditions is a diagnostic (same class as the existing `E-CONN-CYCLE` for scenes, with a quest-specific code), and `lute scenario` draws every edge of the cycle. |
| #182 | A `start` that reads its own quest's state is a diagnostic that names the self-lock and points at `accept="external"` (the spelling for "only the host grants this"); reachability never reports `proven` through a dropped edge. |
| #183 | `lute constraints` on an invalid manifest reports the manifest diagnostics and exits non-zero (same envelope as every other command). |
| #184 | An `unknown` verdict carries the reason (no play/test witness) and no self-counterexample; `reachable` agrees with `scenario reach` (a quest available from the start of play is `reachable [proven]`). |
| #185 | A holding constraint carries no `E-CONSTRAINT-VIOLATED` related diagnostic. |
| #175 | Single-file `check` that skips quest-reference checks says so (info diagnostic naming the skipped class and `--project`). |
| #167 | `W-BRANCH-ID-SHARED` fires only when a play or test names the shared id (the only place sharing is ambiguous). |
| #168 | Reward target contracts gain `target: forbidden`. |
| #174 | Content lines admit the core `wait` stamp (the same stamp every other staging record takes). |
| #187 | `asset-exists` reads every asset-typed attribute on content lines (sprite id, voice asset id), not only directives. |
| #188 | `lute lint <dir>` uses the project's `lute.lint.yaml`; `<dir>` + `--project` works. |
| #160 | Keep the rule (an entity reference must resolve to one kind). Document the shared-root pattern (`subsetOf`) in the `E-ENTITY-KIND-CLASH` hint and the entities page; it keeps ids exact and loosens no reference check (verified in the evaluation with seeded cases). |
| #161 | Keep member ids as names. The `E-PATH-IDENT` hint names the providers route for foreign id sets (`plugins/<id>/providers`, pinned snapshot). |
| #171 | Document the typed-bridge recipe for free-text input (language + runtime-contract pages, EN + KO). No new construct. |
| #173 | Build the project vocabulary (entities, relations, `per:` slots) once per project model and share it across documents; `scenario` / `constraints` / `impact` for one node reuse the same model instead of a whole-project rebuild. Acceptance: the issue's synthetic generator shows per-document cost flat in slot count, and peak RSS no longer scales with documents × slots. Bench gate covers the synthetic grid. |

## 0.50 — authoring extensibility (design first, owner review of the spec)

none ships in 0.49.

| Issue | Question for the spec |

## Out of scope (port-side, not Lute)

- The source's "granted only" quest lock should be ported as `accept="external"`, not as a
  self-reading `start` (#182 makes Lute say so).
- Level gates and space permissions were missing from the round-1 port; that is why the source
  planner's level blockers had no Lute counterpart.
