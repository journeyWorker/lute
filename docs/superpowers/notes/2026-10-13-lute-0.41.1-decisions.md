# Lute 0.41.1 — Rust-only patch decisions

Owner decision, 2026-10-13. Inputs are GitHub issues #67, #72–#76, and
#81–#84, with the released 0.41.0 tree at `39bcfa7a` as the evidence base.
The implementation plan is written for a cold Rust-server session and is
strictly sequential by Rust owner.

## Scope decision

0.41.1 is a **Rust-only patch release**. Rust checker, CLI, compiler, play
script parser, and human transcript code may change. Markdown documentation,
website English/Korean pages, package README files, release metadata, and
Rust regression/conformance fixtures may change. TypeScript source and test
logic in `packages/runtime`, `packages/player`, and `packages/player-web` are
untouched. No other repository is in scope.

The contract guard is hard: the bodies of
`schemas/lute-{ir,events,snapshot,player-bindings}-0.41.schema.json`,
`packages/runtime/src/generated/**`, and `packages/player/src/bindings/schema.ts`
remain byte-identical. Consequently, no issue is allowed to introduce a JSON
schema key, Event/IR/snapshot shape, bindings shape, or TypeScript migration.
The package version stamp pass may mechanically update the seven package
`package.json` versions and matching `bun.lock` workspace records; schema
filenames remain `-0.41`.

## In-scope decisions

| Issue | Decision | Why |
|---|---|---|
| #74 | Fix the UTF-8 byte-boundary panic in YAML domain rewriting; preserve source bytes, comments, and idempotence. | The documented migration command exits 101 on ordinary Korean/em-dash YAML. No contract change is needed. |
| #76 | `lute fix` updates existing stale `luteVersion` values in project defaults and document frontmatter to `0.41.1`; it does not add missing/future stamps. | A migration that leaves the exact stale warning behind is incomplete, and this is a byte-preserving CLI fix. |
| #75 | Keep `W-DEF-UNUSED` as a warning and append the exact `host: true`/`Program.def` escape only for schema/plugin defs. | `host: true` already exists in 0.41; the missing guidance causes destructive deletion. |
| #67 | Resolve profile option value, otherwise plugin manifest default, before `enumFromOption` membership checks; keep existing `E-BAD-ENUM`. | The checker currently skips a domain when the profile omits an option even though its declaration has a default. |
| #81 | Add error `E-BRIDGE-NO-RESULT-WRITE` for `layer: bridge` + `bridgeCall` without an `effects.writes` `fromBridgeResult`; refuse compilation. | A nominal bridge silently compiles as a non-blocking record, making 0.41 `bridgeResult.writes` unreachable. |
| #82 | Accept `{fields, writes}` answers at top-level and per-step `bridges:`; `writes` is the existing runtime `WritesInput` shape; retain flat legacy answers. | Authors need a play surface for bridge writes, but the Event/TS contract already defines the shape. |
| #83 | Add exact nested human transcript lines for beat `advances:` movement, raised occasions, and closed raises; leave JSON/events unchanged. | Reviewers cannot currently see a clock crossing or the closed gate in ordinary `lute play` output. |
| #84 | Add the public `castNames` → `cast` migration note, with the older `castNamesFrom` wording and `bundle.index.cast` destination. | The 0.41 runtime API already requires `cast`; only migration documentation is missing. |
| #73 | Add `packages/cli/README.md` with install/help/docs/migration links that work from npm. | The published launcher has no README. |
| #72 | Replace player README relative/root-relative links with absolute `v0.41.1` URLs. | npm renders the current links as dead paths; package docs must be usable in isolation. |

## Release-axis decision

Per `docs/versioning.md`, every visible axis aligns on every release, even a
patch. Toolchain, language, IR, Event/snapshot, and package versions therefore
read `0.41.1`. The runtime contract remains the 0.41 major/minor line: schema
filenames, schema bodies, generated TypeScript, and `bindingsVersion: "0.41"`
remain unchanged. The changelog MUST call IR/Event/snapshot/bindings moves
stamp-only/no-op for consumers.
