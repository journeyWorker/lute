# Lute 0.48.1 — decisions

Owner decision (2026-10-20): a patch release for the three open defects filed while
implementing 0.47.2 and 0.48, done locally. Each issue body carries the evidence. The 0.47.0
**Testing rule** applies: player / player-web behaviour is tested against real runtime output or
the player-web browser/e2e suite, never a hand-written mock of a view or record.

| Issue | Decision |
|---|---|
| #145 (bug) | `constraints --all-scripts` / `--script` and `context --script` record a witness from a play that completes a quest. The completed-quest set of a play run is built from the play transcript's settled quest transitions (`{"kind":"quest","quest":…,"state":"complete"}`), as it already is from a test trace's final `quests` map. Regression test: a quest-completing `*.play.yaml` under `plays/` makes a `completable` constraint `holds [witnessed]` (fails on 0.48.0 with `unknown`). |
| #142 (bug) | A host-driven batch never hangs on locked audio. Chosen option (the issue's first, the same rule 0.47.2 applied to restore): while audio is locked, a music cue's playback start does not hold the batch — the batch settles, and the music starts once audio unlocks. An sfx/voice cue with `wait` follows the same rule (it does not wait on a sound that cannot start). No new host API. Browser test: `mountPlayer(...).act({ type: "newGame" })` with no gesture reaches a stage-music save point and settles; a later gesture starts the music. |
| #143 (repo) | Run artifacts are not tracked: `packages/player-web/test-results/.last-run.json` and `title.png` are removed from the index (the directory is already ignored; nothing reads them). |

Out of scope: #139 (a literal `{` directly before a marker; contrived, low priority).

Version rule as 0.47.1/0.47.2: every visible axis aligns to `0.48.0` → `0.48.1`; schema file
names stay `-0.48`; `bindingsVersion` and the player save/profile format stay `"0.48"`.
