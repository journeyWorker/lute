# Lute 0.47.1 — fix patch decisions

Owner decision, 2026-10-17: a patch release for the three pre-existing defects found while
implementing 0.47.0 and recorded in its decision note
([`2026-10-17-lute-0.47-decisions.md`](2026-10-17-lute-0.47-decisions.md), "Not fixed"), filed as
#132, #133 and #134. Each issue body states the expected behaviour. The 0.47.0 **Testing rule**
applies unchanged: player / player-web behaviour is tested against real runtime output (compiled
fixtures through `@lute-lang/runtime`, or the player-web browser suite over compiled bundles), and
#132 is shown in the browser on the player-demo.

## Develop in 0.47.1

| Issue | Decision |
|---|---|
| #132 (bug) | A camera `transition` ends with the camera layer (the actors) visible: out → apply framing → in. Browser test on the compiled player-demo: actors are drawn after its opening `transition="fade"` camera cue. |
| #133 (bug) | Bindings `flow.*.target` has one spelling, the prefixed one the runtime and the occasion's `target` use (`place.square`, as the bindings docs show). `check-project` validates it with the same rule beats and plays use; a bare member is `E-BINDING-KEY` naming the prefixed form. One fixture checked by `check-project` and raised through the runtime. |
| #134 (bug) | `\{{x}}` in a source line is literal text and the unescaped marker is substituted (`Lit {{run.a}} and 3.`). Regression in the compiler, through the runtime's rendered line, and in the player. |

## Orchestrator choices (conservative, 2026-10-17)

| Topic | Choice | Why |
|---|---|---|
| Version contract | Patch on the 0.47 line, as 0.41.1 / 0.42.1: every visible axis stamps `0.47.1`; the schema files keep their `-0.47` names and **byte-identical bodies**; generated TypeScript unchanged; `bindingsVersion` stays `"0.47"` (the 0.47 rule compares it with the toolchain's `MAJOR.MINOR`, still `0.47`); the player save/profile format stays `"0.47"`. Unlike those patches the IR is **not** a no-op for consumers: no field changes, but #134 changes what a literal `{{` looks like in line `text` (an engine that substitutes placeholders itself must read the escape); `versioning.md` and the CHANGELOG say so. | `docs/versioning.md` patch precedent for names/bodies. None of the three fixes needs a schema field; the bug cannot be fixed without engines reading the escape (spec review). |
| #134 representation | One source escape rule for every scanner (the inline parser's odd-backslash counting). In the IR line `text` (and segment run `text`, merged `texts` / `localeSegments`) a literal `{{` is written `\{{` and each literal backslash directly before a `{{` is doubled; every other escape stays decoded. An engine reads n backslashes before `{{` as ⌊n/2⌋ backslashes plus a literal `{{` (n odd, consumed as a unit) or a marker (n even), substituted from `placeholders` in order (1:1). A plain "not preceded by `\`" rule would break a line whose literal backslash precedes a real marker (`:speed[x\\]{rate=2}{{run.a}}`, which renders correctly today) — spec review. The Lute runtime does both; its rendered records never contain `\{{`. Before 0.47.1 the decoded literal was indistinguishable from a marker, so the i-th-marker rule substituted the literal and left the real marker raw. | The only representation that fixes the defect without a schema field (patch rule) is one the engine can read from `text` itself. `\{{` is the author's own spelling (dsl 0.1.0 §7.6). Option labels and prompts are attribute strings, which reject `\{` (`E-STRING-ESCAPE`), so only line text is affected. No corpus document uses `\{{`, so no compiled corpus output changes. |
| #134 translations | A translation keeps `\{{` too; the runtime's by-marker rendering of `texts` / `localeSegments` (0.47 §2.2) skips escaped openers and decodes them. This lifts the 0.47 limitation "a translation cannot show a literal `{{…}}` equal to a source marker"; the runtime-contract note is replaced by the rule. | Same rule for source and translation. |
| #134 docs | The IR contract (execution-model, runtime-contract EN/KO, event-contract) states the rule; the schema `placeholder` description is not edited (body byte-identical; it already says the enclosing text keeps the verbatim marker). | Patch rule. |
| #133 rule | `flow_ref` calls `lute_check::…::occasion_target_ok`, the function `lute check` (beat targets) and `lute play` (step targets) already share, with the project's entity kinds; its message (prefixed `flow target`) is the `E-BINDING-KEY` message. As in plays, a target on an occasion without a target domain is refused, and an undeclared entity kind refuses its flow targets. The runtime side is shown by a player session over the compiled fixture raising `place.square` from the bindings and presenting the targeted beat (`lute play` would only re-run the same function; the runtime does not validate targets, a bare member just matches no beat). | One rule, one wording; no new code. |
| #132 rule | The camera layer rests at alpha 1, no mask. A camera cue with `transition` (and no `move`, which keeps precedence): hiding effects (`fade`, `dissolve`, `fadeOut`, `wipe*`, `slide*`, `slideOut`) hide the layer over the first half, the framing/focus is applied, and the layer is shown over the second half; other effects apply the framing then play as today. Every cue ends at alpha 1, no mask, new framing. `cut`/`none`, a zero duration or an instant cue apply at once. Restoring the stage (load, rollback) cancels running camera behaviours and resets alpha/mask before applying the framing. `cameraMove` effects unchanged. | "A camera transition is a transition" (issue); background transitions already end visible (crossfade). Resting alpha 1 rather than "pre-cue alpha" so a half-finished tween cannot compound; a load during the 0.3 s hidden half must not leave actors hidden (spec review). |
| `::use` string arguments (ReviewR1) | The escape is judged on the decoded attribute value spliced into the line, so `p="lit \\{{run.a}}"` passes a literal `{{run.a}}`. | Judging the raw attribute text would have removed the only way to pass a literal `{{` through a param (`\{` is `E-STRING-ESCAPE` in attributes). |
| Not fixed (pre-existing, contrived) | A literal `{` directly before a `{{` marker cannot be encoded (`S }}{\{{{{run.a}}} E` renders `S }}{{3} E`); found by fuzzing in ReviewR1, same in 0.47.0. | Outside #134's case; a follow-up could refuse it with a diagnostic or extend the encoding. |
| Not fixed (pre-existing, outside the three issues) | With `autosave: false` (or `"presentation"`), a non-waiting cue (camera, vfx, sfx) that is the last cue of a batch before a choice is never started: the scheduler forks it with `Effect.forkScoped` and the batch scope closes before the fiber runs (`packages/player/src/scheduler/index.ts`), so its effect — even a camera framing — is dropped silently. Same on v0.47.0. Fix candidate: fork with `startImmediately` or yield before `scheduler.play` returns. | Found by W1 and confirmed by ReviewW1b; player-core scheduler, not #132's camera transition (which plays to its end once its cue has started). The owner scoped 0.47.1 to #132–#134; the docs qualify the claim instead. |
| Not fixed (pre-existing) | A load hangs in `restartMusic` while audio has never been unlocked. | Noted by W1; outside the three issues. |
| W1 slice choices | The camera transition runs on a `Camera`-owned fiber in the player scope (a cue's batch ending does not cut it short); a `move` supersedes a running transition, a transition arriving during a move does not cancel the move; wipes on the camera layer use a stage-sized mask in the parent's space; `slide*` means `slideLeft`/`slideRight` (`slideIn` is an entrance and plays as before). | ReviewW1 / ReviewW1b. |
