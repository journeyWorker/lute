# Lute 0.41 — dogfood fixes: decisions

Inputs: GitHub issues #43–#66 (label `dogfood`), filed while moving lute-town (a Phaser
game) onto `@lute-lang/runtime` + `@lute-lang/player`, and the unreleased 0.40.1 work
(`Program.evaluate` / `Program.def`, index `defs`, strict exprNode input) which ships in
0.41 instead of a separate patch. Clean cutover (ADR D6): breaking contract changes are fine,
every consumer and the corpus migrate in the release. ADR D13 holds: the runtime stays
parser-free and returns effects as data.

## Compiler, CLI, language

| # | Decision |
|---|---|
| #43 | `lute fix` also rewrites renamed domain keys in project/schema YAML (`musicAction:` → `musicPlayback:`), comment-preserving, idempotent. A general "renamed domain" table feeds both the fix and the diagnostic. |
| #44 | `type: number` gets a diagnostic that names the choice (`int` or `double`) and, when every literal default/write the checker can see is integral, suggests `int`. No automatic fix (the choice is semantic). A declaration that fails to parse no longer cascades: dependants (clock, plugin load, directives) report one "depends on an invalid declaration" note at most. |
| #45 | Index `bridgeResults` fields use the same typed field shape as occasion payloads (`int`/`double`/`bool`/`string`/enum members). |
| #46 | Index `enums` carry `labels` when declared. |
| #47 | `check-project` / `check` summaries count by severity (`N error(s), N warning(s), N info`). |
| #48 | `W-OBJECTIVE-STRANDED` does not fire when the objective's quest re-arms across runs/seasons (`repeat`/run-tier lifecycle) or when a beat outside the objective's document can complete it; the message states its evidence level (D9). |
| #49 | Defs may declare `host: true`: exempt from `W-DEF-UNUSED`, carried as `host: true` in index `defs`. |
| #56 | Host conditions: new CLI `lute expr <cel> [--project <dir>] [--json]` lowers a CEL condition against the project (state paths, relations, defs) to an IR exprNode, with checker diagnostics. Runtime stays parser-free (D13): hosts lower at build time. `Program.def(state, name, args?)` evaluates parameterised defs; index `defs` export parameter lists. |

## Runtime and event contract

| # | Decision |
|---|---|
| #51 | A `raiseOccasion` whose `raisedWhen` is false is **rejected** (`RuntimeRejection` `E-OCCASION-GATE`, state unchanged), never halts. New query `Program.gate(state, occasion, target?) -> {open: bool, unresolved?}`; `candidates` gains no gate field (the gate is per occasion, not per beat). |
| #52 | `bridgeResult` accepts optional `writes` (same `WritesInput` as `hostWrite`), applied with the answer before the walk resumes. A plugin whose host action must be visible to later lines of the same presentation declares itself blocking (a bridge). Non-blocking plugin records stay write-free; the event contract says so. |
| #53 | `advanceClock { writes }` applies its writes **before** the clock moves, so beats raised by the move read them. The event contract specifies the order for `advanceClock`, beat `advances:`, and `raiseAtStart` raises. No new await type; the docs recommend expressing clock-boundary rules in the story (derived rules / `dayStart` beats). |
| #54 | `awaitBridge` carries `attrs` (the directive's resolved attributes) and renames the result schema to `results`. |
| #55 | `Session` exposes `program`; the docs state that a `RuntimeState` is valid for every `Program` of the same bundle fingerprint. |
| #57 | The generated `Ir` TypeScript index schemas (`projectIndex`, `indexBeat` incl. `advances`, `indexOccasion`, `indexStateDomain`, `defs`, `cast`, …) are generated from the Rust index types like commands are. |

## Player

| # | Decision |
|---|---|
| #55 | `LutePlayer.make` accepts either `seed`/`snapshot` (as today) or an existing runtime `session`, and the returned handle exposes `session` and `program`. |
| #58 | `DirectorHandle.send(input)` (and a `{type: "send", input}` action) is accepted at `idle` and at `ended` for inputs the runtime accepts there; `PlayerHost.idle` stays as the automatic path. |
| #59 | At `ended` the director accepts `newRun` and outside-run raises through `send`; `PlayerSession.begin` replays `started` only for the first begin. |
| #60 | `DirectorHandle.restore(save: SaveRuntime)` restores runtime session + backlog + stores and re-presents the restored await/stage (`presenter.restore`). |
| #61 | Presenter-paced lines: `Presenter.showLine` may resolve only when the reader released the line (option `linePacing: "presenter"` on `LutePlayer.make`/director); in the default mode an `advance` that arrives while typing is buffered for the coming `shown` instead of being consumed as `reveal` when the presenter declares it confirms itself. |
| #62 | `PlayerHost.plugin?: Record<tag, (record) => Effect<void>>` runs non-blocking plugin records as waiting cues in presentation order; the one-cue-per-event contract of `CueFactory.fromOutput` is documented. |
| #63 | Music cues honour `playback` (`start`/`change`/`stop`/`fadeOut`) and `volume`; `bindings.vfx` accepts a custom effect name, passed through as `StageCue.Vfx { effect: "custom", name }`. |
| #64 | `LineView.speakerName` comes from index `cast`; `LineView` gains `emotion` and `variant`. |
| #65 | Director option `autosave: false \| "presentation" \| "choice"` (default unchanged). |
