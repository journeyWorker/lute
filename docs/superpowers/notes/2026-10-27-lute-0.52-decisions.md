# Lute 0.52 — clean slate: decisions

Decided by the orchestrator under the owner's delegation (the owner delegated
every 0.52 choice to the orchestrator). The rule the orchestrator applied:
**conservative** — the smallest surface, one spelling per concept, static
analysis kept sound, refuse rather than guess, and the runtime and the checker
agree. The release resolves every issue open in `journeyWorker/lute` on
2026-10-27 (#139 #198 #201 #208 #209 #210 #211 #212 #213 #214 #216 #217 #218),
so that the owner can run a fresh dogfood on 0.52.0.

The normative contract is
[`docs/proposals/scenario-dsl/0.52.0.md`](../../proposals/scenario-dsl/0.52.0.md);
the implementation plan is
[`docs/superpowers/plans/2026-10-27-lute-0.52.0-clean-slate.md`](../plans/2026-10-27-lute-0.52.0-clean-slate.md).
Code facts below are cited at `52d5420a` (v0.51.0, `main`). Every reproduction
was run on a debug build of `52d5420a` (`lute toolchain 0.51.0`).

## Where the spec departs from or extends the orchestrator's instruction

Each item was found while specifying; each takes the conservative option.

1. **#216: the IR cannot express "leave the hub" by position.** The runtime runs
   a hub option body as `[start, stop)` (`machine/menu.rs:717`) and ends the
   option on any transfer out of it (`machine/mod.rs:967-969`). A rule "a jump
   out of the range leaves the hub" cannot be read off positions: a compiled
   `<branch>`'s converge jump at the end of an option body targets `stop`
   (it is laid out inline), and a label right after `</hub>` binds to the
   hub's converge, which equals `stop` for the last laid-out non-exit option
   of a hub without `<return>` (probed: `h2.lute`, option bodies are laid out
   consecutively and only an exit option ends in a jump). **Instead:** the
   compiler, which knows the structure, writes `jump.leaves = n` (the number
   of enclosing hub option/`<return>` bodies the jump leaves; omitted when 0),
   and the runtime leaves exactly that many hubs. An engine without the new
   behaviour would re-present the hub, so the artifact requires
   `lute.core.hubLeave/1` (D5), collected only when a `jump` carries `leaves`.
2. **#216: jumps into a separately run body.** The checker accepts a jump from
   one hub option into a sibling option's body, from before a hub into an
   option body, and from one `<objective>` body into another (all probed:
   `h3.lute`, `h4.lute`, `q2.lute` check clean). The runtime ends the range,
   or runs the sibling body inline and falls into the next one. **Instead:** a
   jump's label must lie in the jump's own range body or in a body that
   encloses it through hub bodies only: **`E-JUMP-INTO-BODY`** (new, error).
   A scene's sections are one range (the runtime runs a scene as `0..len`),
   so forward jumps between sections stay legal (the corpus has them,
   `helix-tower.lute`). No corpus document is affected.
3. **#208: `E-JUMP-LOOP-SCOPE`'s 0.51 R4 cause becomes unreachable.** A loop
   region could span an `<on>`/`<objective>` only through a top-level
   `::label`, which #208 refuses. **Instead:** that cause and its message are
   removed (clean cutover); its tests now expect `E-GRAMMAR-NOT-ADMITTED`.
4. **#208: the refusal reuses `E-GRAMMAR-NOT-ADMITTED`.** Admission already
   names its refusals with that code (`admission.rs:652`); a second code for one
   admission rule would be a second spelling. The message is new and points at
   `<on>`/`<objective>`. Top-level `<hub>`/`<timeline>` keep their message.
   Content after the last `<on>`/`<objective>` did run on v0.51.0, by
   fallthrough as part of that body (its segment ran to the end of the quest's
   commands, `machine/quest.rs:130-168, 1162-1170`); it is refused like the
   rest (orchestrator, intentional), migrating into the body it ran with.
5. **#218: prompts were never checked.** `check_prompt_attr`
   (`logic_attrs.rs:459-467`) checks only that a prompt is non-empty; no pass
   scans its `{{…}}` (`prompt="You have {{run.gould}} gold."` with `run.gould`
   undeclared checks clean), and the IR carries no prompt placeholders, so the
   runtime could not render one. **Instead:** `prompt` joins the label grammar:
   every pass that scans a choice label scans it, and `choice`/`hub` records
   gain `promptPlaceholders`. A prompt read that was silently accepted becomes
   an error (corpus: no prompt has a marker).
6. **#218: menu text never halts the walk.** A line's unset payload marker can
   halt (`text_halts`, `format.rs:99-120`). A label or prompt renders with
   `render_markers` alone: an unresolved marker keeps its verbatim text, as
   `render_markers` already does, and the menu is still presented. A menu is
   where the player decides; halting there would be a new stop point.
7. **#218: the menu carries the text, the records do not change shape.**
   `MenuAwait.prompt` exists but is never set (`runtime.rs:1618`). **Instead:**
   it is set to the rendered prompt, `promptTexts` is added, and each
   `MenuOptionAwait` gains `text` (always) and `texts` (rendered translations,
   omitted when empty). This is an event and snapshot shape change (the
   `Snapshot` holds the pending `Await`), so the schemas regenerate at `-0.52`.
   The hub presentation record's `prompt` is rendered too (an untyped payload).
8. **#201: accepts keep `@target` or a quest id.** Directives have no
   `accepts`, so there is no attribute-typing precedent for a quest id, and no
   attribute type names a quest. **Instead:** reward `effects` read `@<attr>`
   where directive effects do — facts and raise targets — and accepts are
   unchanged.
9. **#201: a reward attribute value is a quoted literal.** An `@ref` value is
   `E-REWARD-ATTR`, as an `@ref` `target=` already is (0.49 #192,
   `rewards.rs:459-476`): a reward is static data the engine grants against.
   This avoids a def-folding path for rewards.
10. **#201: declaration faults move to load.** Today a reward kind's `attrs:`
    load unchecked (probed: `{ list: string }`, a name `amount`, a duplicate,
    `default: 3` on a `string`). Once the attrs mean something, each of those is
    a fault: `E-PLUGIN-PARSE` at the entry, reported where 0.50 reports the
    reward-effect faults (`loader.rs:757-780`). `type: text` is already refused
    at parse and stays so.
11. **#211: `\{{` is the label grammar's, not every string's.** The lexer cannot
    tell a label from any other quoted value (a plugin `text` attribute is known
    only with the snapshot). **Instead:** the lexer accepts `\{{` and keeps it
    verbatim (as `decode_value` keeps `\\`, `\n`, `\t`, `attrs.rs:514-551`); the
    checker reports `E-STRING-ESCAPE` for it in any value outside the label
    grammar. A `::use` argument keeps the 0.47.1 spelling `\\{{` (the message
    says so).
12. **#139: labels are not affected.** A label's IR text is its source text
    (no re-encoding), read by the same `{{` rule in the checker and the
    runtime, so the ambiguity exists only where `IrText` re-encodes: line text
    and line translations. The check runs where the inline parser builds plain
    text, so a translation with the sequence is `E-L10N-MODIFIERS` ("does not
    parse (E-INTERP-BRACE: …)") and is not merged.
13. **#217: the other flow walks.** Definite assignment forks every option from
    the entry (`defassign.rs:988-1029`), which is sound because a write never
    un-assigns (the head ⊇ entry); `fact_must` already has a hub fixed point
    (`fact_must.rs:1454`). Only the stage walks (checker fold and compiler
    `walk_hub`) change. The presence walk was inventoried in S4: it forks
    options from the entry, but first kills every path and fact any hub body
    writes (`kill_writes`), so its guard claims hold in every round; unchanged.
14. **#209: one predicate for "alternative" edges.** `EdgeKind` gains
    `is_alternative()` (`Accept | Raises`), used by `ancestors_of`; nothing else
    changes meaning.
15. **#210: evidence.** An `[accept]` edge and a raise with a static target are
    `Proven` dependencies in `impact`; a raise whose target is dynamic
    (`occasion.target`, standing for every answerer) is `Heuristic`.
16. **#213: no behaviour claim.** The fix is the one-line prefix pass plus an
    export/compile agreement test over the corpus (every exported `lineId`
    exists in the compiled artifacts; 4207 units, 0 missing on v0.51.0).
17. **#198: only target-dependent casts.** The `as` casts that saturate
    (`f64` → integer) or wrap a `u32` metric give the same result on every
    target and stay. The trace keeps the record's index as `u64` (no cast; the
    serialized number is unchanged).

## Found while specifying, resolved in 0.52

- **Objective `title` markers are never rendered.** The checker admits
  `{{…}}` in an `<objective title>` (dsl §7.6, `walker.rs:600-604`), but the IR
  has no title placeholders (`stage.rs:1041-1042`) and the runtime emits no
  titles; a host shows the raw marker. No corpus or docs content uses it.
  Rendering it would need a record that carries quest text. **Decision
  (orchestrator, 2026-10-27; the owner wants an empty tracker after 0.52):**
  refuse rather than render. The title becomes plain text and any `{{` in it
  is `E-OBJECTIVE-TITLE-INTERP` (spec §6.7). A new code, because no existing
  one says "this position takes no interpolation" (`E-CEL-PROFILE` judges a
  referent, `E-INTERP-DEF` a def body). The objective title also leaves the
  label-grammar list of #211 (spec §3.2). The plan's bootstrap files the
  issue with this evidence so the CHANGELOG can cite it, and the release
  closes it.
- **A plain `{{` spliced before a marker (#221).** Filed while implementing
  S1: a `::use` argument ending in a plain `{{` is spliced as `\{\{`, whose
  last `\{` fuses with the `{{` of a marker right after it, so the marker is
  lost from the text while its placeholder stays (v0.51.0 renders
  `S {{{{run.a}} E`). **Decision (orchestrator, 2026-10-27; the owner wants an
  empty tracker):** fixed in 0.52 (S1) by refusing, not rendering: the
  spliced-text check judges the text the expansion means, and a marker the
  spliced text loses is `E-INTERP-BRACE` at the outermost `::use`, whose
  message names `\\{{`. A plain `{{` in an argument is an opener without its
  `}}` (dsl 0.26.0 §3.1), not a literal; rendering it as one would add a
  second spelling beside `\\{{` (spec §3.1).
- **`::end` in a hub body (S4).** Neither 0.51 stage walk ends a route at
  `::end`, but spec §5.4 says a non-exit option ending in `::end` does not
  complete. **Decision (orchestrator, 2026-10-27):** one `StageFlow`
  predicate, used by both walks, ends the stage route at `::end` inside a
  hub option or `<return>` body only, so it affects the hub's completion and
  the converge's exit-option states and nothing else. Ending stage routes at
  every `::end` would change branch and match joins outside hubs
  (`conformance/end-reason` among them); not in 0.52's scope.
- **The stage join drops a character whose sprite differs (#222).** Filed
  while implementing S4: `StageState::join` carried a character as on stage
  only with an identical sprite in every side, so a character on stage on
  every route with a differing emotion lost the `auto-pose-reset` before a
  later plain line (v0.51.0, after a branch). The hub head (#217) joins the
  entry with the options' completions, so it lost the reset in
  `summer-station` `radioHub`, a player-visible regression. **Decision
  (orchestrator, 2026-10-27):** fixed in 0.52 (S4). The join keeps a
  character on stage when every side has them; differing attributes merge
  to an unknown sprite. Presence-driven injections follow presence;
  attribute-driven ones stay conservative (an `::actor` of an unknown sprite
  injects the fresh-show anchor and preload, as 0.51 did). One join for
  branches, matches, labels, loop and hub heads. Corpus effect: only gained
  `auto-pose-reset`s and one more precise auto-hide explanation (spec §15
  class 6); no injection lost.

## Review amendments (Review052)

Review052 ("ready after fixes", eight findings) was applied to the spec and
the plan. Decisions by the orchestrator where the review offered a choice:

1. **F1** — the runtime loader requires that removing exactly `leaves` hub
   option/`<return>` ranges from the jump's range ancestry yields the
   target's range body; undercount (it would recreate #216 in the outer hub),
   overcount and sibling targets are refused, and so is `max` with `leaves`
   (spec §5.3). One load-refusal test each.
2. **F2** — the non-exit completion of the hub head is an
   `Option<StageState>`; with no reachable completion `<return>` is not
   applied and there is no back edge (`StageState::join(entry, [])` is
   `entry`, so a join cannot say "unreachable"). All-exit and
   all-routes-leave/end regressions (spec §5.4).
3. **F3** — `promptPlaceholders` add no **new** semantic id but keep the
   existing expression-derived requirements: both choice and hub collectors in
   `semantics.rs` scan them; a prompt-only temporal test (spec §6.2).
4. **F4** — impact evidence comes from the resolved raise sites (with
   static/dynamic provenance) passed alongside the scenario graph; the graph
   is not widened. A `[raises]` edge is `Proven` if any static site backs it,
   else `Heuristic`; static-only, dynamic-only and mixed tests (spec §8.2;
   supersedes item 15's data path).
5. **F5** — `cli-snapshot.py --accept <file>` (S1): exit 0 only when every
   difference is listed in the classified delta file, 1 on an unlisted one, 2
   on a comparator error; self-test covers all three; RG and final gate use it.
6. **F6** — `packages/runtime` `bun run build` after `wasm:build` and before
   any player build (St, final gate).
7. **F7** — bootstrap checks Node 24 and `jq` and runs `npm ci` in
   `conformance/harness/js`.
8. **F8** — RG and final gate add CI's
   `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`
   and `vocab-grid.py gate --runs 5`.
9. **F9** — an accepted-delta entry pins the reviewed bytes:
   `<class> <changed|added|removed> <command label> <stream/file> <sha256 of the normalized head output>`;
   any byte change after approval exits 1 until the entry is re-approved.
   The S1 self-test approves a delta, changes another byte under the same
   label, and expects exit 1.
