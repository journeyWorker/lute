# Lute 0.47 — Brinewake round 2: decisions

Inputs: issues #118–#129 (label `dogfood`), filed in **Brinewake dogfood round 2**
(2026-10-17): the round-1 game (`The Last Bell at Brinewake`, a PixiJS town + player-web VN
life sim) moved to Lute 0.46.0 and grown with the features round 1 skipped — a festival hub
with `<return>`, a bridge minigame whose answer carries writes, rewards, timeline/CG bell
cinematics, a second play-through (`user.*`, `prev.run`), a Korean slice, and the AI edit loop
(`lute context` → `lute patch` → `lute diff`). Evidence (browser transcripts, screenshots,
patch files, friction logs) is on the owner's external SSD,
`/Volumes/External/work/brinewake-dogfood-2026-10-17/`; each issue body quotes what the release
needs. Round 2 also verified 0.46 in practice: #103–#107 and #111 hold; **#112 did not**
(→ #118).

Triage by the orchestrator for the owner (2026-10-17). Same rule as 0.46: develop what a real
host or author hit and cannot reasonably work around; one spelling per concept; D13 (the
runtime owns no presentation). Clean cutover (D6).

**Testing rule added by this release** (from #118, where a unit test mocked a plain string and
the feature never worked): every player / player-web behaviour this release touches is
tested against a **real runtime output** (a compiled fixture project through
`@lute-lang/runtime`, or the player-web browser/e2e suite), not a hand-written mock of a view
or record. Where an existing test of a touched feature mocks runtime data, replace it.

## Develop in 0.47

| Issue | Decision |

| #118 (bug, major) | `ui.ended` selects its screen from the real `view().state` entry (compare the entry's value, typed as the declared domain), with an e2e/browser test per screen in the player-web suite (the demo gets a multi-ending case) — the mocked-string test is replaced. |
| #122 (bug, major) | player-web shows translated dialogue: the line cue, backlog and every text surface read the line's `texts[locale]` (falling back to source) for the current `settings.locale`; choice labels and prompts likewise. Settings offers every locale the loaded bundle carries (source locale + compiled locales), not only the current one. Browser test: switch to `ko` mid-run and on a new game, named line + choice + prompt in Korean. |
| #121 (major) | A second play-through survives a page reload. The player persists the **lineage** (the runtime snapshot at the last `ended`, which holds `user.*`, user-tier facts and `prev.run`) in its profile store; New game after a reload restores that lineage and sends `newRun`. Rule clarified: `begin` on a session restored at `ended` sends `newRun` (it never re-presents `started`). `profileVersion` follows the release; older profiles keep read marks/settings and start with no lineage. Browser test: finish run 1, reload, New game → a `prev.run`-gated line and a `user.*` value from run 1. Documented in the player docs as the cross-run model. |
| #128 | Stale translations are diagnosed: `loc import` stores the source text hash per entry in the locale bundle, and `compile --locales` reports `W-L10N-STALE` (deniable) for an entry whose current source differs; the message names the lineId and says to re-export. `lute loc` docs EN/KO. |
| #125 (part) | Branch and hub `prompt=` text is localizable like choice labels: a stable lineId, exported by `lute loc export`, merged by `loc import` / `compile --locales`, read by the player (#122). **Not developed:** per-document locale scoping for partial slices — a shipping game translates fully; `W-L10N-MISSING` stays project-wide. |
| #127 | player-web draws `::cg` above the stage actors and below the dialogue/UI layers (an event illustration covers the stage). Document the layer order on the player-web page. Browser screenshot test. |
| #129 (bug) | No discard-progress confirm for `toTitle` when the flow is `ended`; the in-game menu keeps it. Browser test on the ended screen's button. |
| #120 | Bindings `ui.title.text` names the game on the title screen; when absent, the title shows the project's display name if the project declares one, else no heading (never the literal "Lute"). Bindings schema + checker + generated TS + player-web. |
| #119 | `bindingsVersion` follows the same rule as `luteVersion` (0.41.1 #76): `lute fix` raises a stale `bindingsVersion` to the toolchain line, and `check-project` warns (`W-BINDINGS-VERSION-STALE`) when it is older; a bindings file using a section newer than its declared line is an error naming the line it needs. |
| #123 (bug) | `lute patch` applies several edits in one file correctly (edits resolved against the original tree and applied in descending offset order, or re-resolved after each) and the written file passes `lute fmt --check` before `accepted` is reported. ## Orchestrator choices (conservative, 2026-10-17)

Judgement calls made while writing the 0.47.0 spec
([`docs/proposals/scenario-dsl/0.47.0.md`](../../proposals/scenario-dsl/0.47.0.md)); each picks the
narrower or the already-established option.

| Topic | Choice | Why |
|---|---|---|
| #118 entry read | Select a screen only for a `{ kind: "str", value }` entry whose value `screens` maps; `EndedProgramView` is replaced by the runtime's `Contract.WorldView`. | Closed-domain members (enum, entity kind) arrive as `str` values; typing from the runtime is what would have caught the bug. |
| #122 source locale | The project index gains optional `contentLang` (from `defaults.contentLang`); the source locale is `index.contentLang`, else the first artifact `meta.contentLang` (index document order), else `"en"`; compiled locales are the keys of the artifacts' `texts`/`promptTexts`. A new profile starts at the source locale; a saved locale the bundle does not carry reads source and Settings selects the source locale. No `MountOptions.locale`. | Scene metas carry no `contentLang` and project defaults never reach artifact metas, so the bundle alone cannot name the source of a scene-only project (spec review); the corpus sets `contentLang` as a project default. Additive index field. The locale is a setting (one spelling). |
| #122 mechanism | `fromOutput(output, readLines, locale)` / `choiceView(await, locale)`; backlog entries keep `texts`/`localeSegments` and resolve when shown. | The factory and session fixed the locale at construction; a per-call locale is the smallest change that reaches custom factories too. |
| #122 backlog | The backlog renders in the locale current when it is shown (entries keep the record's translations). | "every text surface reads `texts[locale]` for the current locale". |
| #121 lineage use | The lineage is written (immediately, not debounced) at every `ended` presentation. In a player started without `snapshot`/`session`, New game that cannot send `newRun` where the session waits (untouched session, or a run abandoned through the menu) restores the lineage instead of the start point, then sends `newRun`; a host `seed` is not used while a lineage exists. A lineage the runtime refuses is dropped and New game starts from the start point. Older profiles decode with their read marks and settings. | A host that passes `snapshot`/`session` chose its state; abandoning run 2 must not lose run 1's user tier (spec review); a refused snapshot must never block the title. |
| #125 prompt id | `{prefix}.{branchOrHubId}.prompt`; `<choice id="prompt">` in a branch/hub with `prompt=` is `E-CHOICE-DUP` (registry summary widened). | The issue's id form; choice ids have no charset that would make another suffix collision-free, and `E-CHOICE-DUP` already owns id collisions in a branch. `E-RESERVED-NAME` is unconditional, while this collision exists only when `prompt=` is set, so only the prompted case is refused. |
| #125 IR | Siblings `promptLineId` (always with a prompt) and `promptTexts` (skip-if-empty) on the `choice`/`hub` command; `prompt` stays a string. | The Rust runtime reads `prompt` as a string (`MenuAwait.prompt`); siblings keep prompt-less records byte-identical. |
| #128 hashes | Export rows carry `sourceHash` (`sha256:` of the record's plain source text — the compiled `LineCmd.text`, option `text`, `prompt` — not the raw authored text, which keeps inline markup and escapes; CSV: last column); the bundle stores it per lineId **and locale** under `sourceHashes`, `schemaVersion: 2` (v1 still read, no stale check). Stale translations still merge. | The export `text` is overwritten by translators, so the source must travel in its own column; two locales can be translated from different exports. |
| #119 rule | `W-BINDINGS-VERSION-STALE` for a value ≠ toolchain line (older / newer / malformed wordings as `W-LUTE-VERSION-STALE`); `E-BINDINGS-VERSION` for a section newer than the declared line, with the table `vfx effect: custom` 0.41, `volumes` 0.42, `ui.ended` 0.46, `ui.title.text` 0.47, everything else 0.40; `lute fix` raises older numeric values only. | Mirrors the luteVersion rule; the table is the git history of each section. |
| #120 fallback | No project display name exists (no manifest or index field), so an unbound `ui.title.text` draws no heading. `background`/`music` become optional (at least one of the three keys when `ui.title` is written), so a title can name the game without assets. | Adding a manifest key for a display name is beyond the decision; "else no heading" is its own fallback. With both assets required, `ui.title: { text }` alone would be refused (spec review). |
| Pre-Z bindings line | Until Z the toolchain line is 0.46, so fixtures/demo using `ui.title.text` declare `"0.47"` and carry only the "newer" `W-BINDINGS-VERSION-STALE`; quayside gains `ui.title.text` only in Z. | Z stamps the line; no early bump. |
| #123 guarantee | Both root causes are fixed (offset mapping, per-region splice). "Passes `fmt --check`" means: clean after if the original bytes were clean; otherwise the touched regions are canonical. A violation is `E-PATCH-FORMAT` (nothing written). | An existing test pins that far non-canonical bytes stay untouched (patch formats touched regions only); refusing is safer than reporting `accepted` for a damaged file. |
| #126 scope | Subtree archive when the other side is a directory inside the cwd's work tree; otherwise the 0.46 behaviour. | The existing test diffs `git:HEAD` against a directory outside the repo. |
| #124 inputs | `inputs` on every `lute schema <command>` description (empty unless the command reads a structured request), schema report `0.47.0.schema`; drift guarded by a round-trip test. | Same shape rule as `outputs` (0.43 §3.4); a payload change moves the report version (0.43 §3.3). |
| #127 order | `background, camera, cg, video, dialogue, choice, overlay, transition`; no per-layout `layer` option. | Decision wording; one order. |
| #129 scope | Only the `ended` flow skips the confirm; `error` keeps it. | Decision wording. |
| docs | The tutorial's localization and second-play-through steps are written over `docs/examples/quayside` in the last docs slice, which also updates the llms mirror once. | Same pattern as 0.46 K. |
