### 1. `::set` writes any expression into any declared path, and the runtime evaluates it to nothing

`TOOL` · `TOOL-DEFECT` · **Blocker: L C B — and the case the verdict passes**

**Entries** — T3.2.

**Wrong.** `run.shedPressure` is declared `{ type: number, default: 0 }`. All three of
`::set{run.shedPressure += "two"}`, `= true`, and `+= (run.shedPressure > 0) * 3` are
`ok: … (0 warning(s))` at exit 0 under `--deny-warnings`, compile, and are carried
through by `lute run` as `final run.shedPressure = 0`, `= true`, `= 0`.
Reproduced at HEAD on 2026-08-04 against a fresh `lute init` tree carrying Anseo's
schemas: `lute check /tmp/triage/p/scenes/probe.lute --project /tmp/triage/p
--deny-warnings` → exit 0. The declared `type:` binds `into=`/`value=` and binds nothing
about `::set`.

**Costs.** Your counter silently stops counting. Every gate downstream of it —
`when="run.shedPressure >= 2"`, `<match on="run.shedPressure">`, an objective's `done=` —
reads a number that never moved, so the branch the player earned never fires and the one
they did not earn does. Nothing anywhere says so: the checker is green, the compile is
green, the reference runtime is green, and a `lute test` suite asserting the transcript
of the arm that *did* play is green too. This is the bug you ship, on the most common
write in the language, on a mechanic every work has.

**Fix.** T3.2's, and it is one construct away from existing. Type the `::set`
right-hand side against the target path's declared type, reusing the path-type lookup
that already produces `E-INTO-VALUE` — *"`value` is required for `run.shedPressure`
(only a `bool` path defaults to `true`)"* — in the same compiler run, on the same path.
New code `E-SET-TYPE`, naming the path, its declared type, and the type of the
expression.

**Shape.** A type lookup and a comparison at a check site that already resolves the path.
Not a new analysis: T3.2's whole argument is that the checker demonstrably holds the
answer at that moment.

**Verify.** T3.2's three probes invert directly into acceptance checks. `+= "two"`,
`= true` and `+= (run.shedPressure > 0) * 3` must each exit 1 naming `run.shedPressure`
and `number`; `+= 2`, `-= 1` and `= 3` must stay exit 0; and the enum case T5.4 re-verified
(`::set{run.ending = "shed-with-modle"}` against `{ enum: [bridge-reached,
shed-with-module] }`) must exit 1 with a did-you-mean, which the path table already
computes for `E-UNDECLARED`.

### 2. The suite cannot see a gate that opens too wide, and one wrong letter turns a false test green

`TOOL` · `TOOL-DEFECT` ×5 · **Blocker: B**

**Entries** — T9.18, T9.8, T9.10, T9.9, T3.10. (T7.11 is a logged recurrence of T3.10.)

**Wrong.** Two independent silences that compound.
*Under-restriction is invisible.* T9.18 mutation-tested the committed tree: delete
`when=` from `haltTheSequence` — one of the two levers that decide which ending the
prologue reaches — and `check-project` is byte-identical, all 31 tests pass, and the
`--coverage` block does not move. Same for weakening `invalidateTheVoyage`. `lute test`
enforces `chosen ⊆ eligible`; nothing anywhere checks `eligible ⊆ intended`.
*Unknown keys are dropped everywhere.* `expect:` knows three keys (`exit`,
`transcriptContains`, `state`) and silently discards every other; the verdict is
`all()` over an empty vector, so a test with no recognised expectations is green. A
**top-level** typo is dropped the same way, and for `choose:` the result is worse than
useless: reproduced at HEAD, a file spelling `chooses:` and asserting a bogus
`transcriptContain:` returns `1 passed, 0 failed`, because the selection is dropped,
`trace` auto-picks the first eligible arm, and the assertions written for the arm the
file names are checked against the arm it excluded. `lute test --help` advertises
"quest status" (confirmed verbatim at HEAD) and there is no `expect:` key for it.

**Costs.** The suite you built to protect the work protects the wrong half. It is a good
regression net for authored text and state deltas — change a line, a `::set`, a choice id
and it goes red at once — and a poor specification of logic: the guards that decide which
ending a run reaches can be deleted outright and it stays green. Anyone reading
`31 passed` as *the branching is correct* is misled, and the direction it cannot see —
a lever that opens for a crew that has not earned it — is the direction that reaches
players. On top of that, the harness will green a test that asserts nothing, or asserts
something false, because of a typo it declines to mention.

**Fix.** Four patches, all against data already in the report. (a) — T9.8/T3.10's —
reject unknown keys at **both** levels of a `*.test.yaml` and in `--mock` files, with a
did-you-mean; the surfaces are closed sets and the codebase already writes such
diagnostics (`E-TRACE-MOCK-UNDECLARED` and friends). (b) — T9.18's, and the one that
closes the mutation — an `expect: eligible: { theCorrection: [haltTheSequence,
sayNothing] }` key asserting the exact eligible set every `<branch>` `Decision` already
carries and `lute trace` already prints. (c) — T9.10's — the remaining slots for
information the same run renders and cannot assert: `transcriptOmits:`, `state: { p:
unset }` (which also retires T9.9's sentinel), the ending reached, quest lifecycle, and
`facts:` as an output. (d) refuse to green a test with zero recognised expectations, and
either report an auto-picked branch or require the test to opt into one.

**Shape.** (a) is a closed-key validator plus suggestions. (b)–(c) are new expectation
kinds over vectors already in `TraceReport`. (d) is a predicate. No new analysis
anywhere; T9.18: *"Nothing new is computed; a vector already in the report gets an
assertion slot."*

**Blocker.** **B** — a branching work's correctness story rests entirely on this. In
effect it binds everything else: a defect your tests cannot catch has unbounded blast
radius.

**Verify.** Re-run T9.18's six-row mutation table against the committed tree. With
`expect: eligible:` added to the four `purser-*.test.yaml` files, **M1** and **M2** must
go red and controls **C1/C2/C3** must stay red. Separately, T9.8's `z-typo-choose.test.yaml`
must exit 1 naming `chooses:` and suggesting `choose:`, and its one-letter-corrected twin
must still fail on the assertion — the log's own control, which is what proves the typo
was the only reason it was green. And T9.9's `state: run.shedPressure: "<never written>"`
must stop reporting `expected "<never written>", got "<never written>"`.

### 3. Every component line is dropped from the localization bundle, and the remedy the tool names is a no-op

`TOOL` · `TOOL-DEFECT` · **Blocker: L C — hard**

**Entries** — T6.10.

**Wrong.** `loc export` correctly emits a component's lines once, keyed to the component
file — and with `"lineId": null`, because `{prefix}` derives from the *importing*
document's `{character}.s{season}ep{episode}`, which a component has no frontmatter to
supply. Everything downstream is keyed on `lineId`. `loc import` skips the row and exits
**0** with *"rows skipped (no lineId) — run lute tag"*; `lute tag
docs/examples/anseo/components/purser-interject.component.lute` answers
**`lute: already tagged`** and changes nothing, because the lines *are* tagged — they
carry `code="0010"`/`code="0020"`; `compile --locales` then emits
`W-L10N-MISSING` for `anseo.s01ep02.purser_0020`, a caller-derived id that appears in no
export the translator ever saw, and ships English at exit 0. All of it reproduced at HEAD.

**Recount.** T6.10 measured "1 → 3 null `lineId`s" at T6's six-document corpus. On the
finished 18-document corpus `loc export` emits **10** null-`lineId` rows: **2** from the
component, carrying a `code`, which `lute tag` can never fix; and **8** quest `<on>`
narration lines carrying no `code`, which it can — the export's own header counts exactly
those eight (`8 lines untagged — run lute tag`). The distinction T6.10 drew is intact and
sharper: the tool's message is correct for 8 rows and structurally impossible for 2.

**Costs.** Adopting the language's only reuse mechanism *removes a line from the
localization pipeline*. Verified with a one-commit before/after: inline, the Purser's
line was localizable; through `::use`, it is not. A translated production must therefore
choose between components and translation, and no diagnostic in the toolchain says so —
`check-project` is `ok` at 18 files.

**Fix.** T6.10's (i), which the entry argues is the right one rather than the cheapest:
`loc export` emits one row **per expansion**, carrying the caller-derived `lineId`, with
the component file and line retained as a `source` field so a TMS dedupes on identical
source text and the translator still sees the string once. This also makes
`W-L10N-MISSING` unreachable for the case. Failing that, (ii) the bundle accepts a
component-scoped key (`purserInterject#0020`) that `compile --locales` resolves before
falling back to `lineId`; (iii) at minimum, `loc import` must not name `lute tag` for a
row whose file declares `component:`, and skipping a translated row must not be exit 0.

**Shape.** A join in an existing project-wide walk. `loc export` already knows the
callers (it walks the project), `compile` already knows all eleven `lineId`s, and
`loc import` already knows the row's file.

**Verify.** The before/after in T6.10 inverts exactly: `lute loc export docs/examples/anseo`
must emit zero rows with `lineId: null` whose file declares `component:`; round-trip a
`ja-JP` bundle through `loc import` and `compile --locales docs/examples/anseo/scenes/cryobank.lute`
must emit no `W-L10N-MISSING` and must render `anseo.s01ep02.purser_0020` in Japanese.
The eight code-less quest rows must still be reported as untagged.

### 4. `{{@param}}` cannot render a `string`, the only param type that carries text

`SPEC` · `SPEC-WRONG` · **Blocker: C**

**Entries** — T6.11. (T6.8 is the page being wrong about this and is in **#10**.)

**Wrong.** `params: who: string`, body `{{@who}}, the schedule advances.` →
`E-REF-TYPE: '@who' produces a non-renderable type; a '{{…}}' interpolation renders only
number/bool/enum (dsl §7.6)`. `number`, `bool` and `{ enum: […] }` all pass. And the
same binary renders strings through the other two interpolation forms in the same run:
`{{userName}}` compiles to `placeholders: [{"kind":"reserved","token":"userName"}]`, and a
`string`-typed declared state path `{{run.label}}` compiles to
`placeholders: [{"kind":"path","path":"run.label"}]`. Nothing is interpolated at compile
time at all; the engine substitutes at present time.

**Costs.** Varying a component's *words* by an argument is unreachable — which is the main
reason to write a component with a param. The Purser naming the module it is billing
("Draw exceeds projection in {{@module}}") has to become a `<match>` writing each variant
out in full: fine for two, impossible for eleven, at which point the words go back to
being authored per scene and reuse is abandoned for exactly the beat that wanted it. Both
shipped component examples declare `string` params, so the spec forbids the shape its own
documentation models.

**Fix.** T6.11's, in its own preference order. (1) Admit `string` as a renderable type and
extend §7.6's normative Rendering paragraph to cover it (*"a **string** → its text
verbatim"*), making the sentence true of all three grammar alternatives instead of one;
`E-REF-TYPE` keeps its real job of refusing structural types. (2) If the motive is
localization safety, scope it where it belongs — a lint over *all* placeholder kinds
(`W-INTERP-FREE-TEXT`), which would also fire on `{{run.label}}`, rather than a type ban
one alternative escapes. (3) Failing both, state the ban as a rule about component params
and fix `E-REF-TYPE`'s wording, which today makes a claim about interpolation that the
same binary falsifies twice.

**Shape.** A design decision on §7.6 first; then a whitelist entry and a rendering clause.
Nothing about the substitution mechanism changes — it already does this.

**Verify.** T6.11's three-probe matrix: one component per param type, each body
`{{@who}}, the schedule advances.` All four must check clean and compile to a
`placeholders: [{"kind":"ref", …}]` entry, and the `{{userName}}` and `{{run.label}}`
controls must be unchanged. A component with a `@ref` producing a map or list must still
be `E-REF-TYPE`.

### 5. A component has no meaning of its own: one body, two callers, two different command streams

`SPEC` · `SPEC-WRONG` · **Blocker: — (C, on trust rather than function)**

**Entries** — T6.2.

**Wrong.** A component's own `uses:` and inline `enums:` are discarded at parse, so the
body resolves against the *importing* document. T6.2's control differs in exactly one
line — `action.exits` — and produces two artifacts from one body: caller A gets **two**
commands, the Purser leaving the stage on `exit: true` and then speaking after having
left; caller B gets **three**, because the same sprite is an entrance so
`entry-emotion-lookahead` injects a preload that exists in neither the component nor the
scene. `ok: . (3 file(s), 0 project-wide warning(s))`, exit 0, no diagnostic on any file.

**Costs.** The language's only reuse construct is the one construct whose behaviour
nothing in the project can pin down. You write a block of words once; what you get is a
block of words *per caller*, and the callers can disagree about whether it removes a
character from the stage. Anseo avoids it by discipline — one project-root schema, every
caller reaching the same one — and discipline is not a guarantee: the next author who
gives one scene its own `action` domain gets T6.2's transcript at exit 0.

**Fix.** T6.2's two alternatives, either sufficient. (i) The named future direction:
`::use` carries the component's declared domains into the expansion, so a component means
what its author wrote. (ii) If that is too large for a point release, the *detection* is
nearly free — `check-project` already resolves every component and every caller in one
run, so for each slot a component body touches, compare the component's declared domain
against each caller's and emit `W-COMPONENT-VOCAB-DIVERGENT` when they differ.
Separately: `vocabulary.md`'s framing sentence, *"This is a scoping limit, not a checking
divergence"*, is true about checking and false about meaning, and should go with the fix.

**Shape.** (i) is a resolution-model change. (ii) is a set comparison inside a walk that
already has both sides in hand.

**Verify.** T6.2's two-vocabulary probe is the acceptance test: two schemas differing in
exactly the `exits:` line, one component, two callers. Under (ii),
`W-COMPONENT-VOCAB-DIVERGENT` must fire twice. Under (i), the two artifacts must become
identical modulo `lineId`. Anseo, where every caller reaches one schema, must stay silent.

### 6. `<choice>` accepts, discards and never mentions any attribute you invent — including one the spec removed

`TOOL` · `TOOL-DEFECT` (silence) · **Blocker: B**

**Entries** — T8.2.

**Wrong.** `<choice id="…" label="…" goto="anseo.s01ep08">` is `ok: … (0 warning(s))`,
exit 0, and `grep -c goto` on the artifact is `0`. Reproduced at HEAD with `goto=` and a
second invented attribute on one choice: exit 0, no diagnostic. It is the whole logic-tag
family — `<branch>`, `<choice>` (under both `<branch>` and `<hub>`), `<match>`, `<when>`,
`<hub>` are all open; `<otherwise>`, the one tag whose permitted set is *empty*, is the
one that enforces (`E-LOGIC-CONTENT`). Directives and content lines are closed and
enforced with per-construct messages. Three attribute surfaces in one language, two
enforced. And one of the attributes silently eaten is `as=`, removed from `<choice>` in
0.1.0, whose sibling `persist` — removed in 0.6.0 — gets a bespoke `E-PERSIST-REMOVED`
with a column-exact span and a migration instruction, three lines away.

**Costs.** You reach for the single most obvious thing at a routing branch and are told
nothing — not that it is unsupported, not that it was discarded. Worse, on a file nobody
thought to run `lute fix` over, `as=` in place of `into=` compiles to **no `set` record at
all**: every choice-driven state write in the document is gone, at exit 0, on a file
`lute check` calls `ok`. `as` is not gibberish — it is a live content-line attribute one
construct to the left.

**Fix.** T8.2's, and the entry calls it the cheapest fix in the task: raise
`E-UNKNOWN-ATTR` — the code the directive and content-line paths already raise — on logic
tags, against the `dsl 0.1.0 §7.3` per-tag permitted table that already exists and from
which `<otherwise>`'s empty set is already enforced. Keep `E-PERSIST-REMOVED`'s shape for
`as=` on a `<choice>`, since the rename has a migration and `lute fix` performs it.

**Shape.** A closed-set check against an existing table, on five constructs.

**Blocker.** **B** — but the `as=` half costs any project, branching or not.

**Verify.** T8.2's seven-row probe table inverts: five of the six constructs must move
from `ok` to `E-UNKNOWN-ATTR` with a column-exact span, `<otherwise>` must keep its
existing message, and every legal attribute in §7.3's table must stay silent. Then the
migration file: `<choice … as="run.vesnaTrust" value="1">` must exit 1 pointing at `as`,
and after `lute fix` the artifact must carry the `set` record.

### 7. No player choice can decide what comes next, and two scenes written as alternatives both unlock forever

`LANG` · `LANGUAGE-GAP` (both shapes) · **Blocker: B**

**Entries** — T8.3.

**Wrong.** There is no `goto`/`next`/`route`/`then` on `<choice>` (§7.3's permitted set is
`id`, `label`, `when`, `into`, `value`). The inversion is closed too: the `after:` grammar
admits no state reads at all, and exclusion is refused by name —
`machine-deck.lute:7:1: error [E-CONN-PROFILE] '!_(…)' is outside the 'after' prerequisite
profile — only visited("id"), completed("id"), active("id"), &&, and || are permitted (no
negation …)`. The grammar is monotone: once a scene is available it is available forever.

**Costs.** The corpus's central structural claim — that ep04 and ep05 are two ways through
the same act — is a comment in a brief. Both declare `after: 'visited("anseo.s01ep03")'`,
both become available at the same instant, and a conformant engine may play both; every
convergence guard downstream is then wrong, and there is no guard that survives it,
because the exclusion the story depends on cannot be stated. `lute scenario`'s graph is
the *availability lattice*, not the story's graph, and nothing tells an author that. The
story's actual shape — alternatives, consequences, roads not taken — lives in an engine
Lute does not ship and cannot check.

**Fix.** T8.3's, and it deliberately keeps the monotone core: a project-level
`exclusive:` group naming node sets of which at most one may be visited —
`exclusive: [[anseo.s01ep04, anseo.s01ep05]]`. It adds no negation to the formula grammar,
it is checkable by exactly the key-set machinery `check-project` already runs, and it lets
`scenario` report the two things an eleven-scene work most wants: which nodes are genuine
alternatives, and how many distinct routes the graph has. The documented-behaviour half
costs one paragraph on `scene-graph.md` (see **#11**).

**Shape.** A manifest schema field, a check over an existing key set, and two new
`scenario` outputs. A design decision first — the exclusivity semantics under revisits
have to be settled (see **#15**, which hits the same undeclared revisit policy).

### 26. `E-CLIP-OVERLAP` rejects the boundary hand-off its own spec makes legal

`TOOL` · `TOOL-DEFECT` · **Blocker: —**

**Entries** — T7.2.

**Wrong.** `::vfx{… at="0.8" duration="0.4"}` followed by `::vfx{… at="1.2"}` →
`E-CLIP-OVERLAP: clip at 1.2 overlaps another clip in track '#vfx'`. Both normative sources
make the hand-off legal and agree: §11.4 says a clip whose start *precedes* the previous
resolved end is the error, and `1.2` does not precede `1.2`; `timeline-semantics.md` states
the same rule as disjoint half-open intervals. **The comparison is not the bug** — the entry
retracts that — `timeline.rs` tests `if at < o_end && o_at < end`, a correct symmetric
half-open intersection. The bug is the right-hand side: `0.8 + 0.4` in IEEE-754 is
`1.2000000000000002`, so the hand-off lands one ULP inside the previous clip. Confirmed by
choosing exactly-representable boundaries, where the same shape passes: `0.5 + 0.25 → 0.75`
`ok`, `1.0 + 0.5 → 1.5` `ok`, `0.1 + 0.2` and `0.2 + 0.4` both rejected. The same leak is
printed at an author by `E-TIMELINE-DURATION`: *"below the max resolved clip end
1.2000000000000002"*.

**Costs.** Boundary hand-off is the normal way to sequence two effects on one channel, and
it works at `0.5 + 0.25` and fails at `0.8 + 0.4` — so the failure looks arbitrary from the
author's chair, with a diagnostic that prints `clip at 1.2` and names no discrepancy. An
author learns to sprinkle epsilons (`1.2000001` passes) and carries the superstition into
every timeline afterwards. The measured cost here was a silent substitution: the shed's
`duration` is `0.35` in the committed scene, and nobody reading `spine-a.lute` will ever
know why.

**Fix.** T7.2's, and it is explicit that this is **not** a comparison-operator change:
either an epsilon tolerance on the interval test (`at + EPS < o_end`, with `EPS` well below
any authorable resolution) or — better, and the entry prefers it — **quantise timeline time
to integer milliseconds at parse** and do all cursor arithmetic in that domain, which
removes the class rather than the instance and incidentally stops `E-TIMELINE-DURATION`
printing `1.2000000000000002`.

**Shape.** A representation change in one module, or one tolerance constant.

**Verify.** T7.2's two probe tables are the acceptance suite. All six rows of the
exactly-representable table must stay `ok`; `0.8+0.4→1.2`, `0.1+0.2→0.3` and `0.2+0.4→0.6`
must move from error to `ok`; and every genuinely-overlapping row of the first table (rows
2, 7, 8, 10) must stay an error, including the zero-duration point clip inside a preceding
span. Then set `spine-a.lute`'s shed back to `duration="0.4"` with the hand-off at `1.2` and
`check-project` must be clean.

contracts with nothing in common.

**Costs.** Entirely on ad-hoc verification, which is what an author and an AI harness actually
do. `grep -m1`, `jq '..|.reason?|select(.)' | head -1`, and any harness that greps the file
read the injector's prose and report success. The evidence that the cost is real is that the
task's own brief had to carry a warning sentence about it.

**Fix.** Theirs: `provenance.reason` has the weaker claim on the name — it is a *why*, not a
*what* — so call it `note` or `justification`. Free, and it ends the collision.

**Shape.** One field rename plus a schema bump.

**Verify.** `grep -c '"reason"'` on a compiled scene with an injected preload and an `::end`
must be 1.

### 37. The `anchor` domain's declared default is the one value an author may not write

`TOOL` · `ERGONOMIC` · **Blocker: —**

**Entries** — T5.8.

**Wrong.** `::auto{character="vesna" anchor="center" action="brace"}` where the `anchor` slot
is `{ members: [port, center, starboard], default: center }` →
`bridge.lute:11:34: warning [W-INJECT-CONFLICT] 'vesna' is shown with an explicit
anchor="center" that 'auto-anchor-on-show' would otherwise inject`. The message is accurate
and the mechanism is right, but the *only* authored shape it fires on is **agreement**:
writing a different anchor is honoured silently and writing none is silent. `port`, which
every other Anseo scene writes explicitly, is fine.

**Costs.** Worse than it looks, because there is no suppression: `lute check` has `--deny
<CODE>` and `--deny-warnings` and **no `--allow`**, and there is no in-source
acknowledgement. A project on `--deny-warnings` in CI — which the toolchain's own docs
encourage — cannot express "centre, on purpose" at all: it must either not say it or edit
its vocabulary to silence a diagnostic. The corpus carries two of these deliberately
(confirmed at HEAD), which is the only reason they are not a build failure. Note the same
missing `--allow` is half of **#16**; `dsl 0.6.1 §6` refuses it on purpose, and these two
entries are the evidence for revisiting that.

**Fix.** Any of the three the entry names, cheapest first: do not warn when the explicit value
equals the injected one — nothing is lost, nothing is ambiguous, nothing is overridden; or a
note-level severity; or an `--allow`. `W-INJECT-CONFLICT` earns its keep in its other role
(**#18** cites it as the precedent), but redundancy and conflict are different claims and
this is the redundant case wearing the conflicting case's name.

**Shape.** One equality check before emitting.

**Verify.** `bridge.lute` must check clean with `anchor="center"` still written;
`check-project docs/examples/anseo` must drop from 2 `W-INJECT-CONFLICT` to 0. A genuine
conflict — an explicit anchor that differs from the injected one *and* is overridden — must
still warn, if such a case exists; if it does not, the code's remaining role is **#18**'s
precedent and it should be re-scoped.

### 38. A component param cannot use the long form every other schema surface uses

`TOOL` · `ERGONOMIC` · **Blocker: —**

**Entries** — T6.6.

**Wrong.** The accepted param grammar is exactly two forms — `pressure: string` and
`pressure: { enum: [steady, rising] }`. `pressure: { type: string }` is
`E-COMPONENT-PARSE: … each entry must be 'name: <type>' (dsl §13)`. The long form is how
`state:` entries are written, how `defs:` entries are written, and how the `anchor` domain is
written in Anseo's own vocabulary — and `components-and-extends.md` says component params are
*"typed exactly like a [def param]"*.

**Costs.** Inconsistency rather than restriction: an author who has read the rest of the YAML
surface writes `{ type: string }` and is told their `params:` is malformed. And the failure
compounds — a malformed `params:` means the param is never registered, so the body's `@ref`
resolves against nothing, and the component's own check reports only that consequence
(**#23**'s T6.7).

**Fix.** Accept `{ type: X }` as a synonym for `X`. The entry: *"would cost nothing and close
it."* This asks only for the synonym — **not** for param defaults, which the entry calls
*"arguably defensible"* to omit; see Do not fix.

**Shape.** One deserializer alternative.

**Verify.** All five rows of T6.6's table: rows 1–4 accepted, row 5
(`{ enum: […], default: … }`) still rejected, and `E-COMPONENT-ARG` still fires on an omitted
argument at the `::use` line and column.

# Do not fix

Fifteen settled calls. Some are correct behaviour the log vindicates; some are the tempting
wrong fix for a real issue above. Both are worth writing down, because re-litigating them
costs more than the items themselves.

1. **Single braces in a `<choice>` label are prose (T3.8).** The only no-action entry. The
   log downgraded it from `TOOL-DEFECT` itself: `{{…}}` is documented on the shipped site,
   Lute never reserved single braces, and a tool reproducing unreserved characters is doing
   its job. Its `W-` lint is filed as a wish, explicitly *"not a finding against 0.9.0 as
   shipped"*. The remedy that is real — one sentence on `choices-and-hubs.md` — is in **#11**.
2. **`::set` stays forbidden in a component body (T6.4).** Vindicated with a reason the
   rationale does not even claim: not purity, but that the one number the whole prologue is
   about would stop being auditable by reading if eleven files could charge it invisibly. Do
   not relax it while fixing **#3**, **#4** or **#5**.
3. **`<track>` bodies stay staging-only (T7.1, `E-TIMELINE-CONTENT`).** The entry endorses the
   restriction and its rationale — dialogue in a track would make the beat reader-paced rather
   than clock-paced. **#29**'s fix is additive: admit a content line *carrying an explicit
   `at`*, so the rationale still holds. `<choice>`/`<branch>`/`<match>` stay out.
4. **`after:` stays monotone and negation-free (T8.3, `E-CONN-PROFILE`).** Monotonicity is
   what makes the graph acyclic and decidable, and negation would cost that. **#7**'s fix is a
   declared `exclusive:` group checked by the existing key-set machinery, *not* negation in the
   formula grammar.
5. **`::end` stays `break`-with-a-label (T5.5).** A scene declaring itself `after:` a scene
   that terminates is **correct**, because terminating a document's walk is what every
   document does. Do not add run-level termination semantics to fix the homepage's sentence;
   fix the sentence (**#10** row e) and give the *claim about endings* a place to live
   (**#14**).
6. **Do not renumber the `timeline` ordinal (T7.16).** Argued in the entry and it is not
   close: `0` is not reserved (absence is spelled by omitting the key), the ordinal is an
   opaque correlation key on which equality is the only supported operation, and changing the
   emitted value would silently shift every artifact already produced by one, with no
   diagnostic and no version signal — breaking precisely the consumers who read the doc. Fix
   the adjective (**#10** row i).
7. **`--project` selects the manifest; nearest does not win (T1.10).** Defensible, and it is
   what the flag's own help says. **#30** fixes the check/compile *disagreement* and the inert
   nested manifest, not the resolution rule. And do not carry forward the original entry's
   "nearest manifest wins" — it was probed again and overturned.
8. **`E-FACT-DOMAIN` should not learn ground-fact truth (T4.3).** `can_halt(vesna)` being
   accepted although no route can open it is the correct boundary: the checker validates the
   query's shape and its arguments' domain membership and declines to claim anything about
   runtime truth. T8.8's `W-FACT-UNREACHABLE` (**#12**, stretch) is a *warning* at ground
   granularity and a separate decision — it is not a change to `E-FACT-DOMAIN`'s scope or
   severity.
9. **`exit` stays `Option<bool>`, absent for non-exits (T2.3).** Do not start serializing
   `"exit": false`. The compiler writes `exit` for precisely the declared-exit members and
   never writes `false`, so absence is total and the consumer's rule is one line. (State the
   guarantee correctly: the encoding does not let a consumer distinguish "not an exit" from
   "unset" — it makes the distinction unnecessary.)
10. **Keep the declared vocabulary model over name-prefix heuristics (T2.3, T1.2).** The
    negative control is the cleanest measurement in the log: two artifacts differing in one
    vocabulary member, from one declared list read by one function both checker and compiler
    call. Nothing in Anseo's vocabulary would have survived the deleted
    `fade-out*`/`exit*`/`hide` heuristic — `go-under` and `step-out` are both exits and neither
    looks like one. **#18** and **#32** exist *because* this trade is right.
11. **Do not add a `::pause` / `::beat` primitive (T7.9).** The entry declined a verdict on
    purpose: the working form — a `duration` + `wait="true"` on a staging directive — produced
    *better writing* than the bare hold would have. What is missing is documentation of the
    empty-`<timeline duration>` hold, which is in **#11**.
12. **Keep `lute test`'s eligibility enforcement (T9.16.1).** A `choose:` naming a guard-false
    option is refused rather than silently played, and it is what makes T8.5's hole exactly one
    tool wide. **#2**(b) is additive to it, not a replacement.
13. **Keep `lute init`'s scaffold (T1.1, T1.2).** It checks clean as generated, and its
    `vocabulary.schema.yaml` declares all seven compiler-typed slots with comments teaching the
    two structural rules *and why*. Anseo's vocabulary is a member-for-member substitution into
    it. **#31** deletes two lines from the generated README; it is not an argument against the
    generator.
14. **Component params keep no defaults (T6.6).** The entry calls the no-defaults rule
    *"arguably defensible"* — an explicit argument at every callsite is legible, and
    `E-COMPONENT-ARG` makes an omission a check-time error rather than a silent fallback.
    **#38** asks only for `{ type: X }` as a synonym, and asking for defaults would trade a
    check for terseness.
15. **`lute-lsp` on `PATH` is not a Lute defect (T1.11, T7.14).** `/usr/local/bin/lute-lsp` is
    an unrelated product — `lute --version` there prints `[deprecated] 'lute' is now 'bard
    lute'` and `0.1.0`. It confidently contradicts the compiler (17 errors on a file
    `check-project` calls `ok`) and it cost two agents real time. Nothing to fix in Lute; at
    most one sentence on the install page.
