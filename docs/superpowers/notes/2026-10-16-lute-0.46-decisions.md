# Lute 0.46 — Brinewake dogfood: decisions

Inputs: issues #100–#112 (label `dogfood`), filed while building **The Last Bell at
Brinewake** (`~/Workspace/tidehollow` on the owner's Mac; local git only) — a small
Stardew-style life sim with a walkable PixiJS town and VN scenes, the **first real game on
`@lute-lang/player-web`**, built from scratch on Lute 0.45.0 with canon 0.21. Evidence
(screenshots, friction logs, play-through scripts, Gemini review transcripts) lives on the NAS
at `journey-temp/projects/tidehollow/2026-10-16-dogfood/`; each issue body quotes what the
release needs.

Triage by the orchestrator for the owner (2026-10-16). Rule used: develop what a real host or
author hit and cannot reasonably work around; keep one spelling per concept (no second
surface for the same thing); no runtime-owned presentation (D13) and no execution-time
language features where a documented recipe works. Clean cutover (D6) for every change.

## Develop in 0.46

| Issue | Decision |
|---|---|
| #111 (bug, major) | Fix the name plate z-order in `packages/player-web/src/text/dialogueWindow.ts` (background at index 0) and add a browser visual/assertion test that a named line shows its speaker name. |
| #105 (bug, major) | A Bun host must install cleanly with player-web's exact `effect` peer. Declare the runtime's Bun platform dependencies as peers pinned to the same Effect release line (exact versions, matching `effect@4.0.2`) so a fresh `bun add` resolves a consistent set, and document the Bun-host install line in the runtime README + `typescript-runtime.md` (EN/KO website page too). Verify with a scratch Bun project from the packed tarballs (`scripts/pack-local.sh`) that `import "@lute-lang/runtime/bun"` runs. |
| #102 (major) | player-web reaches parity with `LutePlayer.make`: `MountOptions` gains `snapshot`, `session`, `autosave`, `linePacing`, `cueFactory` with the same meaning and validation as the player options; the mounted handle exposes `bundle` (the loaded `Bundle`) and `snapshot`/`restore`/`send`/`program`. The Promise facade `mountPlayer` gains the same operations as Promise methods (thin wrappers, no extra behaviour). The custom-hosts recipe "resume in a fresh player from a save" works with player-web and is shown for it. |
| #103 (bug) | player-web stops using Pixi's global `Assets` singleton: it owns a private loader/resolver instance, so a host Pixi app on the same page can `Assets.init` normally. Test: host `Assets.init({ basePath })` after `mount` keeps its basePath. |
| #104 (bug) | `W-BINDING-UNUSED` counts `ui.title.background` / `ui.title.music` (and any other `ui.*` asset reference) as uses of `assets:` keys. |
| #100 (bug) | A component (or template) `params:` name that collides with a reserved attribute of the `::use` site (`at`, `when`, …) is rejected at the declaration with one diagnostic naming the reserved list, instead of failing at every use. Pick the existing code family; register EN/KO pages. |
| #106 (bug) | `lute test --coverage` merges arms executed by play scripts into branch/match arm coverage, so a match covered only by plays reports covered. |
| #107 | Play scripts can assert a refused raise: an `expect` form for a step whose occasion the runtime refuses (`E-OCCASION-GATE`, closed `raisedWhen`), which checks the code and continues the play. Reuse the play-step style; document in tooling/play EN/KO. |
| #112 | Multi-ending games can name the ending: bindings `ui.ended` gains an optional per-member screen table keyed by a state path the project declares (e.g. `by: run.ending`, `screens: { restore: { title, text, background? } }`), checked by `lute check` against that path's domain (unknown member refused, unmapped member falls back to the default screen). player-web renders it. Bindings schema + Rust checker + generated TS + player-web; `bindingsVersion` follows the release. |
| #110 | One end-to-end tutorial for the current release on the website (EN + KO): schema + clock → scenes/beats/barks → plays → bindings → a host with player-web (map/occasions/background barks/save). Every snippet compiled by the doc-snippet check. |

## Do not develop (document instead)

| Issue | Decision |
|---|---|
| #108 | Keep one spelling for entity kinds (`{ members: [...] }` / `{ open: true }`). Do not accept the list shorthand (a second spelling of one thing). Fix the message: `E-ENTITY-KIND-SHAPE` shows the exact `members:` spelling for the author's list. |
| #109 | No contract change. `Program.clock` stays numeric indexes by type; document on the runtime-contract page and in `typescript-runtime.md` that slot names and weekday labels come from `program.view(state).clock`, with a HUD snippet. |
| #101 | No runtime-resolved directive fields and no `fromState:` lowering: that turns staging records into run-time expressions and blurs the build-time/run-time line. Document the recipe (component + enum domain + def + match, or setting `time` per scene) on the clock / plugins page. Candidate for later, only if another game hits it: a **player-side** opt-in where a background binding without an authored `time` follows the current clock slot (presenter policy, no language change). |
