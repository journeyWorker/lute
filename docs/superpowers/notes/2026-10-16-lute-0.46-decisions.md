# Lute 0.46 — Brinewake dogfood: decisions

Inputs: issues #100–#112 (label `dogfood`), filed while building **The Last Bell at
Brinewake** (`~/Workspace/tidehollow` on the owner's Mac; local git only) — a small
Stardew-style life sim with a walkable PixiJS town and VN scenes, the **first real game on
`@lute-lang/player-web`**, built from scratch on Lute 0.45.0 with canon 0.21. Evidence
(screenshots, friction logs, play-through scripts, Gemini review transcripts) lives on the NAS
at `journey-temp/projects/tidehollow/2026-10-16-dogfood/`; each issue body quotes what the
release needs.

Triage by the orchestrator for the owner (2026-10-16). Rule used: develop what a real host or
author hit and cannot reasonably work around; keep one spelling per concept (no second
surface for the same thing); no runtime-owned presentation (D13) and no execution-time
language features where a documented recipe works. Clean cutover (D6) for every change.

## Orchestrator choices (conservative, 2026-10-16)

Judgement calls made while writing the 0.46.0 spec; each picks the narrower or the
already-established option.

| Topic | Choice | Why |
|---|---|---|
| #100 reserved list | A `::use` site reserves `component`, `when`, `at` and `instance`; a component param with one of these names is `E-TEMPLATE` at the `params:` entry (the existing collision check), and the message names the whole list. Beat-template header keys stay as they are. | `at` (timeline clip) and `instance` (identity) are already stripped from named args at every use (`check/use_site.rs`), so such a param can never be passed — the same defect class the existing `component`/`when` check refuses. No new code: `E-TEMPLATE` already owns declaration collisions. |
| #104 ui asset references | Every `ui.*` asset reference (`ui.title.background`, `ui.title.music`, `ui.ended.screens.*.background`) is resolved the way player-web resolves it: an `assets:` key counts as a use of that key (its file is checked through the `assets:` entry); any other value is a path below `assetsBase` and is file-checked (`E-BINDING-FILE`). | One rule for every ui reference, matching the player (`mount.ts` `resolveAsset`). Before 0.46 the checker treated `ui.title.background` as a path only (an `assets:` key there was a false `E-BINDING-FILE`) and never checked `ui.title.music`. |
| #112 shape | `ui.ended: { by: <state path>, screens: { <member>: { title, text, background? } } }`; `by` and `screens` required when `ended` is written. `by` must name a declared state field whose type is a domain with a closed member list (an enum, or an entity kind with `members:`); otherwise `E-BINDING-KEY`. An unknown `screens` key is `E-BINDING-KEY`; an unmapped member is silent and shows the stock screen. No `W-BINDING-MISSING` for unmapped members. | Decision table wording; existing code family (`E-BINDING-KEY` already covers "not a declared domain member … or target"). The fallback is the owner's rule, so a warning would contradict it. |
| #112 resolution | player-web reads the member with the existing query `program.view(state).state[by]` (the effective state keyed by full path) on the session's ended state — no new runtime query, no player-core `ScreenModel` change — for any ended reason; a non-string, absent or unmapped value, or a failing query, shows the stock screen. | No runtime-owned presentation (D13); the screen is player-web's. (Spec review: name the query.) |
| #102 `seed` | `MountOptions` takes the whole `LutePlayerStart` union (`seed` \| `snapshot` \| `session`, mutually exclusive) besides the listed options. | Parity with `LutePlayer.make` is the decision's headline; `seed` is part of the same start union, and leaving it out would need a second, narrower type. |
| #102 Promise facade | `mountPlayer` resolves to `{ act, view, unmount, send, snapshot, restore, program, bundle }`; each Promise method runs the handle's Effect and rejects with the same failure value; `program` and `bundle` are the handle's values. | "Thin wrappers, no extra behaviour". |
| #107 scope | `expect: { refused: <code> }` is a step-level key on `occasion:` steps only (spec review: an `advance:` already notes a closed raise and moves the clock); the only accepted code is `E-OCCASION-GATE` (raisedWhen false, or game over and not `outsideRun`). It combines with state-reading keys (`state`, `facts`, `notFacts`, `clock`, `quests`) checked against the unchanged state, and not with presentation keys (`winner`, `offered`, `notOffered`, `presented`, `options`). A step that expects a refusal and is accepted is a miss; the play then continues. | Smallest form that tests a gate; refuses combinations that cannot mean anything. |
| #106 scope | Play runs contribute match arms **and** guard taken/skipped to arm coverage (both live in the same `arms` table); JSON shape unchanged, only counts and the human header change. | One coverage table; the header no longer excludes plays. |
| #105 | The documented Bun-host install line pins `effect`, `@effect/platform-bun` and `@effect/platform-node-shared` at `4.0.2`; the runtime declares `@effect/platform-node-shared` as an optional exact peer next to `@effect/platform-bun`. Verified in a scratch Bun project from packed tarballs. | Matches the existing exact-peer convention; an optional peer does not force non-Bun hosts to install it. |
| #110 location | Tutorial `getting-started/build-a-town-game` (EN/KO) over a complete project `docs/examples/quayside/` (in the checked corpus: `lute test`, `check-project --deny-warnings`, CLI snapshot). Lute/YAML blocks are pinned with `check="docs/examples/quayside/…"`; the TypeScript host blocks are type-checked against the built packages by a throwaway check at slice time (the doc-snippet check has no TypeScript mode). | Existing pattern (`build-an-investigation` + `docs/examples/investigation`). |
| llms mirror | `packages/website/public/llms-full.txt` is updated once, in the last docs slice, for every 0.46 page change it mirrors. | Avoids concurrent edits to one hand-maintained file. |
