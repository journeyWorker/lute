# Lute 0.51 — flow and text: decisions

Decided by the orchestrator under the owner's delegation (2026-10-25: the owner delegated every
0.50/0.51 design choice to the orchestrator). The orchestrator adopted the recommended options of
[`docs/design/0.50-extensibility-options.md`](../../design/0.50-extensibility-options.md) for the
0.51 items (§6 C, §7 A, §3 A, §8 A `pair`, §9) and its §10 "not developed" list. While the
normative spec [`docs/proposals/scenario-dsl/0.51.0.md`](../../proposals/scenario-dsl/0.51.0.md)
was written, some details of the recommendations did not hold against the code. Each departure
below records what the spec does instead and the evidence. Where a recommendation was unsound,
the spec takes the conservative option and says why.

Code facts in the items below were first cited at `f34f141f` (v0.49.0), the commit the 0.50 spec
also cites, plus the changes the 0.50 spec describes. 0.50.0 has since been released (`9ccd2fa9`)
and its implementation departed from its draft in places; the section "Reconciled with 0.50.0" at
the end lists every change made to the 0.51 documents, and the spec's Appendix A cites every
anchor at `9ccd2fa9`. Where an item below and that section disagree, that section holds.

Implementation plan:
[`docs/superpowers/plans/2026-10-26-lute-0.51.0-flow-and-text.md`](../plans/2026-10-26-lute-0.51.0-flow-and-text.md).

### #176: what is covered and what is deferred

The issue (closed in v0.49.0 by its option 2, refusal at load) names structured source columns.
0.51 does not claim that every one of them has a route:

- **Deferred:** generic enum-list metadata (the issue's `::tagged{tags=…}` with
  `{ list: { enum: [a, b] } }`) and **language-keyed voice-asset maps**. One `voiceKey` per line
  (`crates/lute-compile/src/address.rs:340-342`), resolved without a locale
  (`packages/player/src/cues/index.ts:75-78`), is not a per-language asset map, and a scalar
  `voiceAssetId` stamp is one asset, not one per language.
- **Scalar decompositions, documented where they apply:** a record's fields as one attribute each
  (typed per surface with a scoped stamp, 0.50 #163); player-visible text in several languages as
  one `text` attribute with a locale bundle (#165); a list that really is a set of options as
  `<choice>` elements of a `<branch>`/`<hub>` with option stamps (0.50 #164). Using `<choice>`
  changes metadata into interaction, so it is a route only for real options.

A JSON-array value syntax touches the parser, tree-sitter, `lute fmt`, the LSP, the checker and
component parameters (options §9 cost "M"). 0.51 keeps the refusal and defers structured
authoring; it is reconsidered on a new issue for the deferred cases. The 0.49 refusal message
(`crates/lute-manifest/src/validate.rs:291-296`) recommends a JSON-in-a-string workaround; 0.51
replaces that hint (spec §7). The comment for the issue is in the plan's release step 6.

## Where the spec departs from the options document

Each item was found while specifying.

1. **#159: no snapshot shape change.** The options document puts the loop counters in the
   runtime snapshot with a `snapshotVersion` bump. The runtime resumes a suspended input by
   replaying it from its pre-input world with the answers already given
   (`crates/lute-runtime/src/runtime.rs:1-5`; `Continuation { before, input, answers, … }`,
   `:495-506`; `ReplayFactory::replaying`, `:1496`). Counters are walk-local machine state, like a
   hub's `presentation` (`machine/menu.rs:532`), so replay rebuilds them exactly. **Instead:**
   counters live in the machine for one walk. The `Snapshot` shape (`runtime.rs:337-349`,
   `deny_unknown_fields`) does not change. `snapshotVersion` moves to `0.51` only because every
   axis moves (`docs/versioning.md`, "Alignment"). A conformance case saves and restores in the
   middle of a loop.
2. **#159: a tighter scope rule.** The options document allows the label in "the jump's own body
   or an enclosing one". The runtime runs a hub option body, a hub `<return>` body, a quest
   handler or objective segment, and an entry or beat body as a separate range, and a transfer
   that leaves the range ends it (`machine/mod.rs:669-695`: `if n < start || n >= stop { return }`;
   hub segments `menu.rs:723,739`). A backward jump out of a hub option body would end the
   option, not loop. **Instead:** the chain of bodies from the jump up to the label's body may pass
   only through `<choice>` bodies of a `<branch>` and `<match>` arm bodies, which are laid out
   inline (`E-JUMP-LOOP-SCOPE`).
3. **#159: the counter reset is defined by the region, not by the jump.** The options document
   resets a counter "whenever control reaches its label other than by that jump". With two bounded
   jumps to one label, each would reset the other, and the alternation would never end. **Instead:**
   a counter resets when control arrives at the label from outside the jump's region (fall-through
   into the label, a forward jump, or a bounded jump that lies outside the region). Termination
   follows by induction over the nesting (spec §3.3).
4. **#159: two existing soundness gaps for forward jumps, fixed by the same join.** Definite
   assignment (`crates/lute-check/src/defassign.rs:407-481`) and the stage-state fold
   (`crates/lute-check/src/check/injections.rs:19-65`; the compile walk
   `crates/lute-compile/src/stage.rs:48-110`) thread state straight through a `::label` and never
   join the states of the jumps that reach it. Checked with `@lute-lang/lute@0.49.0`:
   - `::jump{to="later" when="run.f"}`, `::set{run.x = 1}`, `::label{name="later"}`,
     `@narrator: x is {{run.x}}.` (with `run.x` declared without a default) checks clean; on the
     jump path `run.x` is unset, so it should be `E-MAYBE-UNSET`;
   - `@mira: Hi.`, `::actor{character="mira" action="hide"}` (`hide` a declared exit),
     `::jump{to="l" when="run.f"}`, `::actor{character="mira"}`, `::label{name="l"}`,
     `@mira: Again.` checks clean; on the jump path `mira` is off stage, so it should be
     `W-STAGE-ABSENT` at that line. The line injects nothing (a line never auto-shows,
     `crates/lute-check/src/inject.rs:692-750`; 0.50.0 §7); a later explicit `::actor` on that path
     is a fresh show with its injected anchor (`inject.rs:596-640`).

   A loop head's entry state is the join of every edge into it, forward jumps included, so #159
   cannot be sound without this join. **Instead of filing and deferring:** the #159 checker slice
   gives every flow walk one label join, which fixes both gaps. They are a "Fixed" CHANGELOG entry
   with their own regression tests, and the plan files an issue so that the fix is traceable.
   `fact_must.rs` already joins at labels (`:868-885`) and is the model.
5. **#159: `lute trace` does not unroll and reports no *Bounded* verdict.** `lute trace` executes
   on the runtime (`lute-trace/src/lib.rs:1-40`, `trace/driver_records.rs:214-222`), so it follows
   the one path the runtime takes, and the counter bounds it. **Instead:** the trace prints each
   taken back jump with its count and the exhausted fall-through (`again 1/2`, `not taken: 2/2
   used`). Nothing in it is a static claim (the D1 quarantine).
6. **#159: the runtime's runaway guard.** `run_range` stops after `commands.len() * 64 + 1024`
   steps (`machine/mod.rs:675`). Nested loops of `max="99"` legitimately exceed it. **Instead:** the
   guard counts steps since the last taken bounded back edge. Between two such takes the walk is
   acyclic, so the guard still catches a defect cycle.
7. **#159: `max` is declared in `lute.core`, which moves `capabilitySnapshot` once.** The jump's
   attributes live in `crates/lute-manifest/assets/lute.core/directives/staging.yaml:83-87`, and the
   hash folds each directive's `Debug` (`crates/lute-manifest/src/snapshot.rs:279-285`). One
   declaration site is right (LSP, `lute context` and the checker read it), so every artifact's
   `capabilitySnapshot` changes once. The spec makes this its own delta class and the plan checks
   that it is the only difference in those outputs.
8. **#170: its own codes.** The options document reuses `E-PLUGIN-PARSE` for an undeclared
   occasion, `E-BEAT-ATTR` wording for a bad target, and `E-CONN-UNKNOWN-NODE` for a target nothing
   answers. An occasion can come from another plugin, so it is known only at assembly (the 0.50
   `E-PLUGIN-STAMP-SURFACE` precedent). `E-BEAT-ATTR` is about a beat's own attributes, and
   `E-CONN-UNKNOWN-NODE` about `after` formula atoms (`crates/lute-cli/src/codes/registry.rs:80-83,330-333`).
   **Instead:** `E-PLUGIN-RAISES` (assembly) and `E-RAISES-TARGET` (per call, project-wide), one
   code per layer, like `E-ACCEPT-TARGET` for `::accept`.
9. **#170: reachability follows the accept precedent.** A `raises` anchor never proves a node
   unreachable (`connectivity/reachability.rs:249-266`: an anchored quest's `Unreachable` reads
   `Unknown`); a `[raises]` edge that would close a cycle is not drawn
   (`connectivity/graph_assembly.rs:243-246`); and a scene that declares `after:` keeps `after:` as
   its declared route (`graph_assembly.rs:404-406`). A scene that both raises and answers itself
   ("play again") is legal content and must not be `E-CONN-CYCLE`.
10. **#170: the runtime copies resolved raises onto its records, and the reference host shell
    performs them.** The options document has no runtime or player change. A host acts on the event
    stream, and the runtime alone binds `occasion.target` in a call (`machine/plugin.rs:113-127`).
    **Instead:** the `plugin` record and the `grant` record carry the resolved `raises` (an untyped
    record payload: no event schema change). The runtime still raises nothing (D13). The reference
    player's session (`packages/player/src/session/index.ts:25-50`), which already raises occasions
    from `bindings.flow.idle`, raises declared raises when the runtime is idle, before its idle
    flow. Without that, a project using `raisedBy: declared` could not be played in the reference
    player. Review051 F2: because replay re-emits only the undelivered suffix of an output
    (`runtime.rs:1062-1083`), the player persists its pending raise queue in saves and rollback
    points (spec §4.6); the player save shape changes, the Rust `Snapshot` does not.
11. **#170: target binding is typed.** `target: "@scene"` with an occasion domain
    `{ prefix: scene, entity: cutsceneId }` must say how a member becomes a target. **Instead:** an
    `@attr` target names an attribute typed `{ entity: <the domain's kind> }`, and the raise target is
    `<prefix>.<value>`. For `target: true` the attribute value is the whole dotted target. A literal
    is always the whole target.
12. **#165: one `localized` object per attribute, not parallel maps.** The options document adds
    `lineIds`, `texts` and `placeholders` maps keyed by attribute. The reference player collects the
    bundle's locales from the keys of every `texts` map in the artifacts
    (`packages/player/src/cues/index.ts:202`), so `texts: { title: { ko: … } }` would make `title` a
    locale. **Instead:** `localized: { <attr>: { lineId, placeholders?, texts? } }`. The scan
    (`bundleLocales`, `cues/index.ts:194-207`) also stops at any property *named* `texts` or
    `promptTexts`, so an attribute with one of those names would still be misread (Review051 F5);
    the scan therefore reads each `localized` entry structurally (its own `texts` keys) and never
    applies the name rule inside `localized`. St owns that change, with tests for both names.
13. **#165: the choice-label grammar, so `E-L10N-MODIFIERS` does not apply.** The options document
    lists `E-L10N-MODIFIERS` as applying unchanged. That check compares inline markup modifiers and
    runs for lines only (`crates/lute-compile/src/locale.rs:312-348`); option labels and prompts go
    through `bind` (`:282-305`), which has no markup. A `text` attribute takes the label grammar
    (`{{…}}` interpolation with modifiers, `\{{`; `scan_label_interps`, `lute-syntax/src/ast.rs:830`)
    and merges through `bind`.
14. **#165: `text` only on a directive that compiles to a `plugin` record.** The options document
    refuses `text` only for a `lower: { record }` binding. A staging or builtin lowering never
    carries localized text, so a declared `text` attribute there would be silently dropped (0.50
    rule "no silent drop"). **Instead:** a `text` attribute on any directive with a `lower:` is
    `E-PLUGIN-PARSE`, and so is one on a directive with `bridge:` (a bridge signature has no `text`
    type).
15. **#165: the runtime renders a `text` attribute.** The options document passes `texts` through.
    The runtime renders a line's `{{…}}` markers and its translations' (`machine/commands.rs:57-121`);
    option labels keep raw markers today, which leaves every host to re-implement rendering.
    **Instead:** the `plugin` record's `attrs.<attr>` and its `localized.<attr>.texts` are rendered
    the way a line's are, with host-token markers kept verbatim (`machine/format.rs:19-27`).
16. **#165: the export row is `kind: "directive"`, with `key: "<tag>.<attr>"`.** The issue suggests
    `plugin-text`. The CSV schema has one column set for every kind (`crates/lute-cli/src/loc.rs:732-744`),
    and `key` already carries a choice's or prompt's structural key. **Instead:** no new column;
    `code` is filled, `speaker` is empty. `loc import` accepts the kind (it rejects unknown kinds
    today, `loc.rs:1287`).
17. **#172: `when` is refused on `pair`, and the fault rules are fixed.** A `pair` rule has no
    single-row predicate. The spec fixes the precedence (a node matching both `open` and `close` is a
    close while a pair is open) and the four fault phrases, so findings are deterministic.

## Review amendments

Review051 (2026-10-26, "not ready", ten findings) was applied to the spec and the plan, with these
decisions by the orchestrator:

1. **F1** — label and loop joins cover the complete definite-assignment `Flow` (`available` and
   `writes`, `defassign.rs:198-213,1470-1481`), so a skipped write leaves the envelope
   (`envelope.rs:56-94`); the `lute-model` consumers (`scenario.rs:113-135`,
   `reconcile.rs:691-710`) join the S2 inventory; their output changes are class 5.
2. **F2** — the player persists the pending declared-raise queue, with its consumption boundary,
   in saves and rollback points (save format `"0.51"`, the `stores/index.ts:42-46` codec
   included); the Rust `Snapshot` is unchanged. Re-review ("ready after fixes"):
   - **F2a** — the rollback checkpoint is the **existing pre-input checkpoint**: the runtime
     snapshot, pending queue, log and backlog captured before a player input P is submitted
     (`session/index.ts:185-194`). Automatic declared raises never create, replace or append a
     checkpoint, so they are grouped with P into **one** rollback step: `rollback(1)`
     (`director/index.ts:585-593`) undoes P and its raises together. Example: before P
     `(W0, [])`; P produces `(W1, [A, B])`; `rollback(1)` restores `(W0, [])`; replaying P
     regenerates `[A, B]` and delivers each once.
   - **F2b** — an accepted `newRun`, `toStart` or lineage replacement clears old pending raises;
     a rejected one keeps them; the new start output's raises are enqueued exactly once.
   - The director drains the queue at its presentation-settled boundary
     (`director/index.ts:343`), before the host `idle` and the bindings' idle flow (`:567-579`).
3. **F3** — directive text ids are `{prefix}~{tag}~{code}~{attr}`, outside the line template;
   `~` is refused in `lineId` templates (`E-IDENTITY-TEMPLATE`) and in codes
   (`E-LINE-CODE-RESERVED`); `E-LINE-ID-DUP` checks final ids across every unit kind. The
   earlier `{prefix}.{tag}_{code}.{attr}` collided with a choice id
   (`address.rs:345-366`). A legacy `episodeId` in a scene prefix is free text and can contain
   `~` (`crates/lute-check/src/meta/kind.rs:421-444`), so the separator alone does not prove
   distinctness: `E-LINE-ID-DUP` governs that case.
4. **F4** — `effects.raises` on a record- or builtin-lowered directive is
   `E-PLUGIN-INVALID-DIRECTIVE` (staging records have no effects slot, `validate.rs:497-502`;
   `lower.rs:430-440`); staging records are not extended.
5. **F5** — locale discovery reads `localized` structurally (item 12).
6. **F6** — a raise target resolves from the authored value, then the declared default
   (`lower.rs:464-478`); only a genuinely unbound target is suppressed.
7. **F7** — attribute defs stay constant-only (`def_inline.rs:1-14`, `expand.rs:438-452`);
   `occasion.target` is the only dynamic raise target.
8. **F8** — the stage fix asserts `W-STAGE-ABSENT` at the line; entrance injection happens only at
   an explicit `::actor` (item 4).
9. **F9** — definite-assignment loop cases are one-pass stability tests; iteration-disabled
   mutation tests are for facts and stage.
10. **F10** — #176 is reworded: structured authoring deferred, refusal kept, scalar
    decompositions documented where they apply.

### #159

- **R4 — a loop region may not span an `<on>` or `<objective>`** (`E-JUMP-LOOP-SCOPE`, new cause).
  *Reason:* a quest body's top level admits `::label`/`::jump` beside `<on>`/`<objective>`
  (`admission.rs:22-24`), so the original scope rule (empty chain = allowed) admitted a region
  containing them. Each is its own runtime range, and in `fact_must` each carries a 0.50 grant point
  (`lifecycle`, `:782-798`); a probe pass over it would re-apply a grant transfer.
- **R5 — the fixed point keeps every 0.50 Must removal** (spec §3.4 "0.50 rules the fixed point
  keeps", §3.8 tests). *Reason:* 0.50 removed unsound Must claims after review (reward asserts
  possible only, "S3 fix 2"; #203 deferred handler guards, `outlasts_deferral`; #205 quest start
  facts, `outlasts_quest`). The iteration starts from the state on arrival, re-walks only [L, J]
  and only meets, so it cannot reintroduce them; the spec now says why, with one regression test
  per rule.
- **R6 — jump transfer by kind.** An unguarded jump without `max` leaves bottom (as `fact_must`
  does, `:1232-1235`); a guarded or bounded jump sends a copy and falls through; defassign's
  fall-through becomes an `Option<Flow>`. *Reason:* the draft said only that the jump state is
  recorded; a bounded jump without `when` would otherwise end the fall-through and lose its
  exhaustion path.
- **R7 — probe passes publish nothing** (no diagnostics, verdicts, recorded slots, emitted
  records, and no update of the outer or final-pass pending map) but route control fully, with a
  fresh probe-local pending map per iteration (amended by Review051b F1, below); the head is the
  hub's kind of fixed point (greatest below the entry for a Must lattice,
  `fact_must.rs:1363-1392`), not a "least" one. *Reason:* wording; `record_span` (`:892-904`)
  already intersects visits, which the spec notes so the hub keeps its per-pass recording.
- **R8 — counted, bounded iterations.** `LoopWalkStats` per walk kind; per-head bounds (facts
  |entry| + 1, stage 3 × characters + 2, defassign 1); widening; a `lute-bench flow-loops` grid in
  S2 with work as the CI test. *Reason:* the owner asked for 0.50's work-counter approach (0.50 §8.1
  "Cost"); nested heads multiply, so the bound is stated as the runtime's Π(max + 1) shape.
- **R9 — positions** (corrected by Review051b F7). The label pass's counter is depth-first and
  ticks at every node — lines, ordinary directives, `::set`/`::assert`/`::retract`, timelines
  (`next_labels.rs:142-152`) and every structural node before its bodies (`:153-180`); the module
  comment (`:9-17`) saying only label/jump sites tick is stale. The region is the nodes at positions
  in [l, j], i.e. L, J and the nodes that order visits between them. *Reason:* the first
  reconciliation followed the stale comment.
- **R10 — the stage fix** asserts `W-STAGE-ABSENT` with 0.50's S8 hint (the full `lower:` form,
  `ACTOR_LOWERING_HINT`); envelope anchors name `guaranteed`, `scene_effects` and the quest
  completion envelope `writes_on_complete` (`envelope.rs:194-230`). *Reason:* 0.50 S8 changed the
  hint; the draft cited a block range.
- **R11 — `max` and 0.50 stamps.** `on: [jump]` stays `E-PLUGIN-STAMP-SURFACE`

### Review051b (re-review of this reconciliation, "not ready", 7 findings)

All applied; the open choices were decided by the orchestrator (2026-10-26).

- **F1 (P1) — probe routing.** Forbidding pending-label updates in probes was unsound: in a loop
  with an unguarded forward jump to a later label, then a retract and the back edge, the retract
  is reachable only through the pending map (`fact_must.rs:1018-1036,1223-1235`), so the head
  could keep a fact absent on later iterations. **Decision:** each probe pass (nested probes
  included) keeps a fresh probe-local pending map and accumulates back edges; only publication into
  the outer or final-pass pending map is forbidden. S2 adds the reviewer's forward-jump-inside-loop
  regression (spec §3.8).
- **F2 (P2) — reward grant sites.** `quest_grants` (`reward_effects.rs:225-263`) emits one
  `GrantEffect` per fact/accept effect, so a raises-only reward yields none and a mixed reward
  several. **Decision:** S5 owns `reward_grant_sites`, one site per reward with 0.50's grant-point
  and outcome rules and per-document vocabulary, and rebuilds `quest_grants` on it; tests for
  raises-only and mixed rewards.
- **F3 (P2) — clock diagnostics.** `RaiseModel::open` admits only scheduled positions
  (`clock_positions.rs:972-981`), and `unraised`, `check_project_unraised` (`W-BEAT-UNRAISED`) and
  `chapter_window` claim absence from it. **Decision:** a declared raise that reaches an answerer
  counts as a possible delivery at any position (`rule` `None`). S5 owns it. Two corrections from
  the re-check (orchestrator, 2026-10-26):
  - **F3a — matching.** "Reaches" is the raise table's one answerer rule (`RaiseTable::reaches`),
    used by anchors, `W-OCCASION-NEVER-RAISED`, `E-RAISES-TARGET` and the clock analyses alike:
    same `on:` occasion, and an untargeted occasion, a **targetless answerer of a targeted
    occasion** (it answers every target), an `occasion.target` raise, or an equal static target.
    The first wording listed only static/untargeted/`occasion.target` and missed targetless
    answerers. Regression: a targetless beat on a targeted occasion reached by a raise for one
    target.
  - **F3b — scope.** `rule` `None` removes only schedule-only impossibility claims (`unraised`
    returns `None`, `clock_positions.rs:990`). It is not "no closing window is claimed":
    `chapter_window` still evaluates the scenes' guards (`:1145-1181`), so a genuinely expired
    `when` window still reports `W-CHAPTER-STALL`. Tests: one chain whose warning disappears
    (schedule-only), one whose expired guard still warns.
- **F4 (P2) — writer provenance.** `node_envelope.rs:16-41` crosses every ordering edge to find
  "provably before" writers. **Decision:** an edge whose only kind is `Raises` is not crossed; an

- **F5 (P2) — `code` in stamps.** `plugin_stamps` (`lower.rs:291-293,795-809`) uses
