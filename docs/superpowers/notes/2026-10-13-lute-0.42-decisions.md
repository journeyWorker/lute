# Lute 0.42 — decisions

Owner-approved **2026-10-13**. These quotations are the owner decisions and
are normative inputs to
[`docs/proposals/scenario-dsl/0.42.0.md`](../../proposals/scenario-dsl/0.42.0.md).
The spec's additional choices are collected in its Appendix A.

## #77 — volume (owner decision, 2026-10-13)

> **Owner decision (2026-10-13), for 0.42:** `volume` stays a project vocabulary domain (intent, not numbers — same rule as `emotion` / `framing`), and its members are **levels of degree**, not relative moves.
>
> 1. **Bindings map levels to gain.** `player.bindings.yaml` gains `volumes: { <member>: <gain 0..1> }`. `lute check` validates it against the project's `volume` domain like the other binding tables (`W-BINDING-MISSING` for an unmapped member, unknown member refused). The player turns a member into gain only through this table; the `Number(...)` parse in `musicVolume` (`packages/player/src/cues/index.ts`) is removed. An unmapped member never plays at full volume.
> 2. **Documented members are an ordered scale of degree.** Docs, templates and examples teach `volume: [silent, quiet, normal, loud, full]` instead of `[silent, down, normal, up, full]` — `up` / `down` read as "louder/quieter than now", which the runtime does not do (a volume is an absolute level; writing `down` twice does not get quieter).
> 3. **Migration.** The corpus is migrated (`down` → `quiet`, `up` → `loud`; ~158 uses). A `lute fix` rule renames only in projects whose `volume` domain is exactly the old documented set; a project that chose its own members (`low`, `muted`, `raised`, `alarm`, …) keeps them and only needs the `volumes:` table.
>
> Rejected: numeric `volume=0.5` (mix values scattered through scripts, no checkable set, conflicts with the 0.37 staging rule); accepting both forms (two spellings of one thing).

## #78 — resolved media/staging attrs (owner decision, 2026-10-13)

> Runtime `music` / `sfx` / `vfx` (all media/staging records the runtime emits as records) carry resolved `attrs`, the same way 0.41 plugin records do (spec 0.41.0 §5.5) — an Event-contract change: Rust types, generated events/snapshot schemas, generated TS, conformance regeneration, docs. Decide exactly which record kinds (inspect what the runtime emits) and say why.

Recorded resolution: inspection at `f014cdbb` found the runtime dispatches nine
staging record kinds (`bg`, `music`, `sfx`, `vfx`, `actor`, `camera`, `cg`,
`video`, `sequence`). All nine carry `attrs` in 0.42, because a host should
not need an artifact join for any emitted staging record. The exact shapes and
0.41 §5.5 default/timing/stamp rules are normative in spec §4.

## #79 — public cue wrapper and snapshot (owner decision, 2026-10-13)

> `LutePlayer.make` gains a `cueFactory: (base: CueFactoryShape) => CueFactoryShape` option (wrap the default factory; the documented cue seam becomes public API), and `LutePlayerHandle.snapshot: Effect<SaveRuntime, …>` so a host can checkpoint and later `restore`.

Recorded resolution: the public error channel is
`Errors.RuntimeRejection`; the save contains runtime snapshot (including the
pending stage in its continuation), accepted-input log, and backlog (including
`voiceKey`), but not presenter/timer/overlay/profile state. `restore` still
accepts exactly `SaveRuntime`.

## #80 — Director host plugin (owner decision, 2026-10-13)

> `Director.make` takes `host.plugin` and wires it into its cue factory, so hand-composed and `LutePlayer.make` hosts behave the same (no silent no-op).

Recorded resolution: when both a pre-composed `Cues.make({plugin})` and
`host.plugin` provide a handler for one tag, `host.plugin` wins; unique tags
from either map remain available and a duplicate is run once.

## #70 — voice replay (owner decision, 2026-10-13)

> Voice replay resolves the file by the line's `voiceKey` (carry it in the backlog entry / `replayVoice` event), same file as the original cue.

## #68 — Bun checks and CI (owner decision, 2026-10-13)

> Package `typecheck` scripts move to `bun check` (Bun 1.4.3, https://bun.com/blog/bun-v1.4.3); CI's `bun-version` pins move 1.4.2 → 1.4.3 everywhere in `.github/workflows/*.yml`; keep `tsc` only where `.d.ts` emit is needed (`build`); one release of parallel comparison: CI runs both `bun check` and `tsc --noEmit` and fails if their error sets differ (decide how to compare; keep it simple).

Recorded resolution: comparison extracts normalized diagnostic tuples and sorted
message text, compares sets, and is removed after 0.42.0 while the package
script remains `bun check`.
