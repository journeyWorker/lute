# Lute 0.48 — CLI grammar cutover: decisions

Owner decision (2026-10-19): apply [`docs/design/cli-grammar.md`](../../design/cli-grammar.md) to
every command in one release. The grammar came from an audit of the 0.47.2 surface
(`lute schema`, 34 leaf commands): operands and options were inconsistent (the project given
four ways, a graph node four ways, `--target` / `--explain` / `--run` each with two meanings,
`--json` missing on eleven commands, shared options present on some commands only), and two
actions had two command names each (`check` / `check-project` by scope, `compile` /
`compile-stream` by mode).

- The project is always `--project <DIR>` with upward discovery (grammar §2).
- No alignment with canon's flag names (canon uses `--<noun>-id`; Lute uses `--node`).
- D6 clean cutover: removed spellings are usage errors that name the replacement (grammar §7).
- Output is text by default and JSON only with an explicit `--json`; no TTY switching, no
  environment default (grammar §1.1).
- Ordinary commands execute by default; dangerous ones preview by default and act with
  `--commit`; `--yes` skips a prompt, `--force` only overrides a refusal (grammar §1.2).
- One command per action (grammar §1.3): `check-project` folds into `check`, `compile-stream`
  into `compile`; no operand means the whole project, and `--all` is removed.

## Mapping (0.47.2 → 0.48)

Rows list only what changes; every other option keeps its spelling.

| Command | 0.47.2 | 0.48 |
|---|---|---|
| `check-project` | `check-project <DIR>` (project-wide checks, `--wip`); report id `check-project` | `check` with no document operand: every document of the discovered `--project` plus the project-wide checks; `--wip` valid only in this mode (with documents, `E-CLI-USAGE`). The command `check-project` is removed |
| `check` | `check <FILE>`; report `0.43.0.check` | `check [<FILE>]…`: the named documents only, resolved in their project — the same per-document analysis as today (relational guard decisions still need the whole-project mode; say so in help and docs). One report for both modes: `0.48.0.check` with `files[]` (one entry per document) and the project-wide diagnostics when the whole project ran; define the shape once in the spec and its schema |
| `compile` | `compile <FILE>` to stdout / `-o FILE`; `compile --all <DIR>` or `--all --project <DIR>` with `-o DIR` | `compile <FILE>` as today; `compile` with no document operand compiles the whole discovered project into `-o <DIR>` (required) plus `project.index.json`. `--all` is removed |
| `compile-stream` | `compile-stream <FILE>`: body text from stdin against the prefix, NDJSON stream out | `compile --stream <FILE>`: same input and stream (unwrapped, as before; `lute schema compile` lists it as a `stream` output selected by `--stream`). `--stream` with `-o`, `--locales`, `--json`, `--deny*` or without a document is `E-CLI-USAGE` naming the conflict. The command `compile-stream` is removed |
| all project commands | project as `DIR` operand (`check-project`, `impact`, `constraints`, `patch`, `doctor`, `play`, `test`, `loc export`, `loc report`, `beats`, `calendar`, `catalog refresh`), `--dir` (`new`), both operand and `--project` (`test`, `catalog refresh`) | `--project <DIR>` only, upward discovery (grammar §2); `catalog refresh`'s second directory, if it is not the project, gets a named option — record which |
| file commands | `--project` default = none (`check`, `compile`, `compile-stream`, `context`, `trace`, `expr`) | default = discovery from the file operand's directory (cwd for `expr`); a lone document outside any project behaves as today. Note the behaviour change in CHANGELOG |
| `impact` | `DIR TARGET` | `--project`, `--node <NODE>` |
| `context` | `--target <NODEKEY>`, `--run <FILE>`, `--max-items <MAX_ITEMS>` | `--node <NODE>`, `--script <FILE>` (repeatable) / `--all-scripts`, `--max-items <N>` |
| `scenario reach` / `envelope` / `knowledge` | `[NODE_ID]` / `NODE_ID` / `--for <NODE>`; no `--json` | `--node <NODE>`; `--json`; `--format` keeps only non-JSON formats; project via `--project` |
| `constraints` | `--run` (flag) | `--all-scripts`; `--script <FILE>` to select |
| `play` | `--explain <ATOM>`, `--dump-conditions <FILE>` | `--derivation <ATOM>`, `--conditions-output <FILE>` |
| `run` | `EXECUTION-IR`, `--occasion <OCCASION>`, `--dump-conditions <FILE>` | `<FILE>`, `--occasion <OCCASION>[@<TARGET>]` (same value grammar as `trace`), `--conditions-output <FILE>` |
| `trace` | `--choose <ID>=<CHOICEID>[,…]`, `--accept <QUESTID>` | `--choice <BRANCH>=<CHOICE>[,…]`, `--accepted-quest <QUEST>`; project discovery as above |
| `calendar` | `--occasion <OCCASION>[@AXIS[=VALUE],…]`, `--facts <RELATION>`, `--csv` | `@` means only target (grammar §1): move per-occasion axis variation to a spelling that does not use `@` (design it with `--axis`, record it); `--relation <RELATION>`; `--format csv` |
| `compile`, `loc export`, `loc import` | `--out <FILE>` | `-o, --output <PATH>` (`compile --all`: a directory) |
| `compile` | `--locales <FILE>` | name agrees with arity (grammar §4): if it takes one file, a singular noun naming it; record the choice |
| `new` | `KIND NAME`, `--dir <PROJECT>` | subcommand per kind (`new scene <NAME>`, …), options only where the kind uses them (`--occasion`/`--target`/`--start` on `scene`), `--project` |
| `fix`, `tag` | no `--check` | `--check` (grammar §1: every canonical rewriter verifies without writing) |
| `tag` | `--force` renumbers every line `code`, rewriting published codes (breaks the `lineId` / `voiceKey` join) | a named mode `--renumber` (grammar §1.2): by default it prints the renumbering it would apply and writes nothing; `--commit` applies it; still refused under `codesLocked:`. `--force` is removed |
| no `--json` | `compile-stream`, `tag`, `fix`, `fmt`, `catalog refresh`, `init`, `new`, `loc import`, `scenario *` | `--json` with the 0.43 envelope (`schema` exempt) |
| shared groups | `--providers`, `--permission-profile`, `--deny`, `--deny-warnings` on some commands only | grammar §6 groups on every command they apply to (e.g. `--providers` on `play`, `run`, `expr`, `beats`, `calendar`, `lint` where they resolve a project; `--deny*` on `test`, `play`) |
| value names | `PATHS`, `PATH`, `EXECUTION-IR`, `NODEKEY`, `NODE_ID`, `MAX_ITEMS`, `CHOICEID`, `QUESTID` | grammar §5 vocabulary |

Anything the audit missed follows the grammar; record each extra rename here.

## Migration (same change, D6)

- Every command line in docs (EN + KO website, handbook, runtime docs, READMEs, `llms*.txt`),
  CI workflows, `scripts/*`, conformance harnesses, examples, `package.json` scripts,
  play/test YAML comments and the `lute context` / ai-harness guidance.
- `lute schema` output and its tests; shell completions if generated.
- Command names inside diagnostics, help text and Rust doc comments (e.g. "suppressed by
  default in `check-project`", "the output of `lute compile --all`"), and the generated TS whose
  comments come from schema descriptions (`packages/runtime/src/generated/*`,
  `packages/player/src/bindings/schema.ts`): fix the source and regenerate.
- Removed commands (`check-project`, `compile-stream`) answer with `E-CLI-USAGE` naming the
  replacement (grammar §7), like removed options.
- CHANGELOG `[0.48.0]` Breaking: the full table above + the discovery behaviour change; the
  removed-spelling errors make old invocations self-explaining for one minor.
- Other repositories (lute-town, Brinewake) are not edited; their script updates are a
  migration note.

## Enforcement

The grammar §6 test lands in the same release and runs in CI. Its vocabulary file is the single
list of option names; adding an option means adding a row.

## Orchestrator choices (conservative, 2026-10-19)

Judgement calls made while writing the 0.48.0 spec
([`docs/proposals/scenario-dsl/0.48.0.md`](../../proposals/scenario-dsl/0.48.0.md)); each picks the
narrower or the already-established option, or the literal reading of the grammar.

| Topic | Choice | Why |
|---|---|---|
| `--project DIR` as walk root | For every command 0.47.2 gave a directory operand, `--project DIR` (explicit or discovered) means exactly what the operand meant: the walk root, each document/script resolving against its nearest project at or below it (nested projects keep their documents; a directory without a manifest is a workspace). Old `cmd DIR` ≡ new `cmd --project DIR`. | No behaviour is lost: `docs/examples` (itself a project) holds the fourteen game projects and CI runs `check-project docs/examples` / `test docs/examples`, which must keep resolving each game against its own manifest. Discovery only ever finds a directory with a manifest. |
| Discovered = explicit | When `--project` is absent the discovered directory is used exactly as if it had been passed: `compile <FILE>` and `trace <FILE>` gate on the reconciled project verdict and trace uses the single-root producer set, as an explicit `--project` did in 0.47.2. The stderr discovery note stays. | Grammar §2: the default *is* the nearest ancestor; one command line, one meaning. This is the CHANGELOG behaviour change the mapping asks for (0.47.2 already discovered for `check`/`compile`/`compile-stream`/`context`/`trace`, but gated only on an explicit option). |
| No project found | Directory-operand commands (whole-project `check`, `compile` without a document, `impact`, `constraints`, `patch`, `play`, `test`, `loc export`/`report`, `beats`, `calendar`, `scenario*`, `lore`, `refs`, `expr`) fail with `E-CLI-USAGE` naming `--project`. `check <FILE>`, `compile <FILE>`, `context`, `trace`, `lint`, `fmt`, `fix`, `tag`, `new` (self-contained document, as before) and `doctor` (reports the ✗) keep running. | Grammar §2. |
| Project option structs | Three single-option `Args` structs (`--project`, `--providers`, `--permission-profile`), each flattened only where the option can change the command's result (shown by a test); the expected sets are in spec §2.2, the outcome in `docs/design/cli-commands.tsv`. Gate group (`--deny*`) on every command that exits on diagnostics: `check`, `compile`, `lint`, `trace`, `expr`, `play`, `test`, `calendar`. Recorded as amendments to grammar §6 (one group → three structs; `loc export` exempt from `--json`). | Grammar §6 "every command that resolves a project" without adding options that change nothing (ReviewSpec048: `lore` and `scenario` evaluate no profile ceiling). |
| `lore` / `refs` / `scenario` / `diff` / `run` | `lore`, `refs` and `scenario` take `--project` (they walked a directory operand like `check-project`). `diff <BEFORE> <AFTER>` keeps its two same-kind operands (grammar §3). `run` resolves no project and gets no project group. | Audit gaps; "anything the audit missed follows the grammar". |
| `catalog refresh` second directory | The snapshot directory becomes `--providers <DIR>` (the grammar's name for provider snapshots), default the project's `catalogDir` (default `catalog/`); `--project` (or discovery) names the project whose `capabilitySnapshot` stamps them. Neither found → `E-CLI-USAGE` naming `--providers`. | Mapping: "gets a named option — record which". |
| `compile --locales` | `--locale-bundle <FILE>` (one bundle file, as `loc import` names it). | Grammar §4: singular noun naming the one value. |
| `--occasion` value name | `<OCCASION>` on every command; `trace` and `run` accept the `@<TARGET>` suffix (documented in their help). | One value name per option (grammar §6 test); `@` keeps its one meaning. |
| Calendar per-occasion axes | `--occasion-axes <OCCASION>=<AXES>` (repeatable): `<AXES>` is the 0.47.2 list after `@` unchanged (`run.day,run.slot=night`); it also selects the occasion, as `O@…` did. `--occasion O@…` in `calendar` is `E-CLI-USAGE` naming it. | `@` means only "for this target"; plural name = one collection value (grammar §4); same inner grammar. |
| `--script` arity | Arity = `takesValue` and whether the value is optional. `--script <FILE>` takes one value everywhere; it is repeatable where a command uses several (`context`, `constraints`) and single in `play`/`calendar`; in `context`/`constraints` a directory selects every script under it, as 0.47.2 `context --run` did. | Multiple scripts have no meaning for one play; no 0.47.2 selection is lost. |
| `loc export --format` | JSON stays the default export (an artifact, not a report); `--format csv` selects CSV; `--format json` is `E-CLI-USAGE` ("JSON is the default; omit `--format`"). `loc export` gets no `--json` (artifact writer, exempt like `schema`). | Grammar §1 "`--format` never `json`" without changing the default file. |
| `loc import --json` | Requires `-o, --output` (the bundle is the artifact; stdout carries the report). | One stdout document. |
| Path operands | `fmt`, `fix`, `tag` take `[<PATH>]…` (default `.`); `init [<DIR>]` (default `.`, refusing when any file it would write exists); `test [<PATH>]…` selects scripts (none = the project); `doctor` takes no operand. | Grammar §1.3, §2, §3. `init .` must never overwrite an existing repository's files (ReviewSpec048). `test`'s file operand is used in tests and READMEs. |
| `new` | Subcommands `new scene <NAME>`, `new quest <NAME>`, `new lore <NAME>`, `new schema <NAME>`; `--occasion`/`--target` on `scene`, `--start` on `quest`; `--project` (discovery from the cwd: running inside a project's subfolder now writes into that project). | Mapping; the 0.47.2 "not the project root" refusal applies only to an explicit `--project` that is not a root. |
| `--on`, trace `--target` | The hidden `--on` refusals (since 0.28) and trace's hidden `--target` refusal are removed: plain unknown-option errors. | Grammar §7: one minor, then the plain error. |
| Placeholders | §5 gains `<ID>`, `<STEP>`, `<KIND>`, `<RELATION>`, `<QUEST>`, `<COMMAND>`, `<BEFORE>`, `<AFTER>`, `<AXES>` and the composites `<AXIS>=<VALUES>`, `<DIRECTIVE>.<ATTR>`, `<OCCASION>=<AXES>`. | Grammar §5: "a new placeholder is added here first". |
| Report versions | New shapes: `0.48.0.check` (both modes), `0.48.0.tag`, `0.48.0.fix`, `0.48.0.fmt`, `0.48.0.catalog-refresh`, `0.48.0.init`, `0.48.0.new`, `0.48.0.loc-import`. `scenario*` keep their `0.43.0.*` versions (payload unchanged, flag now `--json`); `schema` moves to `0.48.0.schema` because option objects gain `valueOptional: true` for an optional value (R3: the §6 arity rule needs it; same precedent as 0.47.0's `inputs`); `0.43.0.check-project` is retired. | 0.43 §3.3: a version names a payload shape. |
| `check` report fields | `files[]` entries as 0.47.2 `check-project` (`path`, `ok`, `diagnostics`, `resolved`); `project_diagnostics` present only in whole-project mode (snake_case kept). | Removed-command telemetry | `check-project` / `compile-stream` are hidden stubs only long enough to print `E-CLI-USAGE` naming the replacement; the envelope `command` is `null` and telemetry records no command id. | They are not commands any more. |
