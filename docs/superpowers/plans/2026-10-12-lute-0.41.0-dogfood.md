# Lute 0.41.0 — dogfood fixes: implementation plan

- **Spec:** `docs/proposals/scenario-dsl/0.41.0.md` (issue map §2, spec decisions Appendix A, anchors Appendix B).
- **Decisions:** `docs/superpowers/notes/2026-10-12-lute-0.41-dogfood-decisions.md` (owner-approved).
- **Base:** `feat/0.41` at `1b755252` (0.40.0 + unreleased 0.40.1). 0.40.1 is never released: its
  normative text lives in spec §4.3/§5.1; `docs/proposals/scenario-dsl/0.40.1.md` is deleted and the
  CHANGELOG `[Unreleased]` entry folded into `[0.41.0]` in slice Z.
- **Cutover:** clean (ADR D6). Every caller a slice breaks is fixed in that slice.

## Working rules (every slice)

- Own worktree `/tmp/wt-<slice>`, own `CARGO_TARGET_DIR=/tmp/wt-<slice>-target`; the orchestrator merges.
  `LUTE=$CARGO_TARGET_DIR/debug/lute` below.
- **One Rust owner at a time:** R1 → R2 → R3 → R4 → R5 → C are strictly sequential; each starts from
  the merged previous one.
- TS package slices run only after the Rust contract they consume is final (after C and G1), and in
  parallel with each other only on disjoint packages.
- Generated files change only through their generators, each in one owner slice:
  - Rust-generated JSON schemas (`schemas/lute-events-*`, `lute-snapshot-*`, `lute-player-bindings-*`,
    the index `$defs` of `schemas/lute-ir-*`): `cargo run -q -p lute-runtime --features json-schema --bin
    lute-contract-schema`, by the Rust slice that changes the types (R2, R4, R5).
  - **All generated TypeScript** (`packages/runtime/src/generated/Contract.ts`,
    `packages/runtime/src/generated/Ir.ts`, `packages/player/src/bindings/schema.ts`): only slice **G1**,
    with `cd packages/runtime && bun run contract:gen` (`bun scripts/contract-codegen.ts`, generation table
    at `packages/runtime/scripts/contract-codegen.ts:7-25`), once, after the Rust schemas are final; Z
    reruns it after the schema renames. R2/R4/R5 never touch these files.
  - `LUTE_BLESS_DIAGNOSTICS=1` for the diagnostics reference pages; `conformance/regenerate.sh` for
    frozen conformance outputs (slice C only, plus Z's stamp-only rerun); `cargo insta` for
    `crates/lute-compile/tests/snapshots/*`.
- **Allowed red between R2 and G1** (TS drift is not checked by any Rust test — the offline CI job
  diffs only `schemas/`, `.github/workflows/test.yml:142-143`): `cd packages/runtime && bun run
  contract:check` (diffs `src/generated` and `../player/src/bindings/schema.ts`; CI job `runtime-ts`),
  and the `packages/runtime` / `packages/player` / `packages/player-web` typecheck and test suites
  (`packages/runtime/test/Contract.test.ts` decodes the session JSONL with the generated `Contract`).
  Rust slices do not run them; G1 turns them green for runtime, T1–T3 for their packages.
- Never `cargo clean`, never `--release` (so no `wasm:build:release`, no bench build), never
  `cargo doc` (the public-API check is the orchestrator's final gate), never `include!`.
- Each slice updates the docs of the surface it changes (EN + KO website mirrors) and ends with a
  **reviewer pass** (agent `reviewer`) against its spec sections before merge; findings are fixed in the
  slice.
