## Working rules

- One Rust owner at a time: R1 → R2 → R3. TS generation only in G1 (`cd packages/runtime && bun run
  contract:gen`), after R1's IR schema and R2's bindings schema are final; Z reruns it after the schema
  rename. Never hand-edit generated output (`packages/runtime/src/generated/*`,
  `packages/player/src/bindings/schema.ts`, generated parts of `schemas/*`).
- Every slice ends with a reviewer-agent pass against its spec sections; findings are fixed before the
  next dependent slice starts.
- Every fix gets a regression test that fails on the base (`fefaeb2b`); the slice states how that was
  shown (run against `~/lute-047-snap/lute-0.46.0`, or with the fix reverted).
- **Testing rule (spec §6):** player / player-web behaviour is tested against real runtime output (a
  compiled fixture through `@lute-lang/runtime`, or the player-web browser/e2e suites over a compiled
  bundle and the wasm runtime). Tests that mock runtime views/records for a touched feature are replaced.
- Every changed user surface gets EN and KO docs in the same slice (website pages under
  `packages/website/src/content/docs/` and `…/ko/`, plus repo docs under `docs/`).
  `packages/website/public/llms-full.txt` is edited only in slice **K**.
- `cargo fmt --all` before each Rust commit. `cargo clean` only by the orchestrator between slices.
  Never `--release`, never `cargo doc`, never `include!`.
- Allowed red between R1/R2 and G1: `bun run contract:check` and TS suites that decode the IR/bindings.
- Each slice commits its own work (`feat(0.47): <slice> - …`); the worktree is clean at handoff.

## Expected CLI snapshot deltas

Every difference against `~/lute-047-snap/base` must fall in one of these classes; anything else is a defect.

| Class | Source |
|---|---|
| Stamps | Z (normalized away). |
| New `explain` outputs / code listings: `W-L10N-STALE`, `W-BINDINGS-VERSION-STALE`, `E-BINDINGS-VERSION`, `E-PATCH-FORMAT`; changed `explain E-CHOICE-DUP` | R1, R2, R3. |
| `promptLineId` in compiled output of corpus documents with a prompted branch/hub; `contentLang` in project indexes of corpus projects with `defaults.contentLang` | R1. |
| New `session play --events` commands if T1 adds `conformance/session` cases | T1. |
| Corpus changes from K (`docs/examples/quayside`) | K. |

`loc export` rows, `lute schema` and bindings-version warnings are not run by `scripts/cli-snapshot.py`;
they are covered by R1/R2/R3 tests.
