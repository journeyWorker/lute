## Working rules

- One Rust owner at a time: R1 → R2. TS generation only in G1 (`cd packages/runtime && bun run
  contract:gen`), after R1's bindings schema is final; Z reruns it after the schema rename. Never
  hand-edit generated output (`packages/runtime/src/generated/*`, `packages/player/src/bindings/schema.ts`,
  `schemas/*` are written by their generators).
- Every slice ends with a reviewer-agent pass against its spec sections; findings are fixed before the
  next dependent slice starts.
- Every fix gets a regression test that fails on the base (`60a13293`); the slice states how that was
  shown (test run against `~/lute-046-snap/lute-0.45.0`, or with the fix reverted).
- Every changed user surface gets EN and KO docs in the same slice (website pages under
  `packages/website/src/content/docs/` and `…/ko/`, plus repo docs under `docs/`).
  `packages/website/public/llms-full.txt` is edited only in slice **K**.
- `cargo fmt --all` before each Rust commit. `cargo clean` only by the orchestrator between slices.
  Never `--release`, never `cargo doc`, never `include!`.
- Allowed red between R1 and G1: `bun run contract:check` and the TS suites that decode bindings.
- Each slice commits its own work (`feat(0.46): <slice> - …`); the worktree is clean at handoff.
