## Working rules

- **One Rust owner at a time**, in the main checkout, in the order below. TS and
  docs slices run in worktrees, and the orchestrator merges them.
- **Coding rules.** Every Rust slice reads `docs/design/rust-coding-rules.md`
  first. New types (`JumpMax`, `LoopRegion`, `LoopTable`, `RaiseDecl`,
  `RaiseTarget`, `RaisedBy`, `RaiseRecord`, `LocalizedText`, `PairSpec`,
  `PairScope`, `PairFault`, the lint rule-body enum, the `DirectiveTag` code
  owner) are newtypes or enums, not strings. Error types are typed, and no
  `unwrap()` is added outside tests. No `pub(super)`. A module with children is
  `foo/mod.rs`. No HIR, no Fold, no synthesized AST nodes: loops and raises are
  tables the walks consult (spec §2).
- **Reviewer pass per slice**, against its spec sections, before the next
  dependent slice starts. The reviewer reads the whole diff and the slice's
  delta list. Findings are fixed first.
- **Regression test per change**, failing on the base (`$SNAP/lute-0.50.0`, or
  the change reverted, or — for a fixed-point test — the iteration disabled).
  The slice records how it showed the failure.
- **Snapshot compare after every slice:**
  `python3 scripts/cli-snapshot.py target/debug/lute "$SNAP/<slice>" --compare "$SNAP/base" --strict`,
  and from S1 on also with `--capability-hash` (spec §13 class 4). Every
  changed, added or removed output is listed in `$SNAP/<slice>/deltas.txt` with
  its spec §13 class. An unclassified delta is a defect in that slice.
- `cargo fmt --all` before each Rust commit. **`cargo clean` only by the
  orchestrator, between slices.** **Never** `--release`, `cargo doc` or
  `include!`. No `#[allow]` (use `#[expect(…, reason)]`), no new `catch_unwind`,
  no `unsafe`.
- Never hand-edit generated output. Bless registry pages with
  `LUTE_BLESS_DIAGNOSTICS=1` and review the diff. Regenerate contracts with
  `lute-contract-schema` and `bun run contract:gen`. Re-bless insta snapshots
  (`cargo insta`) only for a classified delta, and review each.
- Historical records are never rewritten (spec §9).
- **Out-of-scope bugs:** `gh issue create --label bug` with evidence,
  immediately, plus a line in the log. Do not fix them here. Known ones: spec
  §14 (bootstrap step 8 files them).
- **Commit per slice** (`feat(0.51): <slice> - …`; `docs(0.51):`,
  `test(0.51):`) and per milestone. Log after each. The tree is clean at
  handoff.
- **Budget rule.** If a slice cannot reach a green RG in its session:
  - commit the work as one WIP commit on `feat/0.51-<slice>-wip`, and leave
    `feat/0.51` unchanged;
  - log what is done, what fails (exact errors) and the next step.

  The next session resumes from the WIP branch. Never land a red slice on
  `feat/0.51`.

## Order and rationale

```text
bootstrap ─ S1 ─ S2 ─ S3 ─ S4 ─ S5 ─ S6 ─ S7 ─ S8 ─┬─ merge ─ K ─ snapshot classification ─ Z ─ final gate ─ release
                       St (player, after S5 and S7) ┤
      D1 (docs from spec; example + transcripts after S8) ┘
```

- **#159 first (S1–S3).** It is the largest and riskiest item: it changes every
  flow analysis, which every later slice's tests run under, and it moves
  `capabilitySnapshot` once (S1), which every later compare normalizes.
- **S1 before S2.** S2's walks consult S1's `LoopTable`.
- **S2 before S3.** S2 owns the shared head-state function and the compile
  stage walk; S3's runtime and conformance fixture run on the compiled loops.
- **S4 before S5.** S5's graph, IR and records carry what S4's manifest and
  checks resolve. #170 needs the 0.50 reward `effects:` (in the base).
- **S6 before S7.** S7's tooling and runtime read S6's `localized` IR.
- **S8 is independent** (lint is not captured by the snapshot). It is last of
  Rust only because of the one Rust owner.
- **St** (TypeScript) merges after S5 and S7, which define the record keys it
  reads.
