# Lute 0.36.1 — performance and code-quality pass

- **Inputs:** `docs/design/quality-audit-0.36/{performance,architecture,idiomatic-rust}.md`
  (audits of the 0.36.0 tree).
- **Contract:** no behavior change. Every observable stays byte-identical:
  CLI stdout/stderr/exit codes, JSON shapes, diagnostics, IR, insta
  snapshots, impact/context goldens, `conformance/**` artifacts and
  transcripts, `conformance/edit-tasks/REPORT.json`, the CEL-equivalence
  harness, `lute test docs/examples`. A slice that needs to touch a golden has
  found a behavior change and stops.
- **Version:** 0.36.1 on all axes (language and IR are content no-ops; the
  toolchain earns it), per `docs/versioning.md`.
- **Proof of the perf work:** `lute-bench` A/B against `v0.36.0`
  (`scripts/bench-ab.py`, 7 samples) — each perf slice reports per-tier/phase
  ratios; no cell may regress past 1.10.

## Build hygiene

`export CARGO_PROFILE_DEV_DEBUG=line-tables-only CARGO_INCREMENTAL=0`; scoped
`-p` runs while slices are in flight; `cargo nextest run --workspace` only at a
wave gate; never `cargo clean` mid-wave. Disk is limited: no extra target dirs
except the one A/B baseline build.

## Waves (file ownership disjoint within a wave)

### Wave 1

| Slice | Owns | Change |
|---|---|---|
| **P1 project build** | `crates/lute-model/src/{project,reconcile,input}.rs`, `crates/lute-check/src/defassign*.rs`, `crates/lute-cel/src/fill.rs` (+ a parse cache module) | Profile `ProjectModel::build_impl`; stop re-parsing the same CEL slot text across passes (`defassign::uses_of → parse_uses → parse_slot`) and cloning `Document`s in reconcile; one parse per slot per build. |
| **P2 runtime** | `crates/lute-trace/**` | Profile `lute play`/`lute test` playback (`observe_latches`/`eval_guard`, `Store::derive`); remove repeated work (per-step guard re-parse, closure recompute, clones). |
| **P3 test runner** | `crates/lute-cli/src/{testcmd.rs,play/**}` | `lute test` assembles each project once per run (not per test/play) and reuses the `ExecProject`; split `testcmd.rs` (3.7k lines) into discovery / runner / coverage / render modules. |
| **Q1 typed diff/patch** | `crates/lute-model/src/{diff,patch,rename}.rs`, `crates/lute-cli/src/{cmd_diff,cmd_patch}.rs` | Replace `serde_json::Value` as the internal semantic model with typed values (serialize to the same JSON); split `patch.rs` into decode / stage / apply / preserve; error enums instead of `String`; no >120-col one-liners. |
| **Q2 CLI edges** | `crates/lute-cli/src/{output.rs,project/**,cmd_check.rs,cmd_check_project.rs,cmd_compile.rs,cmd_context.rs,beats_cmd.rs,runner.rs}` | One output envelope/diagnostic-report serializer; one project-discovery + canonical-path helper used by every command; typed condition-dump records in `runner.rs`. |
| **Q3 test support** | `crates/lute-cli/tests/**` (except files other slices name), new `crates/lute-cli/tests/support/` | Shared `TempProject` / `run_cli` / JSON helpers; split `check_project.rs` (3.1k lines) by contract. Test-only. |
| **Q4 syntax** | `crates/lute-syntax/**` | Split `parser.rs` (3k lines): framing/frontmatter, block parsing, line + interpolation; no grammar change. |

### Wave 2

| Slice | Owns | Change |
|---|---|---|
| **K1 CEL visitor** | `crates/lute-cel/**` (visitor API), CEL walkers in `crates/lute-check/src/{cel_paths,cel_resolve,cel_types,chapters,connectivity,decide,deps,gates,check/fact_check,fact_must,check/component_body,check/use_site}.rs` | One `ExprVisitor` with exhaustive node coverage; migrate the ~15 bespoke recursions to it, keeping each pass's stop rules as visitor policy. |

### Wave 3

| Slice | Owns | Change |
|---|---|---|
| **K3 frontmatter once** | `crates/lute-check/src/meta.rs` + every `serde_yaml::from_str(&doc.meta.raw_yaml)` call site | Parse frontmatter once into a typed snapshot carried on the document; callers read it. |

### Wave 4 (mechanical splits, parallel)

`meta.rs`, `beats.rs`, `cast.rs`, `cel_resolve.rs`, `connectivity.rs` each
split by responsibility into submodules (one agent per file), no logic edits.

## Gates

After each wave: reviewer pass per slice (equivalence + idiom), full
`cargo nextest run --workspace`, doc tests, conformance harness, `lute test
docs/examples`, all games `check-project --deny-warnings`, `fmt --check`, both
doc scripts, and (waves with perf slices) the A/B report vs `v0.36.0`.

## Deferred (recorded, not in 0.36.1)

- `lute-model` is an application service above checker/compiler (audit
  architecture #2): splitting a `lute-project` loader crate changes every
  crate's dependency graph; it gets its own design note first.
- Test taxonomy consolidation across insta / conformance / CLI contract tests
  (architecture #25).

## Outcome

Implemented the toolchain-only quality release: one project assembly per root
in `lute test`, the parsed pre-splice document reused by project compile, a
CEL path-use parse cache in definite-assignment, a Datalog join precheck,
typed diff/patch and manifest/schema/expand errors, an exhaustive CEL walk for
context-free passes, frontmatter parsed once into `TypedMeta` for folded-aware
passes, real module splits (parser, testcmd, beats, cast, meta, cel_resolve,
connectivity — explicit re-exports; `lute_check`'s public item list equals
0.36.0's plus `ExpandError`/`FactArgError`), shared CLI test support, and
regression tests. A revision-scoped CEL result cache was tried and removed: it
was slower on an idle machine and had already produced one stale-context bug.
Bench A/B on an idle machine was neutral (every cell 0.97–1.01 versus 0.36.0);
the measurable gain is `lute test` monster-league, 17.9 s → 15.0 s (release).

Deferred, in priority order for the next perf/quality pass:

1. A `ProjectDoc { path, doc, meta: &TypedMeta }` view for the ~30 lute-check
   project passes that take `&[(PathBuf, Document)]`: removes both the
   reconcile `plain_group` Document clones and the remaining frontmatter
   re-parses (connectivity scene identity / bundle id / scene-after /
   scene-frontmatter string; chapters apply and priority; lib desugar
   entrance; lore document series; project-check scene slot and quest hint;
   state declarations; `codes_locked` in tag).
2. Playback: `Session::occasion` / `advance_quests` is ~92% of a monster-league
   play profile (quest latch guards re-evaluated every occasion) — needs a
   read-set-based invalidation design, not a revision-wide memo.
3. `cel_types::check_types` deliberately skips Map/Struct/Comprehension
   children (preserved for byte identity); add a test deciding whether that is
   a checker gap.
4. Files still over 2k lines: `lute-trace/src/trace.rs`,
   `lute-check/src/{reachability,project_check}.rs`, `lute-lsp/src/backend.rs`,
   `lute-cli/src/play/calendar.rs`, `lute-cli/src/codes.rs`,
   `lute-manifest/src/schema.rs`.
5. The `lute-model` application-service crate split (needs a design note).
