# Lute 0.34.0 — project semantic model: implementation plan

- **Spec:** `docs/proposals/scenario-dsl/0.34.0.md`
- **Direction:** `docs/design/architecture-direction.md` D2, D3, D6, D7, D9, D10, §5 phase 3
- **Base:** 0.33.0. Clean cutover: no legacy loader, compatibility alias, or dual project path.
- **Deliverables:** `crates/lute-model`, migrated commands, semantic graph/impact/constraints/evidence, handbook updates, fixtures, and all 0.34.0 stamps.

## Slices and order

```
S1 model crate + migration ───────────────┬─ S3 graph + impact ──┐
                                         ├─ S4 constraints ─────┼─ S5 docs/handbook/stamps/fixtures/release
S2 evidence fields/rendering ─────────────┘                       │
```

- **Wave 1 (parallel):** S1 model and S2a evidence core start after spec
  review. S1 owns the new model and loader migration; S2a owns the
  `lute-core-span` diagnostic/evidence contract and every analysis producer.
  Their shared boundary is the published evidence/report interface, not
  concurrent edits to command files.
- **Wave 2 (parallel, after S1 + S2a):** S2b migrates evidence renderers;
  S3 implements graph/impact and S4 implements constraints. S3/S4 code only
  against S1's published model API.
- **Wave 3:** S5 owns docs, handbook, website EN/KO, llms mirror, changelog,
  version stamps, conformance re-record, and test migration after S2b–S4.
- Every slice has an acceptance run at its end; do not run workspace-wide
  builds or formatters mid-flight.

## S1 — `lute-model` crate and loader migration

**Files owned:**

- new `crates/lute-model/Cargo.toml`, `crates/lute-model/src/lib.rs`, and
  model modules (`input.rs`, `cache.rs`, `project.rs`);
- workspace `Cargo.toml` and dependency manifests;
- move/adapt code from `crates/lute-cli/src/input.rs`, `input_cache.rs`, and
  `project/mod.rs`;
- loading adapters only in command call sites: `cmd_check.rs`,
  `cmd_check_project.rs`, `cmd_context.rs`, `cmd_scenario/` loading entry,
  `beats_cmd.rs`, `play/project.rs`, `play/mod.rs`, `play/calendar.rs`,
  `testcmd.rs`, single-file compile/trace wiring, trace project assembly, and
  `lute-lsp/src/backend.rs` author assembly. S1 does not own evidence
  renderers or diagnostic model files.

**Change:**

1. Add workspace member `lute-model`, depending on `lute-manifest`,
   `lute-check`, and `lute-compile`; `lute-lsp` and `lute-cli` depend on it.
   No reverse edge is permitted.
2. Publish this interface for S3/S4:
   `ProjectModel::build(root: &Path, opts: &ModelOptions) ->
   Result<ProjectModel, ModelError>`, `ModelOptions { providers,
   permission_profile, mode: Mode, compile: bool }`, and
   `ProjectModel::roots_under(dir, opts) -> Vec<ProjectModel>`.
   Accessors are `root()`, `manifest()`, `documents() ->
   &[ModelDocument]`, `project_diagnostics()`, `index() ->
   Option<&ProjectIndex>`, and `reconciled()`. `ModelDocument` exposes
   `path`, `input: CheckInput`, `doc: Document`, `folded: FoldedEnv`,
   `check: CheckResult`, `artifact: Option<ExecutionIr>`, and
   `source_map: Option<SourceMap>`.
3. Move `InputCache` and assembly into the crate; preserve defaults,
   providers, capability snapshot, schema imports, components, identity, and
   diagnostics. Expose mode so CLI uses its existing mode and LSP uses
   `Mode::Author`.
4. Fold/check every document once, reconcile once, compile clean
   non-component documents once with SourceMaps, and retain one index.
   Migrate loading call sites for check, check-project, context, scenario,
   beats, calendar, play, test, trace, compile, trace project assembly, and
   LSP. Keep `run` artifact-only; delete obsolete CLI loaders after cutover.

**Acceptance:**

- A walk containing nested manifests returns separate models, while a file
  command resolves the nearest manifest.
- The model accessors expose the documented fields and all named commands
  observe one model/index identity and reconciliation diagnostics.
- `run` executes an artifact with no source project present.
- A `cargo tree`-style check proves workspace membership and that model edges
  are exactly `{lute-manifest,lute-check,lute-compile}` with no reverse deps;
  `lute-lsp` and CLI depend on model.
- Scoped acceptance: `cargo test -p lute-model -p lute-cli -p lute-lsp`.

## S2a — evidence core (Wave 1, parallel with S1)

**Files owned:**

- `crates/lute-core-span/src/lib.rs` Diagnostic model, custom serializer,
  `RelatedDiagnostic`, and human renderer suffix;
- every analysis diagnostic producer in `crates/lute-check/src/**`, plus
  `crates/lute-trace/src/report.rs` evidence fields, `crates/lute-cli/src/codes.rs`
  bounded-message wording, and LSP conversion of the new fields.

**Change:**

1. Add optional `evidence` and `scope` to the core Diagnostic and serialize
   them when present; leave parse/type/declaration diagnostics absent.
2. Audit every constructor, clone, serializer, related diagnostic, CLI/LSP
   conversion, and analysis producer. Set levels per the spec mapping,
   including bounded clock diagnostics and trace/report fields.
3. Add an invariant test that every analysis code in the registry carries
   evidence and every parse/type/declaration code does not.

**Acceptance:** focused core, producer, serializer, and LSP tests cover
mapping rows, omission/presence, suffixes, related diagnostics, and bounded
wording without “no path exists”.

## S2b — evidence renderers (Wave 2, after S1 + S2a)

**Files owned:** `beats_cmd.rs`, `cmd_scenario/**` output,
`scenario_fmt.rs`, `play/calendar.rs` output, `play/outcome.rs`, `play_expect.rs`,
and `testcmd.rs` output fields. S2b does not edit S1 loading adapters.

**Change:** add evidence to every trace/play/test/calendar/scenario/beats
verdict/result, mark calendar aggregates bounded with axes/product scope, and
render suffixes only for bounded, heuristic, and unknown while preserving
stable scenario reach tokens.

**Acceptance:** calendar, trace unknown, scenario unknown, and witnessed
play/test outputs emit correct evidence/scope; proven results have no suffix.
Scoped acceptance: focused `cargo test -p lute-trace -p lute-cli` report tests.

## S3 — semantic graph and `impact` (Wave 2, after S1 + S2a; parallel with S4)

**Files owned:**

- `crates/lute-model/src/graph.rs`, `impact.rs`, `identity.rs`, and
  `source_join.rs`;
- adapters in `crates/lute-check/src/{cel_paths,defassign,fact_edges,
  fact_must,cast,connectivity,beats}.rs` and component/def analysis modules;
- `crates/lute-cli/src/cmd_impact.rs`, CLI dispatch/help, human/JSON formatters;
- SourceMap/index adapters in `crates/lute-compile/src/{source_map,index}.rs`.

**Change:**

1. Define typed node keys and edge records with source spans and reasons.
2. Build model-owned public adapters in `lute-check` for every folded/expanded
   AST state-path read/write, all fact query forms (including negation,
   aggregates, `validAt`), assert/retract pattern, reverse entry disclosure,
   def-use and component provenance, and reward declarations. Reuse
   `cel_paths` walking logic by making it public as needed; do not treat
   `defassign` must-write output as authored events. Preserve `fact_edges` for
   `scenario --facts`.
3. Add the compiler reward side table (owner/index/span), full Datalog
   least-fixpoint closure with bindings, and explicit engine boundaries.
4. Add reverse adjacency and finite visited-set traversal. Implement evidence
   ranking, tie breaks (fewest edges then lexicographic node keys), pattern
   unification, self-read exclusion, and deterministic output ordering from
   the spec. Add `cmd_impact` and CLI wiring.

**Acceptance:**

- Every target kind parses, rejects malformed keys deterministically, and
  returns stable ordering.
- A direct state path/fact guard is proven; parameterized overlap is heuristic;
  engine boundaries are unknown but still listed.
- A derived relation chain longer than four edges appears in full closure.
- SourceMap joins show exact line IDs and file:line locations, and rewards are
  owner/index nodes.
- Golden drowned-crown runs for both `fact:felled(regent)` and
  `fact:slew(regent)` list every Appendix A item, reason, and evidence level.
- Scoped acceptance: `cargo test -p lute-model -p lute-cli` focused impact tests
  plus a smoke invocation of both golden commands.

## S4 — constraints (Wave 2, after S1 + S2a; parallel with S3)

**Files owned:**

- manifest schema/types/load validation in `crates/lute-manifest/src/` and
  `schemas/`;
- `crates/lute-model/src/constraints.rs` and adapters to connectivity,
  clock-position, cast, and play/test witness data;
- `crates/lute-cli/src/cmd_constraints.rs`, dispatch, human/JSON report;
- `crates/lute-check/src/codes.rs` and diagnostic plumbing for declaration and
  violation codes.

**Change:**

1. Add typed `constraints` to the raw manifest schema, retaining YAML spans
   per declaration and field. Unknown key/kind, missing field, bad node ref,
   duplicate ID, or malformed severity emits `E-CONSTRAINT-DECL` at that
   field's span.
2. Implement `reachable`, `completable`, `speaksOnlyWhen`, and
   `noSingleSlotProgress`. `--run` executes every project `*.play.yaml` and
   `*.test.yaml`, indexes per-run witness records
   `{script path, quest id, observed -> complete transition}` from play
   outcomes/test quest-state traces, and no run means no witnesses.
3. Extract a public parameterized guard-implication decider from `cast.rs`
   for every speaker line including `{vo}`/`{os}`; keep presence assumptions
   only in the layered `W-CAST-ABSENT` adapter.
4. Refactor `clock_positions` to deterministic per-objective records
   (objective, quest, declared windows, candidate beats/spans, verdict).
   Project both legacy stranded/contention diagnostics and constraint results
   from those records; `quest:'*'` means every quest with required objectives
   and aggregates each quest by worst objective.
5. Surface violations in `check-project` with primary declaration YAML span and
   related causal spans ordered by file then byte offset, each with a short
   reason. Unknowns are info only; never emit `W-CONSTRAINT-UNKNOWN`.
   Implement `lute constraints <dir>` report of every verdict, evidence,
   scope, witness, and counterexample.

**Acceptance:**

- Malformed key/kind/field/severity, duplicate ID, and bad node reference
  produce `E-CONSTRAINT-DECL` at the retained manifest field span.
- Constraint tests assert unknown is info, no `W-CONSTRAINT-UNKNOWN` is
  emitted, bounded scope is present, primary diagnostics anchor at the
  manifest span, related spans are causal and deterministically ordered, and
  `--run` names a play/test witness for a completed quest.
- Reachability has proven holds/violated and unknown outcomes; completable
  proves unreachable/unsatisfiable violations and witnessed holds.
- Speaker constraints include `{vo}`/`{os}` lines and prove only what the
  parameterized decider proves. Slot constraints are bounded and scoped.
- Scoped acceptance: focused manifest/model/CLI constraint tests and a smoke
  `lute constraints` report.

## S5 — docs, handbook, stamps, fixtures, release

**Files owned:**

- `docs/handbook/` current-rules pages for project models, evidence,
  constraints, impact, and genre policy/contract;
- `docs/design/modules.md` status/cross-links and any architecture index;
- `docs/examples/games/drowned-crown/` fixtures/scripts and expected reports;
- `crates/lute-cli/tests/{cadence_027,check_project,kind_targets_026,overview,
  scenario,test_gate,templates_chapters_027}.rs`,
  `crates/lute-check/tests/harness_022.rs` (the complete human/JSON assertion
  migration inventory), plus conformance metadata/fixtures, schemas and JSON
  snapshots; `CHANGELOG.md` (if present) and release notes;
- all language/IR/toolchain version constants, Cargo/npm/editor stamps, and
  `docs/versioning.md` references found by the release inventory.

**Change:**

1. Add the normative spec and this plan links to the design index.
2. Rewrite handbook guidance so genre policy is not an execution guarantee;
   document host-advances-time and model/query evidence semantics.
3. Add golden impact and constraints fixtures, including nested roots and LSP
   author assembly. Re-record expected 0.34 outputs only after code is final.
4. Move every axis to `0.34.0`; update schema and command JSON contracts.
   Classify the cutover as source/toolchain/analysis breaking, with no legacy
   loader or output mode.
5. Run docs/snippet checks and release smoke scenarios over at least
   drowned-crown and one other dogfood game.
6. Migrate the inventory's assertions only to the spec-mandated new
   wording/evidence suffixes. Stable tokens (scenario reach tokens and verdict
   codes) remain unchanged; never weaken or delete an assertion merely to make
   it pass.

**Acceptance:**

- `lute version` reports 0.34.0 on language, IR, and toolchain axes.
- Documentation references agree with the spec and every normative code claim
  has a path:line citation.
- All dogfood projects check clean, golden impact/constraint fixtures pass, and
  conformance snapshots are regenerated once.
- `lute run` still accepts only artifacts; source commands use the model.
- Scoped docs/snippet checks and the release smoke commands pass.

## Review gates and build hygiene

- Spec and plan receive a reviewer pass before S1/S2 begin.
- Each slice receives a reviewer pass on its diff after it lands; findings are
  fixed before any dependent slice starts. S3 and S4 each receive a focused
  semantic-model review for evidence soundness and source-span provenance.
- Before S5 re-records snapshots, run a full-diff reviewer pass and inspect the
  two drowned-crown golden reports manually.
- Use the compact cargo environment for scoped proof:
  `CARGO_PROFILE_DEV_DEBUG=line-tables-only CARGO_INCREMENTAL=0`.
  Prefer scoped `cargo test -p <package> <focused test>`; do not use
  `--release`, `cargo doc`, or project-wide builds in a slice.
- **Never run `cargo clean` mid-flight.** Preserve incremental artifacts and
  avoid unrelated rebuild churn. If a clean environment is needed for release
  proof, do it only after all slices have landed and no other slice is active.
- The final release gate runs the project-wide suite once, after all sibling
  work is integrated, followed by the actual CLI smoke scenarios and docs
  checks.
