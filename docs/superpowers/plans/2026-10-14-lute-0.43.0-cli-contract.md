# Lute 0.43.0 — agent-facing CLI contract: implementation plan

* **Spec:** [`docs/proposals/scenario-dsl/0.43.0.md`](../../proposals/scenario-dsl/0.43.0.md).
* **Decisions:** [`docs/superpowers/notes/2026-10-14-lute-0.43-decisions.md`](../notes/2026-10-14-lute-0.43-decisions.md); research basis [`docs/deep-research-report.md`](../../deep-research-report.md).
* **Issues:** #88 (yaml_serde), #89 (envelope), #90 (error envelope), #91 (`lute schema`), #92 (telemetry).
* **Base:** `89ff8caa` (0.42.1); branch `feat/0.43`. Baseline CLI snapshot `~/lute-043-snap/base`, protected hashes `~/lute-043-snap/protected.sha256`.

## Working rules

* One owner per file at a time; slices that run in parallel own disjoint files
  (listed per slice). Every slice: reviewer pass, fixes, commit; tests that fail
  on the base; `cargo fmt --all --check` clean (CI gate).
* Never `cargo clean`, `--release`, `cargo doc`. Generated files are never
  hand-edited (schemas: `cargo run -q -p lute-runtime --features json-schema --bin lute-contract-schema`;
  TS: `cd packages/runtime && bun run contract:gen`).
* Every CLI snapshot delta is explained against spec §8; conformance changes
  only where a fixture pins a report or a stamp.
* Telemetry must never write during tests or generators (§6, decision note §6).

## Order

```text
Y ─► E1 ─► (E2 ∥ E3 ∥ S) ─► T ─► (C ∥ D) ─► Z ─► final gate ─► release
```

## Y — `serde_yaml` → `yaml_serde` (#88)

Apply the trial migration (worktree `/tmp/lute-yaml-trial`, diff
`/tmp/lute-yaml-trial.diff`: 12 manifests, 96 Rust files, Cargo.lock), rename
the remaining comment/doc mentions, `cargo fmt --all`. **Acceptance:** no
`serde_yaml` in the tree outside CHANGELOG history and old proposals; build,
clippy, nextest green; CLI snapshot byte-identical to base.

## E1 — envelope foundation (#89, #90)

**Owns:** new `crates/lute-cli/src/envelope.rs`; `crates/lute-cli/src/lib.rs`
(clap error path and every dispatch-level error site); `codes/registry.rs`
(`E-CLI-USAGE`, `E-CLI-IO`, `E-CLI-INPUT`) and the blessed EN diagnostics page
plus the KO page; their tests.

* A table of commands: id → outputs `{flag, kind, schemaVersion}` (spec §3.3,
  §5); used by the envelope and later by `lute schema`.
* `json_mode(argv)` (spec §4.1) and `command_id(argv)` (first known
  subcommand path, via the clap command tree).
* `emit_report(id, schema_version, exit, payload_object)` inserting
  `command`/`schemaVersion`/`ok`; `CliError { code, message, path, argument,
  hint }` and one `fail(json, id, err) -> ExitCode` that prints the human
  message to stderr unchanged and, in JSON mode, the error envelope to stdout.
* Clap errors in JSON mode → `E-CLI-USAGE` with `argument`/`hint` from clap's
  error context; help/version displays unchanged.

## E2 ∥ E3 — migrate the reports and their error paths

Each command's JSON writer goes through `emit_report`; every exit-2 path of a
JSON-capable command goes through `fail` with the right code (I/O → `E-CLI-IO`,
malformed input → `E-CLI-INPUT`, invalid flag combination → `E-CLI-USAGE`).
Tests updated (former arrays) and added (spec §8).

* **E2 owns:** `cmd_check.rs`, `cmd_check_project.rs`, `output.rs`,
  `cmd_impact.rs`, `cmd_constraints.rs`, `lint.rs`, `cmd_compile.rs`,
  `compile_all.rs`, `cmd_expr.rs`, `cmd_context.rs`, `cmd_diff.rs`,
  `cmd_patch.rs`, and their tests.
* **E3 owns:** `cmd_trace.rs`, `play/**` (incl. calendar), `testcmd/**`,
  `runner.rs` (error paths only — `run --json` stays unwrapped),
  `cmd_scenario/**`, `scenario_fmt.rs`, `knowledge.rs`, `endings.rs`,
  `beats_cmd.rs`, `refs.rs`, `lore_report.rs`, `loc.rs`, `doctor.rs`, and their
  tests.
