# Lute 0.39.0 — runtime R2: implementation plan

- **Spec:** `docs/proposals/scenario-dsl/0.39.0.md`
- **Direction:** ADR D13; brief `docs/design/runtime-player.md` (owner answers 2026-10-09)
- **Base:** branch `feat/0.39` from `main` at release 0.38.0 (`a5958ae5`)
- **Cutover:** the hand-written 0.38 event/snapshot schema files are replaced by generated 0.39 files; no compatibility copies
- **Scope:** generated contract schemas, `lute-runtime-wasm`, `packages/runtime` (Effect 4), Bun and browser layers, replay conformance in TS, publish, docs, version stamps. Not: C ABI, Node layer, concurrent presentations.

## Ordering

```
S0 stamps ─┬─ S1 contract schemas (Rust) ── S3 TS contract codegen ─┐
           └─ S2 wasm binding ──────────────────────────────────────┴─ S4 TS runtime core ── S5 platform layers + conformance ── S6 publish ── S7 docs
```

S1 and S2 touch different crates and run in parallel worktrees. S3 needs
S1's schema files; S4 needs S2's binding and S3's `Contract.ts`. One owner
per crate/package at a time.

## Acceptance every slice runs

Rust slices:

```sh
RUSTFLAGS="-D warnings" cargo check --workspace --all-targets
cargo nextest run --workspace
cargo check -p lute-runtime --target wasm32-unknown-unknown
cargo build -q -p lute-cli && /tmp/lute-baseline-038/compare.sh   # byte-identical vs v0.38.0, stamps normalized
```

TS slices (from `packages/runtime`):

```sh
bun install --frozen-lockfile
bun run typecheck          # tsc --noEmit, strict, exactOptionalPropertyTypes
bunx --bun vitest run      # @effect/vitest on the Bun runtime
bun run contract:check     # regenerate schemas + Contract.ts, git diff --exit-code
```

## G0 — baseline (orchestrator)

Capture the v0.38.0 CLI baseline (`/tmp/lute-baseline-038`, same procedure
and surfaces as 0.38's G0) and the v0.38.0 `lute-bench` binary for the A/B
gate.

## S0 — version stamps 0.39.0

Workspace and npm versions, `LUTE_IR_VERSION`, `EVENT_VERSION`,
`IR_VERSION` in `lute-runtime`, language constant; rename
`schemas/lute-ir-0.38.schema.json` → `0.39` (body unchanged); regenerate
`conformance/session/*/expected.jsonl` (stamp only) and the conformance
artifacts as the release procedure does.

## S1 — contract schemas from Rust (spec §3.1)

1. `json-schema` feature (optional `schemars` 1.x) on `lute-runtime`,
   `lute-ir` (`BeatKind`, `BeatOnce` only) and `lute-manifest` (`ClockAt`,
   `Atom`); derive `JsonSchema` on every contract type of spec §3.1 and
   §4.1; hand-written impls for `BeatOnce` and the snapshot world adapter.
2. Serde + schema for the query results of spec §4.1 (`Candidate`,
   `Verdict`, `Premise`, `WorldView`, `ClockView`, `GuardRead`); unit
   tests pin one JSON example per variant.
3. Typed `Snapshot` (`continuation` omitted when `None`) and `StreamLine`
   in `lute-runtime`; `Runtime::snapshot` returns `Snapshot`, `restore`
   takes it; the CLI `--events` writer uses `StreamLine`. JSON
   byte-identical (session conformance + snapshot test, idle and suspended
   snapshots).
4. Bin `lute-contract-schema` (`required-features = ["json-schema"]`)
   writes `schemas/lute-events-0.39.schema.json` and
   `schemas/lute-snapshot-0.39.schema.json`; delete the 0.38 hand-written
   files.
5. Validation test with the existing Ajv harness in `tree-sitter-lute`
   (one validator, already in CI): every session `expected.jsonl` /
   `inputs.jsonl` line, the fixture lines of spec §8.7 and every snapshot
   the Rust snapshot test writes to a temp directory validate against the
   generated schemas.
6. CI (`test.yml` offline job): `cargo run -p lute-runtime --features
   json-schema --bin lute-contract-schema && git diff --exit-code schemas/`.

## S2 — `crates/lute-runtime-wasm` (spec §4)

1. New cdylib crate, deps `lute-runtime`, `serde_json`, `wasm-bindgen`
   (exact version pinned with `=` in the crate manifest); `Program`,
   `State`, `StepResult`, `RestoreResult`, `LoadResult`; a `test-panic`
   feature adds a debug export that panics (never in the published build).
   No profile changes: `panic = "abort"` comes from `RUSTFLAGS="-C
   panic=abort"` on the binding's build commands (S5 CI, S6 publish); the
   workspace release profile for native binaries is untouched.
2. Native `cargo test` for target-independent logic (result and rejection
   JSON building). Handle semantics (spec §8.6) are tested from TS against
   the built `.wasm` in S4/S5 — `wasm-bindgen-test` is not used.
3. CI: `cargo check -p lute-runtime-wasm --target wasm32-unknown-unknown`
   in the offline job.

## S3 — TS contract codegen (spec §3.2)

1. `packages/runtime` skeleton: `package.json` (`@lute-lang/runtime`,
   `type: module`, exports `.`, `./bun`, `./browser`), `tsconfig.json`
   (strict, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`),
   `effect@4.0.x` exact, `@effect/platform-bun`, `@effect/platform-browser`
   exact, `@effect/vitest`, `vitest`, `typescript`; workspace entry in the
   root `package.json`.
2. `scripts/contract-codegen.ts`: JSON Schema (generated by S1) →
   `src/generated/Contract.ts` per spec §3.2; unknown shapes are errors.
3. `contract:check` script = S1 generator + codegen + `git diff
   --exit-code`.
4. Tests: every session JSONL line decodes and re-encodes to its canonical
   JSON; a hand-made invalid line fails to decode.

## S4 — TS runtime core (spec §5)

1. `LuteWasm` service (platform-free interface over the `wasm-bindgen`
   glue), `LuteRuntime`, `Program`, `RuntimeState` brand, errors (§5.3),
   `Session` (§5.2), `InputLog` (memory + `KeyValueStore`), `Replay` (§5.4).
2. All public operations `Effect.fn("Lute.…")`; no `Effect.runPromise`,
   `async`/`await` or `try`/`catch` inside the package (only in tests'
   harness edges if unavoidable); no `as` casts on contract data.
3. Tests with `it.effect` / `it.layer` over `LuteWasm.layerFromBytes`:
   session rules of spec §8.2, typed rejections §8.3.

## S5 — platform layers and conformance (spec §6, §8)

1. `@lute-lang/runtime/bun`: `wasm`, `runtime`, `bundle(dir)`, `session(options)`
   (wasm + `BunFileSystem`/`BunPath` + `BundleSource.directory`).
2. `@lute-lang/runtime/browser`: `LuteWasm.layerBrowser(url)`,
   `BrowserLuteRuntime.layer` (`FetchHttpClient`, `BundleSource.url`,
   `localStorage` key-value store).
3. Replay conformance test over every `conformance/session/<case>`
   (compile with the built `lute` binary to a temp bundle) — byte-identical
   canonical JSON vs `expected.jsonl`.
4. One Vitest browser-mode test (Playwright Chromium) replaying
   `conformance/session/hub-once`.
5. CI job `runtime-ts` (`test.yml`): Rust wasm build (`RUSTFLAGS="-C
   panic=abort"`, debug) + pinned `wasm-bindgen-cli` → `bun install` →
   typecheck → `contract:check` → `bunx --bun vitest run` (includes the
   binding handle-semantics tests of spec §8.6 and the panic-is-a-defect
   test against a `test-panic` feature build) → `bunx playwright install
   chromium` + browser test. Path filters: `crates/lute-runtime*/**`,
   `crates/lute-ir/**`, `crates/lute-manifest/**`, `packages/runtime/**`,
   `schemas/**`, `conformance/session/**`.

## S6 — publish (spec §7)

`publish.yml` (every package loop and gate, not just a new step):

1. Build: `RUSTFLAGS="-C panic=abort" cargo build --release -p
   lute-runtime-wasm --target wasm32-unknown-unknown`; `wasm-bindgen
   --target web` from a `wasm-bindgen-cli` installed at exactly the
   crate's `wasm-bindgen` version (`cargo install --locked --version`);
   `wasm-opt -O` from a pinned binaryen release; `bun run build` in
   `packages/runtime`, staging the `.wasm` + glue into the package.
2. Add `packages/runtime` to the version-stamp loop and to the
   fresh-release / recovery probe package set (`publish.yml` ~202-212,
   ~251-252), and publish it idempotently (skip if `@lute-lang/runtime@$VERSION`
   exists) with provenance before the launcher.
3. `scripts/check-release-workflow-safety.py`: assert the runtime package
   is in every package set (a test that fails if a loop omits it).

## S7 — documentation and release notes (spec §11)

`docs/runtime/typescript-runtime.md` (new), `docs/runtime/event-contract.md`,
website tooling page + Korean mirror, `docs/versioning.md`, brief R2
status, CHANGELOG `[0.39.0]` (seven class headings), spec and plan
`status: Implemented`; `scripts/check-docs-consistency.py`,
`scripts/check-doc-snippets.py`.

## Final gate (orchestrator)

All CI-equivalent commands, `compare.sh` byte-identical vs v0.38.0, bench
A/B vs v0.38.0, TS suite on Bun, browser test, a local `npm pack` of
`@lute-lang/runtime` installed into a scratch Bun project that replays one
session case from the packed tarball.
