## Rules

- **Module splits:** real modules only (`mod x;` with explicit imports).
  Explicit `pub use` lists. Never `include!`, never glob re-exports of
  submodule contents, no empty files. No file over ~800 lines.
- **Visibility:**
  - The public API must stay the same. Slice C4's gate proves this.
  - Doc comments move with their items; they are never deleted.
- **Ownership:** one editor per file. A crate whose module wiring is changing
  has exactly one owner for that wave.
- **Builds:**
  - Set `CARGO_PROFILE_DEV_DEBUG=line-tables-only CARGO_INCREMENTAL=0`.
  - Run scoped `-p` builds only; never `cargo clean`.
  - Every intermediate state must compile. Other agents build from the same
    tree.

## C2 design

C2 records a guard's complete runtime read set at the evaluation boundary, not
just the syntactic CEL paths.  A read set contains effective-state paths
(including reserved defaults such as `entry.*.read`/`everRead`,
`quest.*.state`/`failedBy`/objective flags, and `clock.*`), queried fact
patterns and relation names (including derived-relation queries and their
rule dependencies), visited scene ids, quest-status ids, the current occasion
target, and bridge-result `(tag, field)` values.  Dynamic/indexed paths are
recorded as the concrete path read after target binding; unresolved dynamic
reads record an untrackable input.  The set also records whether evaluation
produced an unknown/undecided value or bridge result.

The cache is private to a Machine and keyed by the guard site plus its bound
context (raw guard, document/command identity, member and occasion target).
Each entry stores the decided boolean, its read set, and its evaluation
sequence.  The Machine owns a monotonic mutation sequence; every tracked key
(path, relation, visited id, quest key, occasion target, or bridge
`(tag, field)`) stores its last-modified sequence.  A cached result is usable
only when it has no unknown/undecided component and every key in its read set
has `last_modified < evaluation_sequence`.  A base-relation mutation bumps
every transitively dependent derived relation from the rule dependency graph
computed once per artifact.  Unknown, undecided, reserved-default,
derived/uncertain, clock, occasion-target, and bridge reads are never guessed:
an untrackable read forces evaluation, while a concretely observed decided
read is tracked and invalidated by its corresponding mutation.

All mutations mark their keys through one private mutation choke point before
updating storage: state writes/removals mark the concrete path (and any
reserved/clock alias they refresh), fact assert/retract marks the affected
pattern and relation plus all derived dependents, visited additions mark the
scene id, quest-status/objective transitions mark the quest/status keys,
occasion-target changes mark the target, and bridge answers mark their
`(tag, field)` keys.  Seeds, carry restore, new-run resets, and rule-fixpoint
refresh use the same path; no caller mutates these fields directly.

When an evaluation observer is installed (including `--dump-conditions` read
capture), the cache is bypassed completely, so every condition is observed in
the original order and dumps remain byte-identical.  The cached path is proven
separately: a permanent equivalence test runs every `docs/examples` play
script and every `lute test` trace/play once with caching enabled and once with
the crate-private cache-forced-off switch, asserting identical transcripts and
results.  A regression matrix covers each input kind (state path and reserved
default, base/derived fact, visited, quest status, clock, occasion target, and
bridge result): mutate only that input and assert the next evaluation flips,
while an unrelated input permits a cache hit.  Counters expose evaluated versus
skipped guards for the large playback benchmark, and existing transcript/dump
outputs remain unchanged.

## C3 decision

Keep the current skip. CEL's type rules require typing map/message entries and
comprehension subexpressions, but Lute's closed profile rejects all three
constructs first with one `E-CEL-PROFILE` at the slot span
(`docs/runtime/cel-and-facts.md:12-16`; `cel_resolve/profile.rs:165-179`).
History shows the skip in the original typed-CEL walker (`1d1fbd9f`) and
retained it in the exhaustive-walk refactor (`26ac36fb`); corpus grep found no
such source in `docs/examples` or `conformance`.

## C2 outcome (measured, not shipped)

The read-set guard cache above was built and proven exact. It was proven
against cache-off runs over every `docs/examples` play and `lute test`, with
identical output. It was then removed:

- **It rarely hit.** On monster-league `spine` it skipped 117 of 1,566 guard
  evaluations (7.5%). Most guards are re-evaluated right after a real write.
- **Its bookkeeping cost more than it saved.** Release, idle machine, 3 runs:

  | command | v0.36.1 | cache on | cache off (tracking still on) |
  |---|---|---|---|
  | `lute play` spine | 12.3 s | 15.0 s | 14.65 s |
  | `lute test` monster-league | 29.6 s | 33.8 s | 33.3 s |

  The always-on mutation tracking alone made playback 13–19% slower.
- **The profile pointed elsewhere.** Every evaluator re-decodes the
  project's state declarations and rules from artifact JSON. `drop_in_place`
  of `EffectiveState` alone is 7% of the run. That decode is the playback
  slice's real target: decode once per `ExecProject`.
