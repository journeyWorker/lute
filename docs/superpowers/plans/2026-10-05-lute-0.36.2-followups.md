# Lute 0.36.2: follow-ups to the 0.36.1 quality pass

- **Input:** the deferred list in
  [`2026-10-05-lute-0.36.1-quality.md`](2026-10-05-lute-0.36.1-quality.md)
  (Outcome) and `docs/design/quality-audit-0.36/*.md`.
- **Contract:** no behavior change. Apart from version stamps, every
  observable stays byte-identical to `v0.36.1`: CLI stdout, stderr and exit
  codes; JSON; diagnostics (text, order, spans); IR; insta snapshots;
  impact/context goldens; `conformance/**` artifacts;
  `conformance/edit-tasks/REPORT.json`; the CEL-equivalence harness; and
  `lute test docs/examples`.
  - A slice that needs a golden to change has found a behavior change. It
    stops and reports.
  - The one exception is slice C3. It may *propose* a checker change, but the
    change ships only after an explicit owner decision, recorded here.
- **Baseline:** `/tmp/base0361/{lute,lute-bench}` are release builds of
  `v0.36.1`.
- **Perf proof:** `scripts/bench-ab.py` against `/tmp/base0361/lute-bench`,
  7 samples, run on an idle machine (nothing else building). Wall-clock times
  for the named commands are measured release against release.

## Rules

- **Module splits:** real modules only (`mod x;` with explicit imports).
  Explicit `pub use` lists. Never `include!`, never glob re-exports of
  submodule contents, no empty files. No file over ~800 lines.
- **Visibility:**
  - The public API must stay the same. Slice C4's gate proves this.
  - Doc comments move with their items; they are never deleted.
- **Ownership:** one editor per file. A crate whose module wiring is changing
  has exactly one owner for that wave.
- **Builds:**
  - Set `CARGO_PROFILE_DEV_DEBUG=line-tables-only CARGO_INCREMENTAL=0`.
  - Run scoped `-p` builds only; never `cargo clean`.
  - Every intermediate state must compile. Other agents build from the same
    tree.
