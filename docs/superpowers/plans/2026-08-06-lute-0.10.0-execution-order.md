# Lute 0.10.0 — execution order

**Status:** binding. Execution follows this order, **not** plan-by-plan.

Six plan documents hold 46 tasks with six independent task numberings. A seam
review traced every cross-plan dependency and found **no cycles**; this is the
total order it produced, plus the release plan appended. Tasks interleave across
plans — plan 04 Task 2 runs before plan 03, and plan 04's remaining tasks run
after all of plan 03.

## The three load-bearing constraints

Each is **one-directional**: the stated order is harmless and the reverse breaks.

| # | constraint | what breaks in reverse |
| - | ---------- | ---------------------- |
| 1 | `02 T6` before `04 T3`/`T4`/`T5` | all four edit `run_one_test` in `crates/lute-cli/src/testcmd.rs`. `04 T4`'s `:160` anchor survives `02 T6`'s replacement of `:161-170`; the reverse does not hold. Plan 04's own ordering rationale was written about its three `testcmd.rs` tasks and did not mention `02 T6` at all |
| 2 | `04 T2` before `03 T7`/`T9` | `04 T2`'s nine line anchors in `directives.rs` and `content_line.rs` are shifted by `03`'s insertions. The edits are semantically independent — only the anchors collide |
| 3 | `01 T2`/`T3` before `02 T5` | `CheckInput` derives no `Default` and is not `non_exhaustive`. `02 T5` adds a field to it and patches 111 literals cargo-driven; `01 T2`/`T3` specify verbatim 7-field literals. Reversed, `01 T2` Step 3 gets `error[E0063] missing field defaults` instead of its expected assertion failure |

A fourth is non-directional: `03 T7` and `04 T4` both insert into `DENIABLE_CODES`.
Both plans name-anchor on neighbouring code names rather than line numbers, so
either order works — provided neither reverts to a literal line replacement.

## Two environment facts that bite every task

Both were found by executing the foundation plan, not by reading it.

- **`CI=1` is set.** insta reads it as "never write pending snapshots": assertions
  fail, no `.snap.new` appears, and a bare `cargo insta accept` reports
  "no snapshots to review" and **exits 0**. Use `env -u CI cargo insta test` and
  `env -u CI cargo insta accept`. A step that looks like it succeeded will
  otherwise have changed nothing.
- **`scripts/smoke-sprites.ts` is untracked and is not ours.** It is another
  agent's in-flight work. Never `git add -A`, never `git commit -am`; stage
  explicit paths.
