## Working rules

- One Rust owner at a time: R1 → R2 → R3 → R4, in the main checkout. TS generation only in G1
  (`cargo run -q -p lute-runtime --features json-schema --bin lute-contract-schema`, then
  `cd packages/runtime && bun run contract:gen`) after R4 fixed the schema description sources; Z
  reruns it after the schema rename. Never hand-edit generated output.
- Docs/infra slices (D1a, D1b, D2, D3) touch no Rust and run beside the R slices in git worktrees
  (`/workspace/lute-048-<slice>`, branch `feat/0.48-<slice>`), each committing there; the orchestrator
  merges them. Spellings come from the spec (§3, §5), not from the binary; their command-running checks
  (doc snippets, `lute test`, CI commands) run after R3 on the merged tree.
- Every slice ends with a reviewer-agent pass against its spec sections; findings are fixed before the
  next dependent slice starts.
- Every change gets a regression test that fails on the base; the slice states how that was shown (run
  against `~/lute-048-snap/lute-0.47.2`, or with the change reverted).
- `cargo fmt --all` before each Rust commit. `cargo clean` only by the orchestrator between slices.
  Never `--release`, never `cargo doc`, never `include!`.
- Historical records (released specs/plans/notes, earlier CHANGELOG sections, sentences about what an
  earlier version did) are never rewritten.
- Out-of-scope bugs found on the way: `gh issue create --label bug` with evidence, and a row in the
  decision note.
- Each slice commits its own work (`feat(0.48): <slice> - …`); the worktree is clean at handoff.

## Shared files between R slices

Each R slice edits the `envelope.rs` outputs rows, the `tests/schema_043.rs` assertions and the
`envelope.rs` unit-test id list for its own commands, so RG stays green at every handoff. R1 adds a
permission-profile parameter to `collect_project_docs` / `collect_project_inputs` (`project/mod.rs`) for
R2 to thread; R2 owns `crates/lute-model/src/{patch.rs,gate.rs}` for `apply_patch` and the project gate
options. R1 owns `telemetry.rs` (removed commands record no id). R4 owns crate tests outside `lute-cli`
that assert command text (`crates/lute-check/tests/{cast_024.rs,connectivity.rs}` and any others its grep
finds).
