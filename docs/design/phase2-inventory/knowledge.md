# Phase 2 inventory — knowledge

> Draft research input for the 0.33 spec (ADR phase 2). Generated by a read-only scout on 2026-10-02 against the 0.32.0 working tree; verify citations before relying on them.

## Summary

1. Closed typed relations define knowledge vocabulary and ownership.
2. Assert/retract are sequential fact deltas with direct IR commands.
3. Validity is half-open narrative time; holds is valid-now and validAt is historical.
4. Engines compute structured Datalog rules to a stratified least fixpoint.
5. Positive recursion is allowed; negation and aggregates are lower-stratum constrained.
6. May/Must fact envelopes produce sound impossible, guaranteed, and possible verdicts.
7. Lore first-read assertions are the disclosure mechanism; rereads skip effects.
8. Truth, testimony, belief, and inference are separate ordinary relations.
9. Cast presence is a guard-analysis contract over engine/reserved facts.
10. Proposed semantic IDs are split by behavior, not one coarse knowledge ID.

## Proposed architecture

One knowledge domain module should own relation vocabulary/ownership, fact deltas and validity, Datalog closure, CEL fact queries, lore disclosure, and May/Must verdict analysis. It consumes state lifecycle and engine occasions; cast presence is a neighboring consumer of reserved knowledge facts. Semantic IDs should be independently negotiated for each engine-visible behavior.

## Existing ordering rules (with citations)

1. Imported schemas load before document-local declarations; merged relation/rule checks happen after composition [docs/proposals/scenario-dsl/0.3.0.md:230-252].
2. Assert/retract are sequential and later commands in the same arm see earlier fact deltas [docs/proposals/scenario-dsl/0.3.0.md:835-839].
3. Conditions read the same fact snapshot as scalar state; sibling `<on>` handlers judge against one pre-event snapshot, preventing sibling-write leakage [docs/proposals/scenario-dsl/0.3.0.md:840-847; docs/runtime/runtime-unification.md:123-128].
4. Seed + asserted + derived facts reach a least fixpoint; strata evaluate lower dependencies before negation/aggregate users [docs/runtime/cel-and-facts.md:65-115].
5. One narrative token advances per delta; same-token deltas use command order, while validAt is token-granular [docs/proposals/scenario-dsl/0.3.0.md:623-633].
6. Lore eligibility precedes entry body; body is address order; first-read effects apply before read/everRead flags are set [docs/runtime/lore-entries.md:55-86].
7. Occasion beats select by priority then project index; ordinary lore target/category placement and selection remain engine policy, with project order only a stable tiebreak [docs/runtime/lore-entries.md:33-53].
8. May is flow-insensitive and Must path-sensitive; after propagates monotone facts into scene entry points and guards add assumptions [docs/proposals/scenario-dsl/0.20.0.md:43-120].
9. Quest predicates re-evaluate after engine-side reserved asserts; cast assume is narrowed after a changedOn event and descendants [docs/proposals/scenario-dsl/0.3.0.md:847-850; docs/proposals/scenario-dsl/0.25.0.md:80-93].
10. Tier reset clears live facts and interval history, then seeds rematerialize [docs/proposals/scenario-dsl/0.3.0.md:208-212,605-610].

## Eleven gaps/ambiguities for 0.33

1. **Fact delta vs condition boundaries:** docs define in-arm order and sibling pre-event snapshots but not one universal phase algorithm for engine reserved writes → quest settlement → occasion raising → beat presentation [docs/proposals/scenario-dsl/0.3.0.md:840-850; docs/runtime/runtime-unification.md:89-104].
2. **Derived recomputation after scalar `::set`:** runtime-unification records stale rule-derived state in the old run path while current fact semantics imply query-time live recomputation; 0.33 must fix the invalidation boundary [docs/runtime/runtime-unification.md:124-128,154-155; docs/runtime/cel-and-facts.md:108-115].
3. **Multiple reserved engine writes:** changedOn narrows presence but does not define ordering among reserved relation changes or whether all writes precede quest handlers/beat eligibility [docs/proposals/scenario-dsl/0.25.0.md:80-93].
4. **Temporal token granularity:** same-token command order exists, but engine batching (per command/event/presentation) is unspecified [docs/proposals/scenario-dsl/0.3.0.md:623-633].
5. **Lore placement:** Lute defines eligibility/body but leaves which room/item/NPC presents an entry and most ordinary-entry selection policy to the engine [docs/runtime/lore-entries.md:33-53].
6. **Disclosure atomicity on failure:** read flags are written after body completion, but partial assertions before error/termination are not specified as rollback vs commit [docs/runtime/lore-entries.md:55-86].
7. **Belief revision:** contradictory percepts remain valid without key/retract; dogfood policy should choose functional key, explicit retract, or intentional multiplicity [docs/proposals/scenario-dsl/0.3.0.md:855-870].
8. **Presence vs epistemic writes:** no rule says whether an absent speaker may assert testimony/knowledge facts through a plugin, or whether presence gates non-line fact writes [docs/proposals/scenario-dsl/0.24.0.md:135-170; crates/lute-check/src/cast.rs:408-455].
9. **Aggregate verdict evidence:** count interval semantics exist, but diagnostics do not standardize witness lower/upper bounds for countDistinct or exclusion reasoning [docs/proposals/scenario-dsl/0.20.0.md:123-158].
10. **Reserved seed precedence:** schema seeds may populate reserved/app relations while engine events also write them; seed-vs-engine initialization and keyed replacement are unspecified [docs/proposals/scenario-dsl/0.3.0.md:208-212; docs/proposals/scenario-dsl/0.25.0.md:80-93].
11. **Semantic-id granularity:** D5 requires per-engine-visible behavior, but knowledge spans vocabulary, deltas, closure, temporal store, disclosure, presence, epistemics, and verdict analysis; one coarse id would let an engine silently miss a meaning-changing subfeature [docs/design/architecture-direction.md:142-148].
