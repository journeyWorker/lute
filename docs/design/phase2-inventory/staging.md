# Phase 2 inventory — staging

> Draft research input for the 0.33 spec (ADR phase 2). Generated by a read-only scout on 2026-10-02 against the 0.32.0 working tree; verify citations before relying on them.

## Summary

1. Scene/shot are layout and beat-selection boundaries; commands are the executable stream.
2. Lines carry source text plus code-derived opaque lineId/voiceKey joins.
3. Branch/choice records write scene.choices and route to option targets/converge.
4. Hubs revisit at runtime, writing scene.visited and honoring once/exit/return.
5. Match is first-arm-wins CEL control flow with unset and exhaustiveness rules.
6. Components expand before lowering; engines never see ::use, only expanded records.
7. Core staging lowers to background/music/sfx/vfx/sprite/camera/cut/video records.
8. Timelines flatten tracks onto local clocks, sort clips, and close with a barrier.
9. Plugin bridges lower to kind:plugin; hosts dispatch, replay, block, and apply effects.
10. Interpolation/localization are late rendering/join layers; key order and fallback gaps remain.

## Proposed architecture

The area divides into narrative control (scene/shot/line/choice/hub/match/components), staging presentation (core directives and stage lifetime), temporal coordination (timeline/barrier), and host extension boundaries (plugin/bridge/capability negotiation), with identity/localization as cross-cutting services. Compile-time expansion, stage injection, addressing, timeline scheduling, and locale merge precede engine playback; engine execution owns rendering, state application, bridge invocation, replay, and fallback policy.

## Existing module ordering rules

1. **Capability resolution precedes check/compile**: core → global profile → selected profile chain → scene-local plugins → dependency closure; checker/LSP/compiler consume the same snapshot [docs/proposals/scenario-dsl/0.0.1.md:190-194].
2. **Compile normalization/expansion precedes lowering**: components are expanded and builtin plugin lowerings canonicalized before stage/command lowering; runner never sees `::use` [docs/runtime/runtime-unification.md:135-137].
3. **Addressing follows lowering and determines execution order**: command array is final execution order; addr is positional, while lineId/voiceKey are stable joins [docs/runtime/execution-model.md:148-156].
4. **Within ordinary flow, PC order dominates**: engine walks commands array and resolves choice/hub/match targets and convergences [docs/runtime/execution-model.md:160-178].
5. **Stage resolution injects lifetime commands**: auto-show, reposition, pose reset and auto-hide are deterministic build-time insertions [docs/architecture.md:118-123].
6. **Timeline clips are an exception to source order**: track-local cursors resolve omitted times; clips sort by absolute `at`, then track index; barrier joins at duration/max end [docs/runtime/timeline-semantics.md:24-53].
7. **A line/directive `when` is evaluated at its own position**; guarded `::use` wraps the whole expansion atomically, while builtin staging has no guard [docs/runtime/state-lifecycle.md:73-87].
8. **Bridge effects occur after bridge return and in declaration order**; `wait` only blocks when host honors it, and fire-and-continue is host policy [docs/runtime/bridge-protocol.md:69-99].
9. **Occasion `judge: before` moves objective judgment before beats, but handlers run after beats** [docs/runtime/beats-and-occasions.md:53-62].
10. **Localization merge is after lowering/addressing**, keyed by stable line/option IDs; it never replaces source text [crates/lute-compile/src/locale.rs:182-223].

## Gaps / ambiguities for 0.33

- **Scene/shot vs engine occasion boundary**: explicit-flow scene entry, scene reset, and occasion-selected presentation are described separately; the host event that starts/ends a scene tier is intentionally policy [docs/runtime/state-lifecycle.md:39-42]. A semantic contract should state when scene reset occurs relative to occasion objective judgment and beat selection.
- **Stage injection relative to guards and control-flow records**: compiler insertion is deterministic, but no single normative ordering table says whether injected enter/exit records dominate a false line guard, branch menu presentation, or a jump target. [INFERENCE]
- **Non-timeline `wait` sequencing**: architecture says non-wait directives can run concurrently, but exact completion/interleaving semantics between a nonblocking directive and a subsequent state-writing command are host policy. [INFERENCE]
- **Timeline same-time ties**: `(at,track index)` is deterministic, but engine-visible ordering between simultaneous media effects and state writes is not semantically stated beyond sort order; declare whether effects observe prior same-time writes. [INFERENCE]
- **Timeline barrier and failed/async plugin clips**: barrier requires all clips to have played, while bridge replay/blocking is host policy; cancellation, error, timeout, and a plugin clip that never completes need explicit semantics. [INFERENCE]
- **Bridge stale-read dominance remains open**: plugin design explicitly records an unresolved `wait="false"` dataflow question (“is this read dominated by the bridge call?”) [docs/proposals/plugin-system/0.0.2.md:231-237].
- **Replay semantics are under-specified**: `replay` is a declared policy string and result shape, but 0.33 needs the record key, ordering, error/timeout behavior, and whether recorded output includes effect application or only raw result. [INFERENCE]
- **Component identity under nested/conditional uses**: IDs use host 1-based use ordinals and nested segments [docs/runtime/execution-model.md:154-158], but conditional non-executed uses and duplicate component paths need a negotiated stable instance identity rule for patch/replay tools. [INFERENCE]
- **Interpolation evaluation timing with localization**: placeholders are compiled as referents while locale text is merged separately; the contract should say whether placeholders are interpreted after locale selection (expected) and whether locale text may change placeholder shape. [INFERENCE]
- **Occasion target rendering**: `{{occasion.target}}` exists only in targeted beat/entry context [crates/lute-compile/src/ir.rs:920-945], but fallback display-name precedence and behavior on missing target should be a semantic ID contract, not engine convention.
- **Localization fallback/completeness**: compiler warns missing declared locales but merges extra locale keys [crates/lute-compile/src/locale.rs:203-223]; runtime fallback order and whether missing text blocks execution are not specified. [INFERENCE]
- **`code` allocation scope**: docs establish per-speaker backfill and component prefixes, but the 0.33 identity negotiation should explicitly include shots, nested branches, timeline clips, and component effects as one collision domain. [INFERENCE]
