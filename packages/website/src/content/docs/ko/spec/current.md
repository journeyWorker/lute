버전 관리된 제안 스택은 다음 경로 아래에 있으며
[`docs/proposals/scenario-dsl/`](https://github.com/journeyWorker/lute/tree/main/docs/proposals/scenario-dsl)
**여전히 규범적 기준(normative source of truth)입니다**. 이 페이지는 이를 대체하지 않습니다 — 이 페이지는
언어 버전 **0.47.0**에서 *현재* 유효한 것들을 통합한 **인덱스**입니다.
각 언어 영역에 대해 어떤 제안 리비전이 그것을 도입했고, 어떤 리비전이 마지막으로 변경했으며,
규범적 텍스트를 어디서 읽을 수 있는지를 정리합니다.

:::note
이 인덱스와 제안이 서로 다를 경우 저장소의 제안이 우선합니다. 전체 누적 이력
(구현 이전의 `0.0.1` 초안과 capability 제안 포함)은
[사양 인덱스](/ko/spec/)를 참고하십시오.
:::

## 0.42.0 — 플레이어 계약 및 볼륨 바인딩

0.42.0 계약은 언어, IR, Event 및 스냅숏 계약, 플레이어 바인딩,
생성된 계약과 플레이어 패키지를 하나의 축으로 전환합니다. 규범적인 릴리스
제안은
[0.42.0.md](https://github.com/journeyWorker/lute/blob/main/docs/proposals/scenario-dsl/0.42.0.md)입니다.

- `volume`은 절대 레벨인 프로젝트 도메인입니다. 문서화된 축은
  `silent`, `quiet`, `normal`, `loud`, `full`이며 숫자 볼륨은 허용되지 않습니다.
  `lute fix`은 정확히 예전 순서인 `[silent, down, normal, up, full]`일 때만
  `down`을 `quiet`으로, `up`을 `loud`로 변경합니다.
- `player.bindings.yaml`은 `bindingsVersion: "0.42"`와 선택적인
  `volumes: { member: gain }` 맵을 사용합니다. gain은 `[0, 1]`의 유한한
  수여야 하며, 알 수 없는 키는 `E-BINDING-KEY`, 누락된 멤버는
  `W-BINDING-MISSING`, 잘못된 gain은 `E-BINDING-SHAPE`입니다.
- `bg`, `music`, `sfx`, `vfx`, `actor`, `camera`, `cg`, `video`,
  `sequence` 런타임 레코드는 해석된 `attrs`를 가집니다. 호스트는 아티팩트를
  다시 열지 않고 `attrs`에서 미디어 필드를 읽으며 Event와 스냅숏 스키마는
  `-0.42` 계열로 이동합니다.
- `LutePlayer.make`는 한 번 적용되는 `cueFactory(base)` 래퍼를 받고 핸들은
  일관된 `snapshot`을 노출합니다. 재생은 `voiceKey`를 사용하며
  `Director`에서는 중복된 사전 구성 핸들러보다 `host.plugin`이 우선합니다.
- 패키지 `typecheck`은 Bun checker(`bun check`)를 사용하고 CI는 Bun 1.4.3을
  고정합니다. 일곱 패키지와 모든 공개 버전 축은 0.42.0/0.42로 기록됩니다.

아래의 역사적 동작은 이를 도입한 제안에 계속 귀속되며, 이 인덱스는 해당
인용을 다시 쓰지 않습니다.

  더 이상 이름 접두사로부터 이를 추론하지 않기 때문입니다. **해당 릴리스에서 IR shape는
  움직이지 않았습니다**: 어떤 필드도 추가, 이름 변경, 이동되지 않았으며, `irVersion`이
  `"0.9.0"`로 읽힌 것은 릴리스가 모든 축을 재정렬하기 때문일 뿐입니다 — IR
  `0.8`에 게이트된 엔진은 게이트를 `0.9`까지 넓히기만 하면 되었습니다.
  아티팩트의 *콘텐츠*는 실제로 움직입니다 — `enums`은 인라인으로 또는
  `uses:`을 통해 선언하는 프로젝트에서 채워지고, `capabilityVersion`가 바뀝니다.
  저작(authoring) 측면은 [Content vocabulary](/ko/language/vocabulary/)에 정리되어 있습니다.
- **`0.9.0`는 또한 import된 component 본문이 그 본문을 사용하는 콘텐츠와 동일하게 검사되도록 합니다.** `check()`의 18개 진단 단계 중 5개는 root 전용이어서
  컴포넌트 본문에 대해서는 실행되지 않았으므로, 동일한 줄이 `::use`을 통해서는 *clean*으로
  검사되고 씬 수준에서는 *dirty*로 검사되었습니다 — 콘텐츠 줄 attribute 규칙, `E-DUP-LINE-CODE`,
  reachability, walker가 처리하지 않는 콘텐츠의 admission, 그리고 injection
  folding이 그것입니다. 이제 다섯 가지 모두 `::use` 위치에 anchor되어, 컴포넌트와 그 파일을
  명시하는 접두사를 붙여 실행됩니다. 이전에 통과하던 컴포넌트 본문이 보고될 수 있으며,
  그러한 모든 보고는 이미 artifact에 도달하고 있었거나 이미 조용히
  버려지고 있었던 것입니다. 컴포넌트 본문이 여전히 갖지 **못하는** 것은 자체 vocabulary
  scope입니다: 그 `uses:`와 자체 inline `enums:`는 모두 parse 시 버려지므로,
  본문은 **가져오는(importing)** 문서를 기준으로 vocabulary를 해석합니다.
- **`0.10.0` — toolchain은 아는 것을 말합니다 — 는 문서, mock, 그리고
  IR shape를 빨갗게 만듭니다.** 13건의 언어 변경이 있으며, 그 공통 맥락은 그 모든
  항목이 checker가 이미 답을 알고 있던 지점이라는 것입니다. 그중 세 가지는
  현재 clean으로 검사되는 문서를 빨갗게 만들 수 있습니다: `::set`은 이제 우변의
  타입을 자신이 쓰는 경로에 맞춰 검사하고 (`E-SET-TYPE`), 여섯 logic tag는 자신의
  attribute 집합을 닫으며 (`E-UNKNOWN-ATTR`, 그리고 `E-AS-REMOVED`은 `as=`에 대해, 즉
  `<choice>` 상에서 적용됨), 결코 열릴 수 없는 `<quest start>` gate는
  이전에는 조용히 지나가던 곳에서 `E-QUEST-UNREACHABLE`로 처리됩니다. `mocks/*.yaml`는 처음으로
  검증되며 그 `file:` 키는 **필수**입니다 — 이 키가 없는 mock은
  `E-MOCK-SUBJECT`입니다. 그리고 IR **shape**가 처음으로 움직이는데, 이는
  `0.8.0` 이후 처음입니다: `provenance.reason`가 `provenance.explanation`가 되므로, IR
  `0.9`에 gate된 engine은 `0.10`로 넓히고 자신이 읽는 그 한 필드의 이름을 바꿔야 합니다.
  `W-INJECT-CONFLICT`은 좁혀지는 대신 **제거**되며, 그것이 담고 있던 정보는
  이전(migrate)되지 않고 버려집니다 — 선언된 기본값과의 일치가
  유일한 트리거였으므로, 더 이상 경고할 것이 남아 있지 않았습니다.
- **`0.6.1` coverage 경고는 오류가 아니라 정직함입니다.** 이 경고들은 정적 분석이
  증명할 수 있는 것의 정확한 경계를 지목합니다 — 오래된 `luteVersion` stamp,
  생성 불가능한 trace mock — 그리고 스스로 exit code를 바꾸는 일은 결코 없습니다. 세 번째인
  `W-UNPROVEN-RELATIONAL`(checker가 증명도 반박도 할 수 없었던 관계형 fact query)은
  `0.20.0` 이후 사라졌습니다: 이제 `check-project`이 관계형 guard를 판정하며,
  dead guard는 해당 slot의 오류를 통해 보고하고 redundant
  guard는 `W-FACT-GUARANTEED`로 보고하며, 단지 *가능한* guard는 정상적인 경우로서
  조용히 지나갑니다. 두 가지 `0.8.0` 추가 항목은 coverage 주장이 아니라
  일반적인 finding입니다 — `::end` 뒤의 도달 불가능한 콘텐츠, 그리고 번들이
  선언한 locale이 누락된 translatable record — 하지만 동일한
  severity를 갖습니다. 이들 중 어느 것이든 `--deny <CODE>` 또는
  `--deny-warnings`로 오류로 승격할 수 있습니다.
- **설계 근거는 spec과 함께 존재합니다.** 4계층 state model의
  *이유*는
  [`state-model-design.md`](https://github.com/journeyWorker/lute/blob/main/docs/proposals/scenario-dsl/state-model-design.md)에
  기록되어 있으며, 이는 `0.0.1` §9의 비규범적(non-normative) 동반 문서입니다.
- **Capability surface는 별도로 명세됩니다.** Character/cast identity와
  plugin 시스템은 핵심 scenario-DSL 개정이 아니라 capability 제안입니다.
  plugin 시스템의 현재 개정판은 `0.0.4`이며, `0.10.2`과 함께 도입됩니다:
  plugin이 소유하고 checker가 검증하는 frontmatter 키가 이제 컴파일 시 버려지는 대신
  컴파일된 artifact(`meta.plugin`)에 도달합니다. `0.0.3`
  — `lute.core`은 빈 `enums`를 export하고, `enums` 항목은 긴 형식의
  멤버 의미론을 가질 수 있으며, 닫힌 `semantics` flag vocabulary는
  어떤 consumer도 읽지 않던 두 flag를 제거합니다 — 와 `0.0.2` — option 및 frontmatter 값
  검증, 예약된 stamp-attribute 거부, cross-cutting `stampAttrs`,
  그리고 실제로 구현된 선언적 `lower: { record, fields }` 형식 — 은 개정된 형태로
  그 기반으로 남아 있습니다. 네 가지 모두에 대해서는 [specification index](/ko/spec/)를 참조하십시오.

## 0.43 CLI 계약 부록

언어와 아티팩트 형태는 위의 버전 주장에 정의된 계약을 따릅니다. 0.43 에이전트용 추가 사항은
CLI 계약입니다. JSON 보고서는 `command`, `schemaVersion`, 종료 코드와 일치하는 `ok`를 갖는
평면 객체이며, JSON 모드 실패는 `E-CLI-USAGE`, `E-CLI-IO`, `E-CLI-INPUT`을 사용합니다.
`lute schema`는 파서의 명령 트리를 설명하고, 로컬 텔레메트리는
`LUTE_TELEMETRY=0` 또는 `DO_NOT_TRACK=1`로 선택 해제합니다. 아티팩트, `run --json`,
이벤트 스트림은 기존의 보고서가 아닌 프로토콜을 유지합니다.
